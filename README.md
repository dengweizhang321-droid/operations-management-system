# 电扇运营管理系统

## 启动方式

双击 `运行项目.bat`，或在命令行中执行：

```cmd
npm run dev
```

若需要启动预构建的 Workers 产物，先以本机模式完成构建，再执行：

```powershell
$env:VITE_TERUISI_LOCAL_BUILD = "true"
npm run build
npm run start:local-worker
```

`start:local-worker` 会把被 Git 忽略的根目录 `.dev.vars` 以硬链接提供给 `dist/server/wrangler.json`，确保 AI 凭证加密密钥和本机管理员模式进入 Worker；它不会打印或提交密钥。

## 吉客云自动化

- `npm run jackyun:login`：打开专属浏览器，手工登录吉客云
- `npm run jackyun:daily`：运行每日五类数据导入
- `automation/n8n/jackyun-five-dataset-daily.workflow.json`：默认未激活的 n8n 三段式副本；A 生成当天安全计划，B 复用正式五类 runner 串行完成下载、导入和落库回查，C 独立核验清单、审计与精确批次。工作流不保存吉客云账号、密码、Cookie、Token 或 Session，并在已有完整当日结果时跳过重复导入。

## 网店数据

- 数据导入页支持京东商品主数据与 SKU/SPU 日数据，以及已注册天猫店铺的货品、生意参谋商品日数据和推广商品 ZIP。天猫三类来源固定绑定平台“天猫”，店铺必须来自启用的受控注册项；货品要求快照日，日数据要求完整的预期日期范围。
- 天猫生意参谋 SPU 分天数据支持受控多店铺工作流：`config/tmall-store-accounts.json` 为每店配置独立 profile、端口和下载目录；`npm run tmall:daily:import -- --dry-run` 生成缺失日期计划，`npm run tmall:receipt` 校验并签收单日 `.xls`，`npm run tmall:daily:import` 串行导入并回查。亿玖店提供两种默认未激活的 n8n 副本：`automation/n8n/tmall-yijiu-sycm-daily-import.workflow.json` 监听人工下载文件，`automation/n8n/tmall-yijiu-sycm-cookie-daily.workflow.json` 使用店铺独立 Chrome 完成当天货品快照，再通过受本地 Worker 守护的一次性环回辅助进程执行“商品日缺口计划 → Cookie 单日直连下载 → 签收导入回查 → 全站推推广逐日下载导入”。推广末段必须从千牛店铺后台最左侧依次点击“推广 > 货品全站推”，再点击全站推页面左侧“报表”和右侧“下载报表”；推广缺口按日期升序逐日处理，每个报表的起止日期必须是同一个业务日并选择“全部数据指标”，前一天完成下载、内容校验、导入和覆盖回查后才进入下一天，任意一天失败即停止。确认后只点击包含“离线数据生成成功”和“下载任务管理”的成功提示中的“立即前往/前往下载”，再从新页面的下载任务管理只接管本轮唯一成功 ZIP。单 CSV、商品主体、唯一目标日、店铺、行数和哈希全部通过后才导入并回查。平台消息或广告弹窗仅使用明确的关闭/忽略动作。当天已有完成的货品快照及已覆盖的商品日或推广日会自动跳过；n8n 的五个节点绑定同一执行 ID，商品日和推广日每轮各最多处理 1 天，导入必须满足预检、批次、解析与落库回查行数完全一致。商品日下载优先从同一店铺独立 Chrome 的当前会话在内存中读取 Cookie，受控 Cookie 原文件只作为浏览器不可连接时的后备；存在至少 5 个商品且与最新货品主数据零交集时按疑似账号/店铺错位拒绝导入。天猫副本按上海时间 09:10–19:10 每小时有界补跑，与吉客云 `:40` 调度错开；工作流不保存账号、密码、Cookie、Token 或 Session。详细步骤见 `docs/天猫生意参谋SPU多店铺工作流.md`。
- 左侧“工作流”板块可切换“吉客云导入系统”和“天猫店铺数据导入”，并为 `operator`、`admin` 嵌入本机 `http://localhost:5678` 的对应 n8n 画布；`viewer`、`analyst` 只能查看概览。页面会读取 `127.0.0.1:5791/health` 的非敏感就绪状态，在服务离线、天猫 Cookie 原文件缺失、吉客云专用 Chrome profile 缺失或已有任务运行时阻止执行；“辅助服务已就绪”只代表本地服务和 Cookie 原文件可用，Cookie 身份及千牛、阿里妈妈登录态仍由对应执行阶段重新核验。页面展示仓库模板信息，实际发布状态以 n8n 画布为准。本地 Worker 启动器负责拉起一次性辅助进程，并在每轮成功或失败退出后重新待命。两条工作流都保持后端幂等与落库回查，运营系统不读取 n8n 登录态或业务平台凭证，也不会自动发布、激活或执行流程。
- 网店分析提供跨平台货品目录、京东 SKU 日表现、京东/天猫 SPU 商品表现和天猫推广分析。金额接口统一使用人民币分；商品访客只按“商品×日”累计展示，不解释为店铺去重 UV。
- 推广费率与推广成交占比只使用推广报表和生意参谋支付金额均有覆盖的业务日；ROAS、CTR、CPC 等比例从汇总金额或计数重新计算，不平均源文件行比率。
- 导入按来源、平台、店铺和文件哈希幂等隔离，日数据修订只替换精确日期范围；接口在确认成功前回查批次、行数、日期和关键范围。本地验证不等同于生产导入，生产迁移与数据导入仍需单独执行。

## 说明

本项目的主界面运行在 `http://localhost:3000`。

主界面左侧按“经营管理”和“系统管理”分组：经营管理依次为 BI 看板、市场分析、销售分析、网店分析、客服分析、货品详情、库存管理、运营事务、工作流、AI 助理；系统管理依次为数据导入、系统设置。页面顶部只保留当前模块的全局页头与统一统计周期，分析模块切换后继续使用同一日期范围。业务筛选支持多选并由接口按重复参数执行服务端筛选；任意已渲染表格的列标题还可打开列值多选，用于继续筛选当前已加载页。

市场分析的 SKU 主图标准售价经 AI 识别、人工复核并正式入库后，后续月份若三级类目、榜单 scope、SKU 维度、SKUID 和图片均一致，系统会直接沿用历史分类和标准价，不再调用 AI 或重复批量入库；同一业务身份的 SKUID 更换图片时，只沿用仍在当前字典中的人工确认分类，并使用精简的价格专用视觉识别重新读取新图价格；新 SKUID 才执行分类和价格的完整图片识别。商品榜单识别到正式市场定位价格（主图价）后，该行成交均价按同一主图价展示；未识别到主图价时才按成交数据计算。

市场图片 AI 识别优先使用系统已验证的 R2 图片缓存，缺失时才回源京东图床。超大模型输入图会在不改变原图哈希和人工复核原图的前提下，自动缩放到最长边 1600 像素并编码为 WebP；只有结果确实更小时才采用，转换不可用、失败或结果无效时自动回退原图，成功的衍生图按原图哈希缓存到 R2；旧缓存缺少衍生图时会首次按需补齐，后续直接复用。SKU AI 标注的模型并发数可在 1–50 之间按“三级类目 + 执行器”独立记忆；云端默认 10、建议 10–20，过高可能触发供应商限流并计入失败，本地 Ollama 默认且建议 1。新任务配置和当前任务控制分区展示，当前任务即使正在运行也可单独保存并即时应用新的并发数。每个 HTTP 请求仍只处理一张图片，服务端按同一类目配置原子限制有效推理租约；同一任务中业务身份与图片哈希相同的跨月记录只领取一次推理，结果批量扩散到全部月份，重复创建同一任务会恢复已有任务。视觉模型单次调用最多等待 90 秒，浏览器请求最多等待 110 秒，推理租约为 3 分钟；单次模型超时或网络异常只会温和降低运行并发，并让触发异常的通道从 5 秒短冷却开始，其他通道继续处理图片；同一冷却窗口的并发失败只算一次，重复异常才继续阶梯降级且普通异常冷却最多 30 秒。供应商 429 限流仍会让所有通道按减半并发和 60 秒至 5 分钟全局退避。连接每连续成功 3 张就增加一路，直至恢复该类目的配置值。运行中页面只读取轻量进度，不再反复装载整批复核数据；页面保持打开时无需手动刷新或点击继续，已完成结果不会丢失或重复识别。

“系统和 AI 设置”中的待 AI 标注总量按类目、榜单 scope、SKU/SPU 维度和商品编码去重，并互斥拆分为：同图直接复用、新图仅识别价格、完整分类和价格、暂不可自动识别。一个商品身份跨月份命中多种路径时按“完整识别 > 仅价格识别 > 同图复用”归类；无图、非 SKU、有效 Prompt 缺失或识别失败封顶进入阻塞项，四项合计始终等于待 AI 标注总量。
