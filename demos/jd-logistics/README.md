# 京东 POP 入仓监控 Demo

本轮根据用户 2026-10-15 的最新答复，只演示“京东 POP：库存流水与 ERP 建单核对”。自营/C 仓不处理。正式系统入口规划为“库存管理 → 京东入仓监控 → 京东 POP”，现有 ERP 京东仓监控保留。

## 启动

```powershell
node demos/jd-logistics/server.mjs
```

打开 [本地演示](http://127.0.0.1:4326/)。仅监听回环；端口占用会退出，不接管其他进程。可用 `JD_LOGISTICS_DEMO_PORT` 设置独立端口。

无需安装依赖，不使用主系统启动器、数据库或京东会话。文件白名单静态服务器只提供 HTML/CSS/JS，拒绝所有写请求。界面中的修改只在内存，刷新重置；明确标识合成样本，不保存真实商品或单据。

## 已演示

- 保留原页面导航，新增京东 POP；总览、流水、调拨商品核对、商品对照、自动化导入、账号规则六个视图。
- 同单多流水按“物流货主＋京东单号＋事业部商品”合并；部分入库、缺调出来源分别展示。
- 商品对照 C/D 两个字段和调拨 C 人工状态可编辑，修改后待办联动；人工状态不宣称 ERP 台账已验证。
- 搜索、筛选、切店、导出合成流水 CSV、新建账号默认采集/监控/推送关闭、阈值调整、采集预检与提醒预览。
- 自动化页仅展示已调研的来源与流程；真实文件契约待验证时停止，没有真实下载、导入或推送。

## 验证与边界

```powershell
node --test demos/jd-logistics/model.test.mjs
```

此处是可交互静态演示，沿用现有主题和导航层次，不是 React 生产页面接线。正式实现应复用既有页面组件、Django 库存域、真实权限和已有京东受控执行器。详见[交付报告](../../docs/jd-logistics-demo-20261015/REPORT.md)、[表格分析](../../docs/jd-logistics-demo-20261015/表格结构分析.md)、[下载调研](../../docs/jd-logistics-demo-20261015/下载调研.md)和[接口规划](../../docs/jd-logistics-demo-20261015/结构与接口规划.md)。

不包含正式 API、迁移、n8n workflow、ERP 自动建单或生产运行参数变更。样本的业务类型是便于交互的简化标注，不能直接作为京东解析枚举。部分来源、单据和业务键的生产契约仍需要真实文件验证。
