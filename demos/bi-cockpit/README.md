## 启动与源码

仅依赖 Node.js（已在本机验证），无需 npm install，不依赖主项目构建或数据库。

```powershell
Set-Location -LiteralPath 'D:\.codex\worktrees\bi-cockpit-demos\运营管理系统\demos\bi-cockpit'
node server.mjs
```

若需要其他端口，设置专用变量 `$env:BI_DEMO_PORT='4319'` 再运行；服务只监听127.0.0.1，端口占用会失败退出，不接管既有进程。关闭该终端/按Ctrl+C只停止本 Demo。不要运行主项目 npm dev/build/start 来预览这五案。

- `demo01`—`demo05`：五套独立 layout.js、layout.css、NOTES.md。
- `shared/data.js`：唯一合成事实与计算规则；`ui.js`：统一经营域和交互组件。
- `app.js`：统一入口、筛选、加载/失败情景、详情及导航演示、范围与折叠状态。
- `shared/tokens.css`：来自基线最新 tokens，未改主系统样式。
- 日期：复用同仓已存在 `app/netshop/comparison/demo/date-picker.{js,css}` 的独立桥接版；双月日历、快捷范围、输入/点击/拖选、应用/取消。正式接线仍以 `app/statistical-period-picker.tsx` 为公共组件，不声称本 Demo 已完成生产组件集成。

## 共同数据与口径

所有数据都是**合成示例**，冻结演示今天为2026-10-05。8店、5个ERP SKU、8个商品仓位。没有生产读写API、用户权限或真实平台会话。

| 指标 | 统一定义与边界 |
|---|---|
| ERP净销售 | 正向分摊销售−退货金额；不与平台成交或广告归因相加 |
| 综合大毛利额 / 率 | 净销售−成本；汇总毛利÷汇总净销售。不是含费用分摊的订单毛利或财报利润 |
| 退货金额比例 | 负销售绝对额÷正向销售额；分母非正不可用 |
| 同比 / 环比 | 同期实际日期 / 紧邻等长前期。两期店日完整才展示百分比；零/负基期不可比较，未接入不写新增 |
| 比率变化 | 毛利率与退货比例用百分点pp；ROAS变化用倍，金额变化用元或百分比 |
| ERP目标 | 明确合成日计划求和，与ERP净销售口径相同。现财报目标不能直接移用，正式需要补源 |
| 店铺贡献 | 当前已覆盖销售分母；增长贡献=本店增减÷同期整体增减，仅完整两期适用，可负或超过100% |
| 商品 | 仅ERP SKU；不混SPU，不显示虚构店铺去重访客 |
| ROAS | 合成7日点击广告归因成交÷推广花费；不是利润率、增量利润或广告因果证明 |
| 库存 | 固定公司2026-10-01快照，需求2026-09-05—10-04；过期4天暂停采纳理论补货；不伪造历史库存或按店分摊 |
| 月盈利 | 2026-08完整财报公司利润、费用、同月目标；2026-09缺失。不得拆日，不与选期ERP数混称 |
| 缺源 / 零 | null与真实零区分；加载/失败不展示旧范围数值；库存和财报保持独立来源 |

默认范围含未接入店和无基期新店，整体严格比较受限；可选择京东或单店看完整比较。长名称店s2含销售增长毛利下降，s3下滑，K04负毛利，s8真实零，s6无旧基期，s7未接入；推广延迟到10月2日、库存过期与K05销量未匹配已覆盖。
