# Demo 03：多店经营对照矩阵

信息组织：共同经营结果与目标在前，平台 / 店铺矩阵是主工作区；选择店铺后查看局部趋势与 SKU 证据；商品、推广、库存、完整月财报、数据质量仍完整展开。专业模块模拟入口沿用共享事件处理。

交互：平台汇总 / 店铺矩阵切换；点击平台进入该平台全部店铺；按销售、毛利、增减排名；对象名称筛选；查看前五 / 全部；店名选择与详情；趋势期间证据；清除局部选择；恢复全部平台与店铺。共享日期、比较、粒度、平台与店铺控件保留。

真实参考：https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-matrix-visual 。本轮实际联网读取其层级展开、冻结行标题和局部横向滚动说明。借鉴统一指标矩阵与对象选择，并适配当前系统绿白主题、13px 表格、长店名换行。没有复制 Power BI 源码、样例数据或图片；样例仓库 MIT 许可 https://github.com/microsoft/powerbi-desktop-samples/blob/main/LICENSE 不代表 Power BI 产品开源。

业务适配：全部经营算法调用共享 createModel / createUI / ratio / movement。平台聚合也调用共享 createModel；不自行平均毛利率或 ROAS。矩阵仅放可归属平台 / 店铺的 ERP 与广告指标；库存货值与财报利润显示在独立公司证据，不按店分摊。缺覆盖、零值、不可比较与未知基期分别保留；没有库存健康分。

适用场景：多平台、多店复盘，定位销售增但毛利下降或投放效率差异。优势：同口径横向对照、对象钻取明确。代价：矩阵较宽，390px 需局部横向滚动；完整专业分析仍进入现有模块。正式实现复杂度中等，需全授权店集合、完整聚合、ERP / 店铺身份关联与广告来源口径校验。

作者自检：node --check 通过；使用共享模型 / UI 实际执行默认店铺、平台汇总、选店与空数据四种 render，均未抛出错误或出现 NaN。源码独立目录、七域齐全、所有按钮使用共享 handler 或本文件 onAction。浏览器尺寸、实际字体与控制台验收由总控 / 非作者执行，本作者未冒称通过。
