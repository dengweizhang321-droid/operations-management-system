2数据流线路图

2.1 导入主链路：上传 → 解析 → 幂等入库 → 派生 → 展示

① 上传数据导入页选来源或按文件名正则自动识别（FILENAME_SOURCE_RULES），拖拽上传
→
② 解析清洗各 app importer：openpyxl 流式（read_only + reset_dimensions）/ xlrd（.xls）/ csv（编码自动探测）/ zip；表头按 mappings.py 映射；错误行进 ImportReport 明确报错，不静默丢弃
→
③ 幂等入库统一走 common/bulk.upsert()：bulk_create(update_conflicts) 按自然键（dedup_key / (shop,date) 等）冲突更新，2000 行分块；批次记 ImportBatch，可删除回滚
→
④ 派生汇总网店导入后汇总回 JdShopDaily 店铺日表；成本/价格仅变化时追加历史；异常剔除生成负值冲销行
→
⑤ 查询展示只存可加基础量，转化率/客单价等比率在查询时按日/周/月聚合后再派生，保证周月口径正确；前端表格 + ECharts

2.2 预警推送链路

scheduler 容器每小时唤醒，到配置的整点触发（同日幂等）
→
push_alert_center汇总缺货预警、逾期/今日到期/即将到期工作计划
→
钉钉机器人webhook 加签发送；另可写入钉钉多维表（bitable.py）

2.3 幂等机制要点

  • 行级幂等：事实表用 dedup_key（行哈希）或复合自然键（如 (shop, sku, date)、(shop, date)）唯一约束，重复导入同一文件不重复计数。
  • 月级幂等：财报以 FinanceMonth.year_month 为锚，已导月份整月跳过。
  • 批次回滚：所有导入统一记 erp.ImportBatch（source 前缀区分来源），支持删除批次回滚。
  • 异常剔除：NetshopExclusion 以负值冲销行方式生效，resync_exclusions 幂等重建并联动店铺日重算，删除剔除即恢复。

4后端模块详解（8 个 Django App）

accounts — 认证 / 权限 / 审计 / 备份

全站权限的单一事实源，所有其他模块的写操作校验都依赖它。

核心模型：
  • User（AbstractUser + role：admin/member）、ModuleEditPermission（用户-模块编辑授权表，唯一键 (user, module)，只能授权给 member 且排除管理员专属模块）
  • ModuleConfig（模块读权限 read_access：公开/登录/指定账户/仅管理员/隐藏 + 导航排序）
  • AuditLog（导入/增/删/改/推送审计，只追加）、BackupRecord（pg_dump 备份记录）
权限注册表 module_registry.py：10 个模块枚举；ADMIN_ONLY_MODULES = 数据导入/销售分析/网店分析/系统设置；核心函数 can_read / can_edit / capabilities / serialize_me。
API：/api/auth/me|login|logout/；/api/backups/…（备份列表/创建/导入/下载/恢复）。
命令：seed_demo（幂等种子账号：admin / member_a / member_b）。

common — 批量幂等 upsert 工具

所有导入器入库的统一入口。

bulk.upsert(model, rows, unique_fields=…, update_fields=…, chunk=2000)：用 bulk_create(update_conflicts=True) 按自然键冲突更新，分块避免大内存与逐行往返（数十万行秒级而非分钟级），返回 (created, updated)。

erp — ERP（吉客云）销售明细

销售分析（毛利/退货/渠道）的数据基座；ImportBatch 被全系统复用。

核心模型：
  • ImportBatch：全局导入批次表（source 前缀区分 erp_sales / inv_ / jd_ / finance_report），记行数/新增/更新/错误/导入人，删除即回滚。
  • ErpSalesLine：销售明细事实表。维度：订单号/店铺/仓库/品牌/货品编号/分类；度量带符号（退货为负）：数量/金额/成本；biz_type（销售/退货/换货）；自营入仓标记。幂等键 dedup_key。
导入器：openpyxl 流式解析销售明细账，日期/金额清洗、缺字段报错；自营入仓识别（网店订单号 10 位数字 + 无需物流）。分析口径（净额/毛额/退货率）在 metrics.py。
API：/api/erp/sales/import|batches/（导入）；/api/erp/sales/overview|filters|summary|ranking|trend|split_trend/（销售总览/渠道分析数据源）。
关键口径：刷单剔除（warehouse='刷刷仓' 必须 exclude）；套餐/客单分析按网店订单号归并。

netshop — 网店分析（京东自营 / 京东 POP / 天猫）

事实表最密集的模块。所有表带 shop 维度，唯一约束一律 (shop, 原自然键)；店铺→平台由 finance.FinanceShopConfig 权威定义。

核心模型：
  • 主数据：JdProductMaster（商品主数据 + 全列 raw）、JdPriceHistory（采购价/京东价/到手价变化历史）、YimeiSku(+History)（亿美店长插件全字段 + 主图本地缓存）
  • 分天事实：JdSkuDaily / JdSpuDaily（SKU/SPU×日；访客/成交客户数是去重人数不可加，SPU 口径取 JdSpuDaily）
  • JdAdRow（推广行级：京东快车 CSV / 天猫万相台）、JdB2bRow（京东企业购出库明细，仅自营）
  • JdTradeOverview（交易概况·分天，京东店铺日权威来源）→ 派生 JdShopDaily（店铺日汇总，只存可加量 + 三来源完整度标记）
  • NetshopExclusion（异常数据剔除：店铺+SKU/SPU+日期 扣减销售/访客/成交人数/件数/推广成交额，负值冲销行引擎）
  • JdCustomGroup(+Member)（自定义分组，混合 SPU/SKU/品类）、JdProductNote（筛选级备注）
导入器：1500+ 行，xlsx/csv/zip 三格式，平台自动识别（含天猫生意参谋 .xls、发布模板、店透视 zip 抽取）；导入后自动汇总店铺日、联动完善库存 SKU 映射。
API：/api/netshop/import|batches/；分析：shop-daily / overview / product-analysis / product-search / b2b-analysis / category-analysis / promotion-analysis / products / price-history / note / custom-groups / exclusions。
命令：cache_yimei_images（主图本地缓存）。

inventory — 库存 / 主数据 MDM / 毛利测算

主数据地基：各平台商品编号 → 内部统一货品编号的映射；两套库存逻辑严格分开（自有仓 vs 京东自营仓）。

主数据 / 映射（MDM）：
  • Product（商品主数据）+ ProductCostHistory / SalePriceHistory（成本/定价带时间版本，算历史毛利用当时成本）
  • SelfopSkuMap（网店 SKU→内部货品编号，带 shop）、CategoryMap(+CustomCategoryOrder)、SupplierAlias、BrandConfig、WarehouseTypeMap、WarehouseGroup(+Member)、PurchaserMap / PurchaserCategoryMap、StaffMap / DeptMap（钉钉 unionId/deptId）
  • ProductParam（销售定价/自营入仓/货品组/多级分类）、ComboProduct(+Item)(组合装，成本动态算）、FeeItem（毛利测算中间费用项：多级 × 经营模式，按优先级解析）
  • InventorySettings（全局参数单例：目标库存天数/低周转阈值/钉钉配置/推送整点/BI 统计天数/自营扣点）
  • ReplenishmentPlan（备货计划，draft/confirmed 计为在途）、SlowMovingPlan（滞销清理，行级权限）
快照事实表：WarehouseStock（自有仓日快照）、InventoryAge（库龄批次快照，FIFO）、SelfopInventory（京东自营供应链库存，RDC/DC，含 1/7/30/90 天出库）。
服务：services.py（按货品汇总自有+自营+库龄+多窗口销量）、combo.py（组合装成本）、sync.py（商品↔映射↔配置打通）、bitable.py（钉钉多维表写入）、mapping_io.py（映射批量导入导出）。
API：导入与映射 ViewSet 12+ 个（module=data_import）；/api/inventory/overview|filters|age-analysis|age-detail|warnings|replenishment|slow-moving/（module=inventory）；/cost-history|margin-calc/（module=product）；/settings/（module=settings）。

finance — 月度财报 / 经营目标 / 网店店铺配置

财报按名扁平存储（字段增减无需改表）；FinanceShopConfig 是全系统「店铺→平台」维度的权威表。

核心模型：FinanceMonth（月份幂等锚）、FinanceLine（财报行，section=汇总区/金蝶科目区，唯一键 (month, section, shop, name)）、FinanceShopConfig（店铺开关/平台/链接）、FinanceFeeItemMap（费用项合并改名排序）、FinanceTarget（经营目标：销售额/利润/毛利率/清库存/推广占比/呆滞）。
导入器：WPS .xls（BIFF/xlrd），一 sheet 一月份，汇总区+金蝶科目区分段解析，同名科目按店铺列求和，从批注提取返点。
API：/api/finance/import|batches/；/months|shops|analysis/ 与 targets / shop-configs / fee-item-maps ViewSet（仅管理员）。
口径：财报销售额 = ERP − 返点单；自品牌事业部 = 6 店合计。

ops — 运营事务 / 预警中心 / 钉钉推送

日常流程管理 + 待办驾驶舱，唯一有定时推送的模块。

核心模型：OptionItem（变量字典：工作项/紧急度/跟进人/店铺）、WorkMemo（工作计划，「已逾期」动态派生）、NewProduct（新品上架 6 阶段 + 图片）、InspectionItem（巡店检查，可一键转工作计划）、ReviewPhotoPlan（评价晒图计划）。
API：ViewSet（行级权限）：/api/ops/options|memos|new-products|inspections|review-photos/；/api/ops/dashboard/（BI 运营待办）、/api/ops/alert-center/(push/)、/api/ops/dingtalk/test/。
命令：push_alert_center（scheduler 每小时调，整点触发钉钉推送，同日幂等）。

modules — 占位接口

给尚未实现独立页面的模块提供统一占位列表接口：GET /api/modules/<module>/items/（Module 枚举白名单，未知 404），前端对应 ModulePage.jsx。

5权限体系

角色读写
管理员（1 人）全部全部 + 用户/权限管理 + 数据导入 + 主数据维护 + 系统设置
编辑成员（2 人）按模块读权限配置仅「用户-模块编辑授权表」授权的模块（当前：巡店、工作推进）；管理员专属模块（数据导入/销售分析/网店分析/系统设置）不可授权
匿名公开模块只读（内网/VPN 内）无
  • 数据驱动，不硬编码：可编辑模块存 ModuleEditPermission 表；读权限存 ModuleConfig.read_access（公开/登录/指定账户/仅管理员/隐藏），未配置回退默认值。
  • 后端强校验：写操作（POST/PUT/DELETE）经 ModulePermission.can_edit；含成本/价格的读接口用 AuthenticatedReadModulePermission；财报/参数用 IsAdmin；工作计划等行级数据用 IsRowOwnerOrAdmin。
  • 前端跟随：/api/auth/me/ 返回每模块 can_read/can_edit，驱动菜单、Tab 可见性与编辑按钮。
  • 审计：AuditLogMixin 自动记录增删改与导入，审计失败不阻断业务。
