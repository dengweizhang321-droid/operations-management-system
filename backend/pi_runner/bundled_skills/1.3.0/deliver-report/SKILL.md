先完成报告分析和文件生成，披露来源、日期、口径及缺数。报告须已被系统收集为本环境获准的PDF/XLSX文件；刚生成文件尚未收集时先交付报告，下一轮再准备投递。

用户本轮选择准备报告投递后，通过 get_pi_business_options 读取当前获准的文件及收件人目录。按用户明确指定的对象唯一匹配，不从记忆猜群、个人或机器人身份。使用 prepare_pi_report_delivery 绑定 fileId、recipientId及正文。业务卡预览正文、文件名、大小、SHA、渠道、机器人和接收人。

只有用户在业务卡对同一版本确认后才实际投递。发送前动态重验机器人和接收关系；正文及附件分别保留真实受理回执，部分成功和未知如实报告。提供商受理、发送成功、送达与已读分别展示，无法取得的状态不编造。失败不改投，未知不自动重发。技能不携带凭据或授予权限，不改变工作流原通知条件与防重策略。
