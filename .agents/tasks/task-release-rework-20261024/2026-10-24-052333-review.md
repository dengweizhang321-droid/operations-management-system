### 准入与放弃的先后（v1 #3）

```
unresolved && abandonment
   └─ admitPreparation()  (assertConsumerIdentity + assertOrdinaryPreparationContext，只读探测)
        ├ 抛出 -> abandonmentAdmitted=false -> 不探测锁、不写 abandoned/ -> 按 dispatch 写 blocked，break
        └ 通过 -> 原有放弃门禁 -> 写 abandoned/ -> continue
                  └ 下一轮：清单重读，unresolved 为空 -> 再次 admitPreparation -> observe/prepare
```

两个准入函数都只做身份与令牌探测，不写盘，重复调用只多一次 PowerShell 探测。被拒路径与基线等价：基线在 unresolved 时同样先写 blocked 再 break，准入根本走不到。新测试先用抛出的准入驱动，断言调用序列只有 `admit`、`abandoned/` 不存在、原 unknown 字节不变、阻塞记录指向原 dispatch；再用通过的准入驱动，断言 `admit` 先于 `probe`、放弃记录写出、新票 `prepared`。撤回修复后该项失败，序列断言能挡住回退到旧顺序。

可辨识性缺口（Issue 1）：`catch{abandonmentAdmitted=false;}` 不保留错误，被拒宿主写出的阻塞记录与“期限未到/有标记/锁被占”写出的完全相同。早上若有人在提升权限的窗口里触发了消费，结果是 a3d53227 继续阻塞、新票被记 blocked、下一次放弃要等再来一张票，而记录里看不出原因。runbook 第 5 步的条件清单只有 resolution、期限、标记、轮换锁 4 条，准入写在文末“独审 v1 后的补充”，按第 5 步排查的人会漏看。
