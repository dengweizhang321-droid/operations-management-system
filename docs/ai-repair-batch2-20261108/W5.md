# W5 模型失败分层与报告模型选择

2026-11-08，第二批隔离工作树，源码基线 `ec71bd21`。执行请求为 `gpt-6.1-sol/high`，工具未回传可独立核实的底层型号。本文记录实施与验证，独立反审由批次负责人发起。

## 实施

- 模型诊断区分系统 DNS、公网 DNS 校验或恢复、连接、TLS、发送、响应读取、供应商 HTTP、响应解析、工具及收尾。诊断保留站内状态、供应商状态、是否已尝试发送及阶段毫秒数，供应商 HTTP 429 仍映射站内 503。HTTP 429 已知时直接记录状态，固定的订阅判断与钉钉摘要仅使用完整的 16 KiB 内拒绝正文。解析对畸形 JSON、SSE 和 Responses 字段使用固定原因。声明正文长度尚未收齐时拒绝 JSON 响应。
- 工作流日志沿用原 `clientRequestId`，同时记录任务、工作流、节点、派发及适用的工具调用 ID。对话沿现有请求审计收录适用的模型诊断，Pi 沿现有派发回执及冻结事件投影固定字段。工具耗时与收尾耗时在工作流层记录，细分模型传输耗时在同条日志单独列出，二者是父子计时，汇总时不要相加。
- 网店经营周报、库存健康报告与推广复盘复用 AI 流水线配置表单。用户可选择本次模型或使用当前默认。报告创建将显式 `modelId` 纳入原请求摘要和活动报告去重，并交给 `workflows.create` 固定实际模型 ID 和版本。新请求选择 B 时可与 A 分开创建，同一请求 ID 改换模型返回冲突。空跑显示选择且不调用模型。工作流遇到版本漂移时在调用前拒绝，并在报告详情标记实际失败节点。
- 模型网络调用继续使用既有精确 HTTPS origin、固定公网地址、TLS 和发送围栏。只有发送前的既有 DNS 或地址恢复逻辑可选择候选地址。历史失败与结果未知沿原账本留存，模型调用由新明确任务触发。
