## 实现边界

| 阶段 | 账本观察 |
| --- | --- |
| 准备、凭据、取 token、媒体上传、发送前身份 | 运行保持 `ready`。能证明尚未进入收件人请求的失败保留具体阶段；上传是准备，可能已有媒体上传，收件人消息仍未发出。 |
| 写出消息请求 | 复用最终 POST 钩子。动态核验当前应用、凭据和绑定。群路径核对原精确会话 ID 与唯一机器人安装，广东仓沿用来源复验。在同一事务按任务再执行槽顺序锁定，核对启用、版本、`ready`，提交 `sending` 预留。令牌、上传、群身份查询、DNS 都无法触发这个预留。 |
| 明确拒绝 | 终结为 `failed` / `dingtalk_send_rejected`。只采用明确拒绝类 HTTP 状态，或单聊响应明确拒绝本次唯一收件人且没有冲突的受理标识。 |
| 发出后结果不明 | 网关异常、超时、坏响应、相互冲突的收件结果、在途进程中断保留 `unknown`；没有自动重发或群/个人换投路径。已带新准备标记的 `ready` 恢复时能证明尚无收件人请求，记为准备中断。旧在途状态沿用原保守恢复，旧终态不会被恢复流程重写。 |
| 平台接受和后续可观察程度 | 仅有效 `processQueryKey` 及无冲突收件结果记 `sent`，固定写入受理键摘要及 `recipientObservation=unavailable`。页面展示“已生成”“平台已受理，送达及已读未核验”及未知状态。 |

停用和预留在同一任务行上串行。停用先提交时旧版本不能预留。预留先提交时按在途处理，真实迟到回执仍可结算原槽，停用继续阻止后续调度。已撤销群和已失效报告仍可通过原编辑入口停用其既有任务，重新启用时复核原依赖。运行保留同一执行槽和同一收件人。平台阶段和耗时写入原 `stage_details_json`，可识别的平台错误码保留固定值，其他短码、请求关联和受理键只留 SHA-256。原始响应、请求头、账号、会话 ID、消息、凭据及令牌不进入该诊断字段。[钉钉单聊机器人发送接口](https://open.dingtalk.com/document/orgapp/chatbots-send-one-on-one-chat-messages-in-batches) · [钉钉群聊机器人发送接口](https://open.dingtalk.com/document/orgapp/the-robot-sends-a-group-message)
