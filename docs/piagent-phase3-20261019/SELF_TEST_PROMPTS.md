# 上线后用户自测提示词

仅供用户自行执行，开发代理不执行。先完成应用、结构152、Runner及1.2.0镜像/技能的对应采用。补缺另需采用并激活登记的n8n候选，外发需当前渠道配置与账号绑定。

入口：“AI对话 → Agent”，使用未限定单店的执行环境及领域允许的操作账号。在输入区选择对应“本轮业务动作”。占位内容须替换成真实明确值。

## 工作计划

选择“创建工作计划”：

> 请创建并保存正式工作计划：标题“商品详情优化”，目标“完成指定商品详情改版”，事项“整理问题清单并完成新版详情”，负责人“【真实负责人】”，业务店铺“【完整店名】”，开始日期【YYYY-MM-DD】，截止日期【YYYY-MM-DD】，普通优先级。请返回真实对象链接和版本。

预期：参数完整后直接排队，正式对象保存完成才成功；缺负责人、店铺或日期时澄清。刷新读取原动作，不重复新增。

## 补货草稿

选择“保存补货草稿”：

> 请按系统正式口径，为仓库“【精确仓库】”、货品编码“【真实编码】”生成并保存可编辑补货草稿。展示库存日期、在途、近30日销量、建议量、计算依据和缺失信息，不下采购单、调拨单或发送供应商指令。

预期：正式库存writer保存draft并提供可编辑对象链接、版本与依据；缺资料或质量门禁未通过时不猜数。再次查询和刷新不形成第二次作用。

## 已注册补缺

选择“准备补缺执行”：

> 请查询已登记的天猫补缺能力。为“【六店之一的准确storeKey与店名】”，补齐截至上海昨天的七个完整日【开始日】至【结束日】的商品与推广数据。先复查缺口并展示精确工作流版本、日期、数据集及含原到期货品节点的完整范围，等我在业务卡确认后执行。分别报告受理、工作流、下载、导入批次和目标覆盖。

预期：无缺口不创建动作和execution；候选未采用或范围不支持时明确拒绝。确认后沿原完整链执行，只有批次与覆盖证据齐全才成功。取消不冒称已在途节点回滚，unknown不换ID重跑。

## 报告预览与定向投递

先不选择投递：

> 请根据【业务范围及日期】生成一份XLSX经营报告，列明来源、截止日、口径和缺失数据，并交付可下载附件。

报告已收集后，下一轮选择“准备报告投递”：

> 请读取当前获准接收对象，将上一轮报告准备投递到“【本次目录中的准确接收对象名称】”，正文为“【完整正文】”。展示机器人、渠道、接收人、正文、附件和SHA摘要，等我在业务卡确认后实际发送。返回各阶段真实状态，不自动重发或改投。

预期：预览不发送；确认绑定正文和附件版本。正文与附件分别保存真实提供商受理回执，部分成功或未知如实显示；无法取得的送达和已读状态不编造。改变正文、附件或接收对象须重新明确意图并预览。
