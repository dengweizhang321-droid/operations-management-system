# AI定时任务稳定性与广东仓监控试点

日期：2026-10-15，Asia/Shanghai。状态：隔离开发试点；不代表已合入、正式制品准入或生产采用。用户明确保留生产发布另行授权，长任务队列隔离不在本轮范围。

## 已实现

- 模型适配保留顶层兼容错误码，增加固定、无响应正文的解析阶段与原因。OpenAI 可选 `tool_calls:null` 只规范为无调用；错误容器、参数、缺失调用终态仍拒绝。推理只在本次内存工具回传中保留，原精确 OpenCode 请求头、会话头及模型 POST 不自动重放规则保留。详情与模型能力证据见 [PROVIDER.md](PROVIDER.md)。
- 普通连接、非流式工具闭环、SSE 工具闭环分别测试、保存和展示。首轮必须调用合成工具，第二轮准确使用首轮结束后新生成的随机结果。配置、参数指纹或适配版本变化即过期。没有将合成传输测试结果写入正式模型能力记录。
- 文本任务可独立绑定模型；空绑定兼容每轮解析当前默认，显式绑定失效不换默认。每轮使用独立会话，仍绑定原任务版本、执行槽、请求 ID、principal、scope 和投递身份。保存实际模型与配置摘要；付费调用前后及发送前复验。被任务绑定或在途运行引用的模型不能删除，已失效模型不妨碍停用原任务。
- 广东仓新增显式模式，中央能力固定取水位与广东人工启用清单，复用领域最终风险、自动风险、人工覆盖及备货跟进口径。系统保留完整汇总、前二十行重点明细、日期、来源快照及覆盖范围；AI 不自主选工具，只做结构化解释和建议。开放分析继续保留多轮工具与复杂推理。
- 校验 AI JSON、事实摘要、商品和证据引用、常见新增数值表达、渠道容量；系统渲染固定指标和风险。保留外链、@、HTML 净化，固定监控超出渠道容量则停止，不静默截断。校验不能证明全部自由文字语义正确，建议仍需负责人判断。
- 取数、分析、发送分别保存状态、阶段错误及时间。内容持久化后预留原 `sending` 槽；最终事实复验在目标准备完成、实际外发之前的 `before_send` 接缝执行。来源、业务日、模型、任务或权限变化均停止；预留后的失败保持保守 unknown，不再领取重放。没有自动基础简报降级或另一次付费生成。

高输出、长上下文、长任务时限、工具轮数及调用总数的原配置和自由调整能力均未降低。五分钟仍是领取窗口，不是已领取任务的执行时限。广东仓沿用领域 `inventoryStale` 规则（库存超过三天），销售及库龄展示实际日期，不新增“必须昨天”的跨域阈值。

## 数据与兼容

新增 `0083_schedule_execution_profile`，继承已有 `0082_no_new_keys_profile`：仅扩展两张既有定时表，含任务模型/模式、运行三阶段、模型快照、事实与已校验内容。无新增表、角色或密钥。增加数据库大小/类型/状态约束，readiness 同步检查；旧任务不自动转为广东模式，旧完成记录显示“旧记录未分段”。

广东来源快照复用库存缓存的库存、销售/ERP、authority 与业务日组成；既有广东 version 的 `_sales_revision()` 已包含 ERP，不能声称本次才修复 ERP 版本遗漏。新增字段提供完整快照绑定并用于发送前相等性复验，不做跨运行缓存。

正式广东任务、默认模型、真实模型参数、发送目标均未修改；旧 unknown 运行未重放。运行状态可辨认本次在哪一步停止，不把平台受理当作已读。
