### 恢复验证（`-Action RestoreTest`，本次新增）

抽样校验只证明"字节没坏"，不证明"数据能用"。R2 数据实际由两半组成：

- `site-creator-r2\blobs\` —— 对象内容，**39,846 个裸文件，文件名是 blob_id，不含 key 也不含类型**
- `miniflare-R2BucketObject\49e6826f....sqlite` —— 21.5 MB 索引，表 `_mf_objects`（`key, blob_id, version, size, etag, uploaded, checksums, http_metadata, custom_metadata`）

**缺了索引，blobs 就只是一堆无名二进制。** 所以恢复验证按索引取 key → 解析 blob_id → 比对 size 与 etag(MD5)：

```
index_objects=39846    blob_files=39846    （完全对应）
result ok=20 bad=0 missing=0 sampled=20
```

抽中的对象是 `market-images/v1/...`，content-type `image/jpeg` 与 `image/png`，大小 56 KB ~ 508 KB，均正常。这证明副本可恢复可用。

## 实现决策与依据

### 不复用 `tools/release-daily-backup.mjs`
该工具 `:7-8` import 了 `worker-local-release.mjs` 与 `worker-local-release-rotation.mjs`，`:10` 以 `D:\.codex\automations\e\automation.toml` 的 `status = "ACTIVE"` 作为调度门禁。附件备份挂上去会继承发布链耦合，在发布链改造期间一起失效——而那正是最需要备份的时候。本脚本零 import 发布链模块。

### 源目录全程只读
脚本对源只做 `Get-ChildItem` 与 robocopy 读取；SHA-256 清单基于**副本**计算，不给源盘增加读压力之外的任何写入。

### 踩坑：含中文的 .ps1 必须带 UTF-8 BOM
Windows PowerShell 5.1 按 GBK 读脚本文件。首版写成 UTF-8 无 BOM，中文字符串被截断，`switch` 块解析失败（`MissingExpressionAfterToken`）。加 BOM 后正常。本项目后续新增 .ps1 均需注意。

## 待你决定：每日计划任务

**1. 是否用 SYSTEM 账户。** 行动卡写的是 SYSTEM 级（无人登录也能跑）。但需先确认 SYSTEM 对源目录的读权限不被 ACL 挡住——审查 #6 指出启动时会对约 9.4 万个对象做 ACL 校验。
