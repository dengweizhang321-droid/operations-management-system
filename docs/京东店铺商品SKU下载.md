# 京东店铺商品 SKU 下载

> 本文描述 `wares-jdm.jd.com` 的商品主数据 SKU 导出。京东商智“商品明细 → SKU → 分天下载”的日数据流程请使用[《京东商智商品明细 SKU 日数据下载》](./京东商智商品明细SKU日数据下载.md)，两套流程不要混用。

## 适用范围

用于下载京东商家后台“售卖中”商品的 SKU 导出文件。

- 目标页面：<https://wares-jdm.jd.com/ware/wareList?activeTab=OnsaleWare&businessModel=0>
- 导出维度：SKU 导出
- 页面入口：`商品 → 批量操作 → 导出查询商品 → SKU 导出`

## 最快的日常操作

若存在 `outputs/jd-ware-export/active-task-<storeKey>.json`，先按其中 taskId 或 baseline 接管同店原任务；即使任务已完成，也不能新建。旧版全局 `active-task.json` 存在时必须安全停止并人工确认归属，不能静默忽略。没有活动清单时，恰有一个待处理任务则按 ID 接管；存在多个待处理任务时安全停止。只有显式使用 `--reuse-latest` 时，才复用其他已完成记录。

1. 直接打开目标页面，跳过左侧菜单导航。
2. 点击唯一可见的 `查询`，确认结果总数大于 0。
3. 打开 `批量操作`，再点击其中的 `导出查询商品`。
4. 保持 `SKU导出` 页签。
5. 在“导出记录”中确认目标任务 ID 唯一；待处理则继续等待，已完成才可下载。
6. 核对“执行结果”的成功条数后，只点击该任务所在行的 `下载`。

本次实测复用已完成任务 `9371960`，成功条数为 `1453`，从准备就绪到触发下载约 3 分钟。

## 需要新数据时

只有在没有待处理任务、且不复用现有完成任务时，才创建新的任务：

1. 打开目标页面。
2. 点击 `查询`，确认结果总数大于 0；为 0 时停止，不能创建空导出。
3. 打开 `批量操作 → 导出查询商品`。
4. 选择或确认 `SKU导出`。
5. 点击一次 `确定导出`。
6. 在“导出记录”中轮询本次新生成的任务 ID。
7. 任务显示 `已完成` 且成功条数符合预期后，点击该任务行的 `下载`。

不要因等待而再次点击“确定导出”，也不要下载记录列表中较早的同名文件。

## 自动化脚本

项目中的脚本为：[`tools/jackyun-ware-export.ts`](../tools/jackyun-ware-export.ts)。保留了原有命令名，以避免影响既有调用。

```powershell
# 复用最新的已完成导出任务（推荐的日常方式）
npm run jackyun:ware-export -- --reuse-latest

# 创建新的 SKU 导出任务，并等待完成后下载
npm run jackyun:ware-export

# 调整等待任务完成的最长时间，例如 120 秒
npm run jackyun:ware-export -- --task-timeout-seconds 120

# 需要页面截图排查时使用
npm run jackyun:ware-export -- --debug
```

脚本首次使用前，需要在其专用 Chrome 配置中完成京东商家后台登录。成功捕获下载事件时，文件会保存至：

```text
outputs/jd-ware-export/downloads/<任务ID>-<原始文件名>
```

运行审计结果会保存至：

```text
outputs/jd-ware-export/run-<时间戳>.json
```

## 自动化保护规则

- 直接访问商品列表 URL，不再逐级展开菜单。
- 不使用整页刷新轮询；只读取导出任务表，并按需点击“刷新列表”。
- 新建任务前记录已有任务 ID；下载时只匹配本次任务 ID，不使用“第一个下载”按钮。
- 同时检测到多个未知新任务时停止自动下载，避免误取其他人的导出文件。
- 下载点击已触发但浏览器没有返回下载事件时，不自动重复点击，避免重复文件或误判。

## 异常处理

| 现象 | 处理方式 |
| --- | --- |
| 提示未登录 | 在专用 Chrome 配置中手工登录后重试。 |
| 导出任务长期处理中 | 在页面点击“刷新列表”并核对任务 ID；不要再次确认导出。 |
| 多个新任务同时出现 | 停止自动下载，人工确认本次任务 ID 后再下载。 |
| 已点击下载但未看到文件 | 先查看浏览器下载列表；不要重复点击下载按钮。 |
| 页面显示商品页签数量但查询为 0 条 | 关闭残留抽屉，重新执行唯一的“查询”；仍为 0 时停止，不创建空任务。 |
| 下载数据不够新 | 不使用 `--reuse-latest`，改为创建新导出任务。 |
