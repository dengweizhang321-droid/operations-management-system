# 运营 Agent 工作流

入口：**AI 助理 → AI 流水线**。在“Agent 工作流”页也可点击“打开推荐工作流”。管理和运行沿用现有权限，仅无数据范围限制的管理员使用；单 Agent 与自定义 DAG 的原权限不变。

## 推荐的日常分工

下载、导入、批次核验继续交给现有 n8n 自动化；AI 流水线负责读取已导入数据、分析和形成待复核报告。人负责确认判断并在对应业务模块执行后续动作。通用报告流水线固定为 **核验取数 → 分析报告 → 人工复核 → 下载或单独确认通知**。

建议先使用“每日经营检查”和“数据健康检查”，确认数据可信后再增加专题分析。

| 推荐工作流 | 建议使用时间 | 主要输出 | 默认观察周期 |
| --- | --- | --- | --- |
| 每日经营检查 | 每天导入核验后 | 单店核心变化、异常依据、最多 10 项行动建议 | 上海昨天 |
| 库存与补货检查 | 每天或补货决策前 | 缺货/积压、现有备货、依据缺口 | 最近 30 个完整自然日 |
| 推广效果复盘 | 每周或预算调整前 | 来源 ROI、投入产出、异常对象及复查指标 | 最近 7 个完整自然日 |
| 新品进度跟进 | 每周或新品协调会前 | 七阶段进度、阻塞和待确认事项 | 最近 7 个完整自然日 |
| 数据健康检查 | 每天自动导入结束后 | 执行、批次、覆盖三层证据与未知项 | 上海昨天 |
| 客服质量复盘 | 每周 | 结构化会话摘要、常见问题、改进机会 | 最近 7 个完整自然日 |

以上是**使用频率建议**，这些流水线每次手动启动，不会自动创建定时任务。添加推荐也不会调用模型或发送消息。

## 配置和运行

1. 点击推荐卡片的“添加并配置”。系统一次保存对应的流水线、报告模板和分析方法，成为可重复使用的资源库配置。
2. 查看运行配置中的完整取数步骤、报告章节和写作要求。“编辑报告模板”可修改取数、章节、关注点和交付要求；展开分析方法后可直接编辑方法正文。保存追加一个版本，正在运行的报告继续使用原快照。
3. 填写精确平台、店铺名称；库存工作流填写实际来源及仓别/监控范围。选择起止日期，或点击“昨天”“近7天”“近30天”。快捷日期以 Asia/Shanghai 为准，均截至昨天；首尾日期都包含，沿用连续 1–93 天的后端限制。
4. 先“空跑（不调用模型）”检查流程结构，再按需点击“开始分析（调用模型）”。空跑不证明数据完整、模型可用或报告结论正确。正式分析使用当前默认文本模型，受原模型额度和工具权限约束。
5. 在“我的报告任务”查看详情、节点输出及报告。核对范围、截止日期和实际取数证据后人工复核；通过后才可下载正式 HTML/Excel。需要通知时另外选择渠道并确认。此功能不替代业务模块中的任务、备货或投放操作。

添加相同推荐不会覆盖用户已经修改或停用的资源。部分标识被占用、配置版本变化或资源库已满时会报错并保留原配置。可以刷新核对后操作，不要把报错理解为保存成功。历史版本仍可查看；旧版配置不会被推荐目录静默补写。

## 分析边界

- 推荐方法是可编辑的文字指导，不能扩展权限、开放工具或变成业务写入。中央工具注册表与 Django 执行器继续决定实际可用能力。
- 每次先核验真实数据新鲜度。精确店铺、仓别或时间范围无法由工具证明时，报告应列缺口；不得用跨店汇总或关键词搜索代替精确筛选。可用工具可能受运行模型、账号和现场来源状态限制。
- ERP 净销售、平台交易、推广归因成交是不同口径；不相加。区间去重访客不能用每天或每个 SKU 的访客数相加。
- 库存是最新快照；观察日期不把它变成历史期末库存。补货量必须有销量、可用库存和到货周期依据。
- 新品查询返回当前进度时不能反推历史完成日期。数据健康工作流须区分上海今天的调度状态与所查业务日期；n8n success 不等于已导入且覆盖完整。
- 客服复盘仅使用已授权的结构化摘要和标注，不获取原始客户聊天或身份。样本结论不代表全店投诉率或员工绩效结论。
- 六个推荐复用既有三种报告场景分类；例如日报、新品和客服在编辑器中仍属于既有经营报告类别。业务用途由推荐名称、模板及分析方法说明。
