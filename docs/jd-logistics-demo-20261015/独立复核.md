| 触发条件与原问题 | 最终处理与回查 |

| 原规划及合成仓名混入 C 仓 | 仓名改为 POP 示例物流仓；最终规划整篇收窄至流水、店铺商品和人工维护，C 仓仅保留范围外观察 |

## 关键逻辑核验

- ERP“已建单”始终显示为人工维护或人工标记；页面明确 ERP 台账尚未接入。未知人工值及超龄“待核对”仍为待核对，不自动变成真实缺单；缺 ERP 编号或名称优先显示待补映射。
- 调出与实收分别累计，不以正负净额归零判断成功。负向变动没有被解释为负结存；非调拨流水本轮不提供调拨状态维护。
- 人工状态保存按 `transferKey` 更新同一调拨商品的已加载事件，不绑定展示行号。反转源顺序不改变分组数量、出入量或京东进度；货主和商品不同会得到不同键。
- 初始及新账号的采集、监控、推送均为 false。关闭监控时风险卡片明确是示例试算；开关不启动真实流程。每账号超时阈值保存后，切换账号再返回仍保留各自值。
- 共享货主没有按账号复制一份可加的库存量；当前仅为小样本来源归属展示。真实一商品多店、重复采集和业务权限仍需最终规划所列的来源契约与后端验证，不能以本 demo 代替。
- 最终规划将人工状态独立保存，并要求新增流水后需复核、CAS 和源版本校验。本 demo 没有补历史或真实导入入口，本次没有证明正式历史补采链路已经成立。
