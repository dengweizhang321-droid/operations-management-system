## 实际计算与共享 consumer

`get_sales_summary` 保持 full/dashboard 默认与所有旧字段，只增加 core 和内部 `include_metadata`；summary consumer 跳过随后会被剔除的 filterOptions/latestBatch，返回键完全不变。商品经营 product_performance 原路径、BI dashboard、销售/AI/财务/搜索/网店/市场/库存相关消费者通过对应回归。

领域计算缓存固定32项、4MiB总量、单项1MiB、最长30秒，包含数据库连接身份、账号/角色/scope、双 revision、运行绑定 sales epoch/cutover 和原已授权 ERP authority；每次命中与发布复验，事务和非 autocommit 绕过，过大值不缓存。固定32条锁不淘汰在用锁。外层响应缓存从固定 hash 改为动态上下文 factory，在命中/等锁后/返回前复验；没有读取 reader 未获授权的 sales_write_authority 或扩权。

## 固定环境和计时定义

150000销售（2026年9月、2025年9月、2026年8月15天）、2000商品、60品类、120店/目标，另两家复合同名店月报。独立 cluster/回环端口/随机凭据、白名单环境、无生产URL回退。数据库页已热；各轮首测清空响应及领域两个缓存，串行三轮。直接域计算与带签名薄适配浏览器分别记录。
