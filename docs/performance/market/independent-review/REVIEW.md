## 源码结论

首轮发现设置工作区提前挂载导致数据配置在状态到达前固定今天为导入默认日期、图片状态到达后仍保留等待提示。另发现初始 null 状态被展示为“暂无任务”和零张待处理图片。作者分别将导入表单延迟至真实状态、同步清理等待提示、对未知记录显示等待与图片数量显示 `—`。最新源码的浏览器负例已通过。

后端改动保留原业务规则：full 首选记录仅延迟未消费的 raw_json；趋势先 SQL 统计完整身份 distinct 月份，再沿原排序取 60 行；图片状态 GROUP BY 与原 Counter 等价；非 data/all 工作区原本返回空 coverage，现直接省去该查询；comparison latest 保留同身份、排序与数据字段。没有发现扩大原始记录上限、改变价格/去重/投影排序/权限或改变自动化执行规则的代码。

最新趋势抽屉采用完整身份键、generation 与原有 readMarketJson 的期限/取消；重试只 GET。竞品比较禁止跨范围旧 payload 回退，同范围刷新失败仍保留成功数据，重新加载通过 refreshKey 触发同一读取。首轮指出趋势重试无即时反馈，追加两行修复后重跑七组独立取消/迟到/跨范围失败/同范围刷新恢复负例全部通过，包括趋势立即清错/展示加载与竞品原错误下重试状态。

真实非空设置复核暴露细分类目字符串数组被按 FilterOption 渲染的预存接线错误。市场专属前端适配两种形状、复用 workspace.categories 完整计数，缺失 count 显示 `—`；两个真实类别选取、请求身份与非空字典以及缺 SKU/标注统计保持 `—` 已通过。旧独立待确认价格 panel 被原全局 CSS 隐藏，当前实际入口是合并主列表价格状态筛选与编辑；没有通过修改全局 CSS 把隐藏兼容面板冒充新子页面。

60 条记录/2 个月的长窗口还暴露原两行 drawer grid 中间计数说明被挤成零高度。计数移入既有 header 后，原 grid 和共享 Dialog 保持，真实样式下说明可见、table scope=none/total=60、重复月份行键稳定的独立负例通过。后端旧 truncated 输出保持，UI 分开说明记录数与完整历史月份。

追加主数据 SQL 将原两次相同 CTE 的完整计数和取页合成一条，完整排序、最后页收敛与空集回执保持。独立基线必须另外加载原 main 的 master_query，并把 baseline_admin.master_page 指向旧函数，不能让基线和候选共用新函数。84 组完整响应验证按这一绑定执行；60 组 master 边界每次捕获候选只有一次包含 source 的 CTE SQL；这不等同于执行计划只扫描一次 selected 中间关系。合成单 SQL 仍受原 7 秒门槛，宽范围两个旧查询分别低于上限不等于新一个查询也低于上限，真实 PG 规模重测仍必要。

新增图片 distinct 总量标量缓存复用已有 FilterCache 的身份、revision、锁和失败退避；独立缓存实例容量仅 256 字节，原筛选缓存 2 MiB 保持。ready/failed 图片状态仍每次读取，不能依赖事实 revision 缓存该状态。已有浏览器预取/请求合并/分页保持。浏览器缓存仅 requestKey 的历史身份绑定限制没有在本候选扩大缓存范围或 TTL；若公共底座调整缓存，必须独立验身份与权限。新加载反馈立即出现，debounce 从 350ms 改为 150ms，不能将这项响应反馈改善当成数据库查询提速。

## 范围与尚未完成的验收

既有竞品比较范围缺陷独立复现：公开 route 传递日期/类目等参数，但 backend comparison 只按完整选中身份读取全部历史汇总，没有使用日期与其他筛选。在仅含 2026 年 10 月事实的合成库，传入 2000 年 1 月及不存在的类目仍返回两个商品及非空指标。前端新 scope 键防止旧请求显示到新范围，不能替代后端范围正确性；“基线深等价”也只证明保留原行为。`nonempty-equivalence.json.knownCompareScopeGap` 保留此事实。该页不能称完整业务口径验收完成，修复应另有明确预期与边界验证，不能为保持与错误基线相等而忽略它。
