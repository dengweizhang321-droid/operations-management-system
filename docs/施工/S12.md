# S12 · 蓝绿发布可行性与可选设计

**类型** 可选架构方案；实施范围另定　**依赖** S07　**优先序** 16

先读[看板](BOARD.md)与[执行约定](执行约定.md)。准备与维护优化后仍有明确中断损失，且收益足以覆盖实施和维护成本时才启用；不是主路线必做项。

## 必答边界

- 真实固定端口、进程回执、supervisor、effective head与activation fence是否允许旧新共存，须改哪些受保护入口？
- 前门如何切流、排空在途请求及长连接，静态资源/会话如何跨版本兼容？
- Django/Worker两版本与数据库结构是否兼容？writer、调度器、导入、AI runner等后台职责如何保持唯一合法所有者？
- 回退后数据/结构是否仍兼容，哪些变化只能前向恢复？不承诺所有版本均可回退。
- 额外内存、端口与运行维护成本是否值得？故障时维护兜底如何生效？

不能以“不改内部”作为预设同时承诺零中断；若确需生命周期/业务/结构变化，明确范围和授权后再实施，不隐含扩大本单。

方案不成立则取消S12及S13，保留维护路径。S14/S15、S16/S17与S18继续，不存在跳单死锁。设计完成不等于已上线；S13必须有实际实现、对应制品及必要兼容/恢复材料后才可采用。
