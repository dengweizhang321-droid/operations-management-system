# 发布提速施工执行约定

本文件是[看板](BOARD.md)的操作边界补充，不替代[项目规范](../../AGENTS.md)。旧单与本轮新计划冲突时，未来执行按本文件和当前规范；历史事实、原回执不改写。

## 范围与完成

- 每次任务按项目启动协议读取相关规范，不再执行“不读规范”的旧要求。新开发从最新 main 独立分支/worktree 开始；源已冻结后的准备/发布不得漂移目标。同步 main 按现行流程，不机械禁止 fetch，也不在未知准备期间用推送试队列。
- 已通过事项复用有效成果；B1 已合入，不再推一次旧分支。源码完成、合并、制品就绪、控制采用、应用上线分开记录。文档规划不授予控制采用、服务启停、队列写入或生产发布权限。
- 检查遵守[发布检查与功能验收分工](../规范/验证与发布.md#发布检查与功能验收分工)：只做构建、部署、启动所需检查，按变化补必要兼容/恢复边界，不默认全仓测试、业务接口验收或多轮复审。成功依据原生回执，不再额外扫业务健康；功能由用户检测。
- 生产动作通过已采用固定入口；BAT 只是包装，不能直接复制旧 worktree 中命令。原生 PREPARED 缺失时不能上线，排队、冻结请求、non-production 都不是目标应用制品就绪。
- 静态结果仅在源码、依赖、工具、配置、制品和适用前驱等绑定仍有效时复用；动态身份、锁、排空、前驱和期限按实际门禁即时复验。
- 原件留在证据文件；聊天/看板只给简要结论、关键字段与链接，不要求整段日志灌入上下文。没有找到应说明搜索/枚举边界，不能凭一次未命中断言不存在。

## 恢复与长任务

unknown 原件保留，停止依赖它的新写入；不得伪造 FAILED/SUCCESS/resolution，不手动删 owner 或更换身份重放。恢复必须先证明精确分支适用；已审源码未采用不等于现场入口具备能力。

准备阶段 unknown 只能由已采用工具写出的放弃记录关闭，且须通过其资格检查（包从未被消费、发布目录无上线阶段标记、过期限与宽限、轮换锁空闲、无 resolution）；原 unknown 保留，重新准备使用新包目录。上线阶段 unknown 仍然阻塞；仍不得伪造 FAILED/SUCCESS/resolution。（2026-10-24，S05d 通用机制）

现有 cleaned-preparation 的跨普查检查可能因新 shell 而拒绝；只在确实采用该协议的观察窗口内按其门禁协调，不把限制推广到全部开发/发布时间。临时停用 watchdog、计划任务或 n8n 属于独立生产影响，须纳入具体授权与恢复清单，不能由本看板自动授权；不得随意终止别人的进程。

“关闭状态查看窗口”与“终止承载准备的进程树”分别判断。防中断工程先核真实宿主、父子进程、日志落盘及终态协议；不根据单个退出码认定用户关窗，也不借提速删除 unknown 保护。改动若无根因证据或无收益，单独记录而不扩成宿主重构。

## 计时与 ROI

| 指标 | 起止与用途 |
| --- | --- |
| 准备交付等待 | 最终目标合并/触发至对应原生 PREPARED；拆队列、冻结、复制、依赖、编译、摘要/封装、后台准备 |
| 上线后总等待 | 用户该次明确上线指令至必要交付收尾；若指令早于准备完成，照实包含准备等待 |
| 就绪后执行 | 已就绪版本实际发布开始至必要收尾；与用户等待另列 |
| 业务中断 | 原生维护/排空/启动时间线及已有业务可用性证据分别列；采样间隙不填为零 |

保留原始时间、目标及制品摘要；父子重叠阶段不累加。分开正常、失败恢复、迁移、冷/热缓存与变更类型，样本少时只报告样本，不宣称稳定 P95。缺失阶段填未观测，不用计划预算补实测。

现行15分钟是制品就绪后的常规发布交付优化目标；含准备的总等待另设实测基线与降幅，不冒充同一口径。维护≤2分钟、首请求接近稳态及零中断均为按适用场景评估的目标，不是已达成事实或强制杀进程时限。

排序表记录适用次数/占比、每次净省时、实现与维护投入、证据可信度，单位一致后才能算回收期。异常恢复收益与正常每轮节省分别列，不重复计算。先利用现有日志和自然发布样本；不为了取得漂亮数字额外发布同一版本。配对比较真实小改动、后端/文档等实际出现的类别；没有代表样本则结论保持有限。

## 批次与退出条件

同一批可以覆盖多单，必须逐单关联实际采用字节与原生结果。恢复控制采用有独立身份/版本条件；首次采用新的分类/缓存能力，仍按现有工具执行，不能提前消费未来优化。

分析/代码单若证明现有能力已满足或该方案净收益不成立，可按“通过：无需实施”结案，列依据和遗留限制；采用单相应记“不适用，无生产动作”，不能声称上线。若已有批准的关键目标未实现，须明确报告未达，而非用“不适用”掩盖失败。

可选项的未实施不阻塞 S18。收尾只核本次文档、证据及符合条件的工作树；用户改动、未合并或仍在用的树保留，不按“仅保留生产一棵”笼统清理。
