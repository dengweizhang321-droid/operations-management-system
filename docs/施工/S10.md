# S10 · 按证据消除重复启动

**类型** 可选隔离代码　**依赖** S05c；需新维护数据时补S07　**优先序** 12

先读[看板](BOARD.md)与[执行约定](执行约定.md)。

仅在精确进程/日志证实重复启动、已有唯一生命周期入口仍有真实缺口，且预期净收益值得投入时启用。无证据或占比很小则保持可选/取消，不阻塞S18。

复用既有单例/互斥/owner机制，明确启动者与等待者的身份、失败、取消及有界等待。不得用固定sleep替代状态判定，也不得无界等待以满足“永不超时”。

等待方超时可以是合法结果，必须明确未取得所有权、不会并发启动及业务实际状态。首启动者失败后只有原协议能证明安全接管时才允许接手，不能把超时自动变成接管权限。

交付缺陷证据、机制边界、必要并发/启动代码检查、前后净收益和S11采用路径。不为观察而在生产故意制造启动失败。
