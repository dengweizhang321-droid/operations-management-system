## 本单要做什么

### 步骤 1 · 审查 B1 对 `worker-local-service.ps1` 的改动（只读，先做）

```powershell
git -C D:\codex-worktrees\merge-20261022 diff origin/main...2dd8f23f -- tools/worker-local-service.ps1
```

**必须逐函数确认**（结论写进交付）：

| 检查 | 已初步观察到（须自己复核） |
|---|---|
| 是否触及 worker **停止**路径（`Stop-*`、进程终止、信号处理） | 全 diff 中 `Stop-` / `Kill` / `Terminate` / `Signal` **0 次命中** |
| 新增内容是什么 | `Write-WorkerStartupTiming` 新增约 138 行（启动计时观测），`BudgetMilliseconds` 4 处（预算数字） |
| 是否改动 `Start-VerifiedWorkerSupervisor` / `Invoke-WorkerSystemStart` 的行为 | 有改动，须说明改的是什么、是否影响"停止/维护"语义 |
| `Maintenance` 相关出现 5 处 | 逐条列出原文，说明是否只是注释/参数名 |

**任一项显示"停止或维护路径被改动"** → 停止，报告，不改白名单。

### 步骤 2 · 给门禁加 worker 侧已审资格

现在的结构只允许 django 一个例外。本单要把它改成**每个控制器各自的已审集合**，但**语义不能放宽**：

- 每个控制器名各自持有一个"已审候选哈希集合"
- 候选哈希不在自己那个集合里 → 仍然**失败关闭**
- 未登记的控制器名 → 仍然**失败关闭**（不许"未知 name 默认放行"）
- 先把 B1 的 `worker-local-service.ps1` 新哈希登记进去（值 = B1 分支里该文件的 sha256）

**同时必须保留**：
- `piNativeCandidateDjangoScriptSha256` 这个既有常量或等价语义（S04a 登记的 `65f05729…` 必须继续有效）
- 所有既有断言一条都不许删

### 步骤 3 · 测试（必须覆盖"不该放行的仍不放行"）

1. B1 的 `worker-local-service.ps1` 新哈希 → 不抛
2. 任意的其它 worker 哈希 → 抛 `实际原生控制器代际与候选不一致：worker-local-service.ps1`
3. S04a 登记的 `django-local-service.ps1` = `65f05729…` → 仍不抛（回归）
4. 任意其它 django 哈希 → 仍抛
5. `process-deadline.ps1` 未登记任何哈希 → 仍抛
6. 未知 name（如 `foo.ps1`）→ 必须抛
7. 既有 `tests/` 里相关用例全跑，记录原始输出、退出码、以及**改前基线对照**

- **本单不合并 B1**，B1 留给 S05 的第一步
