# S16 · 准备阶段热点优化

**类型** 隔离代码　**依赖** S05c、S08　**优先序** 5

先读[看板](BOARD.md)与[执行约定](执行约定.md)。不依赖S15或蓝绿，也不依赖S05已上线。

## 按实测选择手段

以已有前端阶段1455秒为线索，依据S05c拆解，优先处理占比大且经常发生的依赖准备、源码/产物复制、重复摘要或封装成本。已经实施的复用不能重复记收益。必要时只补最小分项计时，不先做一整套缓存平台。

## 缓存与复用边界

1. 分开依赖缓存、构建中间结果和最终制品。完整源码树最终制品缓存主要解决同版本重复准备，不能用它证明新版本发布提速。
2. 输入绑定须覆盖实际影响产出的源码/依赖锁、工具链版本、构建参数/配置、目标平台等；保留原 cacheLockSha256 与完整性/路径门禁。不能只凭mtime、文件名或提交号复用。
3. 新输入必须得到针对新输入的有效产物；可复用经工具保证的未变部分，不要求所有源码变化都无差别全量重建。无法证明边界时回到当前受控完整构建。
4. 缓存损坏要显式记录并拒绝复用。仅在既有或审定的干净重建分支中重建；不吞错继续，不修改未知/生产状态。
5. 完整产物摘要/清单验证与抽样诊断分开；抽样不能声称全部逐字节相同。不可重复字节因素先说明，不能随意剔除字段凑一致。
6. 原生准备/制品回执仍绑定最终候选与实际产物，不能拿旧PREPARED覆盖新候选。

## ROI 交付与退出

优先复用已有日志及隔离构建的必要输出，比较真实小改动的冷/热情况、依赖变更、同版本复用。报告样本和适用频率，不强制三次生产发布或重复全量构建取数。

交付热点前后净省时、成本/风险、输入闭包、采用方式和未达目标。收益不足则记录“通过：无需实施”与原因；不能把文档缓存收益当功能发布收益。S17关闭实际采用与效果。
