## 为什么要这一单

S04 发布时被这道门挡死（`publish-559e64fd8586/preparation/FAILED-c8e0ea7a-….json`）：

```
phase            = 核对维护前驱资格
maintenanceStarted = false      ← 维护从未开启，停机 0 分钟
error = 实际原生控制器代际与候选不一致：django-local-service.ps1
        + 'c9e72fcc…'  (installed)
        - '65f05729…'  (candidate)
```

原因在 `tools/manual-maintenance-continuation.mjs`：

```js
export const piNativeCandidateDjangoScriptSha256='d012318c82d7db60…';
export function assertMaintenanceControllerGeneration({name,installedSha,expected,candidateSha}){
 if(installedSha===expected)return;
 if(name==='django-local-service.ps1'&&candidateSha===piNativeCandidateDjangoScriptSha256)return;
 assert.equal(installedSha,expected,'实际原生控制器代际与候选不一致：'+name);
}
```

**候选侧 `django-local-service.ps1` 只允许等于那一个"已审"哈希。** 而 A1 的修复**恰好就是改这个文件**
（把"关闭门禁时真的去 spawn `wrangler --version`"改成纯 JSON 事实校验），新哈希 `65f05729…` 不在白名单里 → 失败关闭。

**这是门禁在正常工作，不是 bug。** 要发的修复必须先被审查、登记为"已审前驱资格"。
