# S08 · 精确分类与有效结果复用

**类型** 隔离代码/缺口分析　**依赖** S05c　**优先序** 4

先读[看板](BOARD.md)与[执行约定](执行约定.md)。恢复未闭合不阻断隔离分析/开发，但禁止新生产 dispatch。

## 先复用已有能力

最新主线 release-scope-plan 已识别 docs、README、AGENTS 与 tests 的非生产变化。先核真正消费入口和生产到候选的完整差异；只改docs却仍准备，可能是尚未发布的其他代码或控制代际，不直接认定分类器失效。

## 只补证实的缺口

- 区分文档/离线测试、仅控制包、Worker载荷、Django载荷、共享依赖及未知输入，完整检查重命名的旧新路径。
- 禁止“tools/** 一律轻量”。明确工具依赖闭包、打包成员、配置/安装器及调用消费者；只在证明不影响应用载荷且有正式控制采用路径时免应用重建。
- 未知按现行完整范围处理，不能把工具改名挪目录来规避。
- 核已就绪同源码/制品的原生复用与同轮静态校验复用，保留动态前驱、身份、锁、排空和期限。
- 机器可读字段先复用既有回执，缺必要字段才兼容扩展；不为统一格式重写所有回执。
- 工具文件清单由真实调用闭包决定，不照旧单限制3个文件导致有判定无消费者。新增/替换范围必须有直接证据，不作无关重构。

## 必需检查与采用交接

核文档/测试、已证明仅控制工具、运行时工具、前端、后端、混合和未知路径的判定边界及实际消费者。只做必要发布程序检查，不推无意义main提交来验分类，不跑业务测试。

交付分类表、实际节省对象、闭包证据及采用方式。首次采用是否仍要完整准备必须明示，不能提前套用新分类；S09负责采用。若现有能力已满足，记录“通过：无需改动”及依据，而非重造。
