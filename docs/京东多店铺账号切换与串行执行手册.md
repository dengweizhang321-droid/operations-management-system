# 京东多店铺账号切换与串行执行手册

## 目的

本手册用于店铺 SKU、商智 SPU 分天和商智 SKU 分天任务的多店铺运行。系统通过店铺注册表和独立 Chromium profile 隔离账号，按顺序完成一个店铺后再切换下一个店铺。

## 安全边界

密码、验证码、Cookie 和 Token 不保存到程序、Markdown、Skill、配置文件、日志或 Git。首次登录必须人工完成；程序只复用已经登录的浏览器 profile。

## 店铺注册表

文件：`config/jd-store-accounts.json`

每项至少包含：

- `storeKey`：脚本使用的稳定键
- `accountLabel`：账号提示标签，不是密码
- `shopName`、`shopId`：店铺识别信息
- `browser.executablePath`：受控 Chromium 程序
- `browser.userDataDir`：Chromium 用户数据根目录
- `browser.profileName`：`Default` 或 `Profile N`
- `browser.profileDir`：`userDataDir/profileName` 对应的实际独立 profile 目录
- `browser.debugPort`：独立 CDP 端口
- `browser.downloadDir`：独立下载目录

当前四店映射为：设备旗舰店使用 `Default`，厨电旗舰店使用 `Profile 1`，切肉机旗舰店使用 `Profile 2`，洗碗机旗舰店使用 `Profile 3`。修改注册表后，必须检查店铺键、shopId、端口、解析后的 `profileDir` 和 `downloadDir` 均不重复，`profileDir` 必须精确等于 `userDataDir/profileName`，并确认目录可用；平台字段只能是 `京东`。

## 首次登录

对每个 `storeKey` 单独运行对应脚本，Chromium 打开后人工登录并完成验证。确认页面显示的店铺名与注册表一致，再关闭对应窗口。不得在命令行参数、环境变量或文件中传入密码。四店共享同一 Chromium 用户数据根目录，因此只能由受控 runner 严格串行启动；如果普通 Chromium 窗口正在占用该根目录，自动任务必须失败关闭，不得强制结束未知窗口。

## 运行方式

单店店铺 SKU：

```powershell
npm run jackyun:ware-export -- --store-key jd-yiyong-director
```

单店商智 SKU：

```powershell
npm run jdsz:product-detail-export -- --store-key jd-chudian-weizhang --dimension SKU --start-date 2026-07-01 --end-date 2026-07-19
```

全部店铺串行运行（`--mode all` 固定按主数据、SKU 日数据、SPU 日数据执行）：

```powershell
npm run jd:all-stores -- --mode all --start-date 2026-07-01 --end-date 2026-07-19
```

只跑一种日数据时使用 `--mode sku-daily` 或 `--mode spu-daily`；只重跑失败店铺时加 `--store-key <注册表键>`。`--dry-run` 只写入 `planned` 审计，不会标记完成。执行器一次只启动一个店铺，成功后才切换下一个店铺；任何失败都会停止，不会自动跳过。

完全静默运行时增加 `--no-visible-recovery`。该模式仍使用后台有头 Chromium 并直接保存下载文件，但登录、验证码、安全验证或店铺身份异常时只失败关闭并保留审计，不打开可见窗口；需要人工登录时另行显式使用 `--interactive-login`，两种模式不得同时混用。

每轮只写一个 `outputs/jd-multi-store-runner/run-*.json` 审计文件。步骤会依次记录 `planned/running/completed/failed`，失败项包含子进程 stderr 摘要；成功项记录下载路径、批次 ID 和行数。不要把下载完成当成已导入，只有子程序 JSON 中带有通过验证的批次结果才表示已自动导入。

## 故障恢复

1. 记录失败的 `storeKey`、阶段、任务 ID、审计文件和下载目录。
2. 检查对应 profile 是否仍登录、页面店铺是否匹配、是否存在多个待处理任务。
3. 不要重复点击未知任务，也不要盲目复用“最新”任务。
4. 修复后只重跑失败店铺，例如 `npm run jd:all-stores -- --store-key jd-chudian-weizhang --mode all`，验证导入结果后再继续后续店铺。

```powershell
rg -n --hidden --glob '!node_modules/**' 'password|secret|token|Cookie' config .agents/skills docs
git diff --check
```

检查结果不得包含实际密码或会话凭据。
