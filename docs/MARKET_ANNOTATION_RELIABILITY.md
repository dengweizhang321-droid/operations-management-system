# 市场 AI 标注调度与复核修复

本说明对应 `codex/market-annotation-throughput` 候选代码；尚未在正式运行环境采用。入口为“市场分析 → 系统和 AI 设置 → AI 标注与批量入库”。

## 已确认原因

2026-09-13 从本机同源公开 API 只读检查任务状态（运营 MCP 不可用，使用本机替代来源）：5 条计划的云端运行状态均为 running，其中一条总数 9,330、失败数 5,386，抽样失败原因为“账号或数据权限已变化”。这些是检查时的任务状态，不能视为实时数据覆盖或所有失败类型的全量统计。

- 旧后台使用固定的市场调度身份获取 AI 模型配置；AI 域对真实账号权限复验时拒绝该身份，错误被记成图片失败后仍继续领取。
- 定时器一次只识别一张图，设置并发没有转成实际派发；无指定任务的领取只检查最早任务，满载或无候选时阻塞其他计划。
- 复核资格依赖前端最近 50 个任务及最近 300 个 Prompt，与全部历史结果的跨任务查询不一致；大任务还没完全结束时，已完成图片也被禁用。筛选、全选和入库的服务端规则存在差异，批量入库缺少前端依赖的 500 条分页回执。

## 修复后的执行方式

1. Django 返回有界可运行计划及其真实创建人；后台先实时复验创建人权限，模型调用前再次复验。身份或模型配置失效立即暂停，显示可操作原因，不连续消耗其他图片的尝试次数。
2. 每轮公平选择最多 5 条计划，每条按当前可用槽分配；总计最多 50 个并发通道。权限与协调租约准备各自有请求时限，准备完成后开启最多 10 秒的新图领取窗口、最多 200 次领取，随后只等待已启动的请求完成。准备较慢不再消耗全部领取窗口，其余计划在后续定时唤醒中轮转。并发配置、冷却、协调租约和单图租约以 PostgreSQL 为权威，浏览器只负责控制和轮询。
3. 普通超时/网络错误降低并发并冷却对应通道；供应商限流在相同模型的计划间共同退避，其他模型继续运行。连续成功后逐步恢复配置并发。
4. 同任务内相同类目、口径、SKU、榜单维度和图片哈希的跨月候选共用一次模型结果，成功和扩散在同一事务完成。完成写入使用固定请求身份重试回执，不重新调用模型；云端租约过期且结果未知时整组隔离、暂停并要求人工核验，不能把未知结果当作未执行。
5. 单次模型 HTTP 最多 90 秒，模型请求还受本次租约剩余时间限制，预留结果落库时间。模型成功与数据库回执失败分开处理；回执丢失不得把成功结果改记为模型失败。
6. 过期租约清理先检查是否存在过期推理；没有时直接返回，避免在同模型锁内扫描整个候选积压。2026-09-13 正式只读等价查询发现，4,919 条待处理候选的空过期相关扫描耗时 6,922 ms，而过期存在性检查不足 1 ms。该数据仅证明查询瓶颈，不能推算模型提速倍数。

本机部署要求运营系统持续运行；关闭浏览器可继续，关闭电脑或停止系统后不能继续执行。提高并发不能补偿权限失效、模型限流或服务离线。

## 复核与批量入库

- 已识别完成的单条候选即可复核，不必等待整条大计划结束。服务端返回该候选的有效枚举及资格，历史任务列表截断不再影响可选性。
- 列表、全选和入库使用一致的类目、细分品类、识别来源及入库状态规则；不跨出当前筛选。无可选项、未加载完成或权限限制会显示原因。
- 全选前先保存当前页未保存的编辑；重复全选不反复增加候选版本。每次入库最多 500 条，通过 `hasMore` 继续处理，回执幂等且保留审计；任务仍有待识别项时继续运行。
- 并发领取、人工编辑和入库统一锁顺序，并保留候选版本、当前图片快照和正式价类型校验。

## 验证与采用

使用独立工作树和合成 PostgreSQL 集群，运行 `tools/market-annotation-postgres-rehearsal.py`，覆盖多计划、公平领取、配置动态变更、通道冷却、同模型限流、跨月去重、租约过期、提交回滚恢复、跨页筛选、重复选择及 500+1 入库。镜像同时验证当前市场 reader/writer 最小权限。

TypeScript 行为测试覆盖并发总量、任务公平分配、失权拒绝、调度预算、回执错误不再推理和选择资格；另运行市场现有测试、全量单元测试、lint、生产边界检查与隔离构建。真实模型吞吐量、供应商限流和现有失败任务的受控恢复须在授权采用后单独验收，不以合成模型延时推算真实提速倍数。

本次无数据库结构迁移、生产写入、模型付费调用、服务重启或旧任务重放。发布时需一并采用 Django 与 Worker；旧失败记录保留，不自动重置封顶项。

候选验证结果：真实 PostgreSQL 市场测试 51/51 通过，市场定向测试 105/105 通过，全量单元测试 2,129 通过、0 失败、23 跳过；最终运行器与派发测试 11/11 通过。lint 为 0 错误、11 项其他文件的现有警告，隔离构建和 430 模块后端边界检查通过。整仓 `tsc --noEmit` 仍报告未触及的历史测试/工具类型错误，未标记为通过。可提交证据见 [验证记录](evidence/market-annotation-reliability-validation-20260913.json)。
