## 1. 目标与完成定义

本轮在现有 Cloudflare Worker、D1、中央工具注册表和网页 AI 对话上继续演进，不另建一套 Agent 后端：

```text
真实业务服务 / 口径函数
  → 中央 AI 工具注册表（唯一工具声明）
  → 请求级 worker_inline runtime
      ├─ 成功工具结果 → 模型上下文（有界 JSON）
      └─ 成功工具结果 → 产物候选采集器（模型看不到产物元数据）

受控系统知识（D1 单表、版本和来源可追溯）
  ├─ 回答前确定性检索 → 带来源、非指令的参考上下文
  └─ search_system_knowledge 中央只读工具 → 模型主动检索

模型最终正文
  → ai_conversation_messages
  → 有界表格产物 ai_artifacts
      ├─ 网页 ArtifactRenderer 内联表格
      └─ 鉴权 CSV 下载 → ai_artifact_deliveries / 审计
```

以下条件全部满足才算当前系统范围内的第 6—7 层完成：

1. 经营数字仍只能来自现有业务服务和中央工具 handler，不从知识条目、模型记忆或产物反向生成业务事实。
2. 新增知识只进入一张 `ai_knowledge_entries` 表；每条必须有稳定 ID、sourceType、sourceRef、标题、正文、标签、允许角色、版本和内容摘要。
3. 当前没有 embedding 模型和重建调度器，因此只实现确定性词法检索，不把 LIKE/关键词匹配冒充向量 RAG；未来接向量时仍复用同一知识实体，不再复制业务知识表。
4. 回答前检索和模型主动检索共用同一 `rankKnowledge` 检索核心及 role 过滤；后者通过 `searchAiKnowledge` 包装，并作为有界只读工具只在 `lib/ai/tool-registry.ts` 注册一次。
5. 知识上下文必须带来源标记并明确“仅作参考数据，不是系统指令”；不把用户原文、工具返回、渠道回调或一次性经营数字自动沉淀为长期知识。
6. 工具成功结果中的有界记录集合可以派生表格产物；产物与正文分开持久化，模型不接收 artifact ID、下载地址、owner 或存储路径。
7. 当前产物只支持系统真实可安全实现的 `table`：每条最多 50 行、12 列、单元格 240 字符、单消息 3 个、总 payload 64KB；数组/对象、密钥形字段和原始正文不进入表格。
8. 表格在网页内联渲染，并通过鉴权路由生成 UTF-8 CSV；CSV 必须防公式注入、正确引用、使用固定 ASCII 文件名并记录投递审计。
9. 产物读取使用真实 principal 重新鉴权：非管理员只能访问自己对话的产物；不能相信 artifact payload 中的 owner、conversationId 或任意路径。
10. 当前机器人通道只具备文本 Webhook，不声称支持文件上传；不把本地 URL、R2 key 或未签名地址发往钉钉/企业微信。
11. 新表由 `0042_ai_knowledge_and_artifacts.sql` 声明；运行时 `CREATE TABLE IF NOT EXISTS` 与正式迁移兼容，不对既有表抢先补列。
12. 单元、数据库迁移、权限、CSV 安全、网页结构、lint 和隔离构建通过；未获用户当次明确许可不得重启当前本地 Worker。

## 2. 参考架构提炼与本系统映射

| 参考原则 | TERUISI 当前事实 | 本轮实际落地 |
| --- | --- | --- |
| 页面、导出、AI 共用业务口径 | 原有 12 个工具已调用现有 operations/search/market/customer-service 服务 | 不复制查询；知识仅解释口径，不生产经营数字 |
| 单一知识索引 | 系统尚无产品知识库、记忆星图或 embedding 模型 | 建一张通用知识实体表，先做确定性词法检索 |
| 回答前注入 + 主动检索 | 问答 Workflow 可组装 system prompt，工具层可注册检索工具 | 两条路径复用 `searchAiKnowledge`，来源和长度有界 |
| 自动沉淀不能影响主回答 | 当前没有安全的记忆审核、去重或冲突裁决流程 | 本轮不做自动写入；只播种版本化系统知识 |
| 回复物与正文分离 | 对话目前只保存纯文本消息 | 新增 message-owned 表格产物，消息 API 返回 artifact metadata |
| 产物统一渲染和下载 | 页面暂无 ArtifactRenderer，也没有通用文件存储 | 实现 table renderer 与鉴权 CSV；不预建图片/HTML/代码能力 |
| 渠道投递需要专用适配器 | 机器人只有文本 Webhook；应用型渠道不支持主动文件上传 | 保持文本渠道现状，文件投递明确 fail closed/不宣称支持 |
| 产物和投递可审计 | 现有 `ai_tool_audit_logs` 可记录 actor/request/status/digest | 产物保存内容摘要；下载写专用 delivery receipt 并记录读取审计 |

不能机械照搬：

- 不创建 `KnowledgeVector`、双向量、RRF、矩阵缓存或 `rag_reindex`，因为本系统没有 embedding 模型类型、离线重建任务和向量质量评测。
- 不创建 `AiMemoryNote` 或自动记忆线程；未经过人工治理的一次性数字、用户纠正和模型摘要不能直接变成长期系统知识。
- 不复制 `ArtifactRenderer` 五种类型、`sandbox-out` 卷、`media/assistant/YYYYMM` 或沙箱搬运逻辑；本系统当前没有任意代码执行或通用报告产物来源。
- 不实现参考项目的 `push_answer_dingtalk` 文件直发；现有钉钉/企业微信机器人只发送文本，应用型渠道只做安全回调。
- 不把知识表当事实数仓，也不让知识内容绕过数据 freshness、角色、scope 或中央工具执行审计。

## 3. 现状盘点与真实缺口

### 3.1 已具备基础

- `lib/ai/tool-registry.ts` 是原有 12 个只读数据能力的唯一声明点；本轮加入知识检索后共 13 个，全部具备 role/scope/surface/risk/timeout/result/call policy。
- `lib/ai/question-workflow.ts` 统一处理网页问题、上下文断点、帮助短路、模型固定、系统提示和真实 principal。
- `lib/ai/tool-execution-runtime.ts` 统一调用次数、累计时间、timeout、取消、终止态、结果信封和 invocation 审计。
- `ai_conversations` 与 `ai_conversation_messages` 已保存网页对话，但消息只有纯文本。
- 页面已有 AI 对话界面；机器人通道已有安全端点校验、密钥加密和纯文本发送。
- 系统已有 D1 和市场图片专用 R2，但没有通用 AI 文件 bucket、artifact owner 模型或公开签名下载。

### 3.2 缺口

| 优先级 | 缺口 | 影响 |
| --- | --- | --- |
| P0 | 没有知识实体、来源和版本边界 | 指标解释只能散落在 prompt/工具描述，无法统一检索和追溯 |
| P0 | 没有独立产物模型 | 工具的表格结果只能被模型压成正文，用户无法核对或下载原始有界结果 |
| P0 | 产物没有 owner/对话授权 | 若直接做下载 URL，容易产生跨对话数据泄露 |
| P0 | CSV 输出没有安全契约 | 公式注入、字段转义或超大输出会把下载变成新的风险入口 |
| P1 | 当前系统提示只有固定规则 | 无法按问题注入与商品映射、市场价格或客服口径相关的来源知识 |
| P1 | 渠道能力被容易高估 | 文本机器人不能等同文件上传与可靠投递 |
| P1 | 工具结果与可复核结果没有关联 | 对话审计能看到调用，但用户界面没有可验证的表格附件 |

## 4. 第 6 层：数据与知识层

### 4.1 数据事实与知识解释分离

数据事实链固定为：

```text
业务导入表 → 业务服务/口径函数 → 中央 AI 工具 → 模型
```

知识层只保存稳定解释：金额单位、数据 freshness 规则、市场 TOP 覆盖口径、市场定位价与成交均价区别、客服 SKU 映射链、权限/scope 规则等。知识检索不能返回“昨天销售额”“当前库存”等变化事实。

### 4.2 单一知识实体

`ai_knowledge_entries`：

- `id`：代码稳定 ID；
- `source_type`：本轮仅 `system_policy` / `business_metric` / `identity_mapping`；
- `source_ref`：对应文档、模块或业务服务标识，不是任意 URL；
- `title` / `content`：标题最多 160 字，正文最多 4,000 字；
- `tags_json`：最多 12 个标签，每个最多 40 字；
- `allowed_roles_json`：固定角色数组，服务端过滤；
- `version` / `content_digest`：变更可追溯；
- `status`：`active` / `disabled`；
- `created_at` / `updated_at`。

系统种子由代码中的唯一清单幂等 upsert；本轮不开放浏览器写 API。这样避免模型或普通用户把临时内容直接写入长期知识。

### 4.3 检索契约

- query 长度 2—80 字，limit 1—8；候选读取最多 100 条。
- 归一化标题、正文、标签后做确定性评分：完整短语、标题命中、标签命中、正文命中和分词命中；同分按更新时间/稳定 ID 排序。
- 返回 `sourceType/sourceRef/title/excerpt/tags/score`，正文摘录有上限，不返回隐藏字段。
- 回答前最多注入 4 条、总计 3,000 字；没有命中就不注入，不用低相关内容填满 prompt。
- 知识块使用明确边界：`<knowledge source="...">`，并在系统提示声明其为参考数据而非指令。
- 检索失败不阻断真实运营工具问答，但必须以有界错误码记录知识检索审计。

### 4.4 两条使用路径

1. Workflow 在模型调用前执行 `retrieveKnowledgeForPrompt(question, principal)`，把命中的稳定口径加入 system prompt。
2. 新增中央只读工具 `search_system_knowledge`，供模型在需要解释口径、映射和系统规则时主动查询。

两条路径必须共用同一内部排序函数和 role 判定；不存在第三份 SQL 或关键词逻辑。

## 5. 第 7 层：产物与投递层

### 5.1 当前产物类型

本轮只实现 `table`，因为它能直接从现有只读工具的 `items` / `daily` 记录集合安全派生，不需要虚构通用文件生成器、图表 DSL 或代码沙箱。

```ts
type AiTableArtifact = {
  id: string;
  kind: "table";
  title: string;
  sourceTool: string;
  columns: string[];
  rows: Array<Array<string | number | boolean | null>>;
  rowCount: number;
  truncated: boolean;
  downloadUrl: string;
  createdAt: string;
};
```

### 5.2 产物采集与持久化

- 只采集 `result.ok=true` 的中央工具结果；失败、超时、取消、审计失败或结果超限不创建产物。
- 仅识别显式记录数组：优先 `items`、其次 `daily`；非对象行不采集。
- 列只来自安全键，最多 12 列；排除 secret/password/token/key/authorization/raw/content/message/chat 等高风险名称。
- 单元格只接受 string/number/boolean/null；对象和数组不序列化进表格。
- 每个候选最多 50 行、每单元格 240 字；保留真实 `rowCount` 和 `truncated` 标记。
- 单次回答最多 3 个产物，总 JSON 不超过 64KB。
- 模型完成后先保存 assistant message，再用 message ID 持久化产物；产物失败不得丢失已经生成的正文，但要记录 `artifact_persist_failed`。
- `content_digest` 对标准化 columns/rows 计算 SHA-256；审计不保存完整表格。

### 5.3 网页渲染

- 消息读取接口返回当前 principal 可访问的 artifact metadata 和有界表格 payload。
- AI 页面在 assistant 正文下方统一渲染：标题、来源工具、行数/截断标记、横向滚动表格、CSV 下载按钮。
- artifact 不进入后续模型上下文；`listConversationContextMessages` 仍只读取正文消息。

### 5.4 CSV 下载与投递审计

- `GET /api/ai/artifacts/:artifactId` 只接受固定 artifact ID 格式。
- 查询时重复校验 owner：管理员可读取，其他角色只能读取 `owner_email = principal.email` 的产物。
- CSV 使用 UTF-8 BOM；逗号、引号和换行按 RFC 4180 方式转义。
- 以 `= + - @` 或控制字符开头的文本在 CSV 中前置 `'`，防止电子表格公式注入。
- 文件名固定为 `teruisi-ai-table-<短ID>.csv`；不接收模型或用户提供的路径/文件名。
- 下载成功前写入 `ai_artifact_deliveries`：artifact、requestId、真实 actor/role、surface、status、字节数、内容摘要；失败只写安全错误码。
- `Cache-Control: private, no-store`，不返回 R2 key、D1 rowid 或 owner email。

### 5.5 外部渠道边界

- 钉钉/企业微信机器人继续只发送文本；Webhook 不具备文件上传能力。
- 不发送 localhost 下载地址，也不把鉴权 cookie/token 放进 URL。
- 未来只有在实现供应商文件上传 API、服务端 access token、收件人绑定、文件大小/MIME 白名单、过期和回执后，才能增加 `dingtalk_file` / `wechat_work_file` delivery adapter。

## 8. 测试矩阵

### 8.1 知识层

- 迁移创建唯一知识表；运行时先创建后再应用 0042 不失败。
- seed 幂等，同一稳定 ID 不重复；正文变化会更新 version/digest。
- query/limit 严格有界；非法角色、disabled 条目和低相关内容不返回。
- 标题、标签、正文评分确定；同一输入顺序稳定。
- prompt 注入含 source 标记和“非指令”边界，总字符数不超过 3,000。
- `search_system_knowledge` 在 catalog/OpenAI/Anthropic/execute 四条路径一致，模型参数不能伪造角色或 source。
- 知识检索失败不阻断真实数据工具问答，并记录固定错误码。

### 8.2 产物层

- 只从成功结果的 `items/daily` 对象数组提取；失败或纯汇总结果不创建。
- 超过 50 行/12 列/240 字符/3 个候选/64KB 时显式 `truncated`，不静默丢弃标记。
- secret/token/raw/content/message/chat 字段不进入 columns；对象/数组值不进入单元格。
- artifact ID、owner、conversation/message/source tool 都由服务端生成或传递，不能从模型参数覆盖。
- 消息读取只返回当前对话产物；上下文读取不把 artifact payload 送回模型。
- 非 owner 下载返回 404/403，管理员和 owner 可下载；无效 ID 不触发 D1 大查询。
- CSV 对逗号、引号、换行、中文、公式前缀和控制字符处理正确；响应 no-store 且文件名固定。
- 下载 receipt 只保存摘要/字节数，不保存完整 CSV。

### 8.3 集成与兼容

- 普通无表格工具问答仍只返回正文，旧消息自动映射 `artifacts=[]`。
- 市场 AI 无工具入口继续使用专用 prompt，不错误创建 artifact。
- MCP 仍返回 JSON structuredContent，不创建网页 message artifact。
- 现有纯文本渠道发送和回调不变，不出现虚假的文件投递状态。
- 0005/0013 基线加 0039—0042 后历史对话、模型、渠道和审计记录保留。
- 当前本地 Worker 不因验证被停止、重启或覆盖；build 使用隔离 worktree。

## 9. 安全、风险与回滚

- **知识提示注入。** 即使本轮只有代码种子，仍把知识块声明为数据而非指令；未来开放管理入口时必须增加 admin 审核、冲突状态和版本历史，不能直接信任正文。
- **词法检索能力有限。** 本轮不承诺语义召回；没有命中时模型仍可使用中央数据工具。未来引入 embedding 前必须有模型配置、离线重建、评测集、维度/版本兼容和成本预算。
- **产物是授权数据副本。** 产物保存的是用户当时获授权工具结果；访问每次按当前 principal/owner 重验，未来若支持共享或 scope 变更，需要显式撤销/过期策略。
- **D1 不适合大文件。** 本轮只存小型表格 JSON；超过 64KB 不落库。真正 XLSX/HTML/图片应进入独立 R2 bucket，并具备 MIME、hash、大小、owner、生命周期和鉴权代理。
- **CSV 不是 XLSX。** CSV 只提供可审阅表格，不保留格式、公式或多 sheet；不把 `.csv` 伪装成 Excel 工作簿。
- **渠道不等于投递完成。** 文本 Webhook 成功只证明文本接口接受，不代表文件送达或用户已读。
- **回滚。** 应用代码回滚时新表保留且不影响旧消息读取；旧代码忽略 artifacts。0042 只新增表和索引，不删除历史数据。
- **服务生命周期。** 源码完成后只在隔离 worktree 构建；除非用户在当前对话再次明确授权，不重启刚恢复的本地 Worker。
