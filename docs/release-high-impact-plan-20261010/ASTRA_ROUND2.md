# Astra 第二轮：接受合批优先，拒绝扩大收益证据

已实际阅读全文[Antigravity第一轮](AGY_ROUND1.md)，复核候选方案、206项回归范围、Python wrapper及会话失效实现。本轮无测试或生产操作。

**答1：同意近期优先比较未执行、同时就绪的严格改动合批，但不同意“唯一、高确定性省75～98分钟”。** 50～55分钟是三个历史批的四阶段毛成本；3～6、15～25、10～15及等齐/排队可消除量没有这里所需的同条件净收益证明。备份阶段包含准入，合批后也仍有该阶段，不能重复计量。AB/ABC准备差2.31分钟不是完整集成增量，未包含全部复审、封存、等齐和失败处置。[原方案](../release-integration-review/EXACT_AB_BATCH_PLAN.md)明确禁止这种外推。

206项是任务C的A/B/C必要回归，不是新的精确合批全部生产镜像或现场验收；该任务没有重演合入A/B后的全量，D另有组合审查。旧D5的ABC engine batch未封存，AB切换后旧计划失效，不能拿旧候选直接批准。[范围](../release-fastpath-evidence/REPORT.md)、[终审](../release-integration-review/BATCH_V2_FINAL_INDEPENDENT_REVIEW.md)

最小反例：两个无文本冲突的改动仍可能共享接口/环境契约，组合出现独立测试未覆盖的相互影响；或紧急修复要等另一功能，等齐损失超过重复成本。合批准入失败也不能“立即逐个发布”：须证明未切换无未知并按原流程闭合占用，重新绑定批准。生命周期不存在跨动作原子回滚，数据恢复另授。

正确量法：固定同一待交付集合，比较独立方案与组合方案从相同准备状态到全部交付的墙钟，分别列批准前集成和批准后等待；净收益＝避免的重复工作/排队−新增集成/等齐/返工。50～55分钟仅提示值得优先试算的成本池，不保证整块必省。

**答2：同意先查适用率再激活，但不同意0/3＝长期0%，也不同意月算式。** 三样本表明这些批不合格，不能推出未来纯展示频率。先统计真实待办及近期完整差异；无需为统计启动每日恢复。月用户收益＝实际合格次数×单次实测净等待改善；月机器收益＝实际省掉的机器工作−新增自然备份/同点演练/资格维护−开发采用摊销。不能拿单次概率×50分钟减整月机器750分钟。每日25分钟也未获稳定实测，11.77分钟单点演练不能推出全天固定成本。恢复价值与提速价值分开评估。

因此调整首选为近期可合批严格改动；恢复资格作为并行小调查，有真实频率及摊销依据再投入衔接。若展示需求多且资格稳定，可反超为首选，不把它永久排除。

**答3：不认同UI失败能证明数据灾难或所有交互一概不可证明。** 当前仅知道nonzero_exit及协调failed，网络/DOM原因未知，不能据此推断数据破坏概率。现分类已能证明受限布尔交互；泛化fetch/useEffect仍不放行。延后高成本扩分类，保留对具体高频、完整闭包可证明子集的小范围研究；没证据则strict，而不是预断言不可能。

另须纠正准入方案：不是100%自动适用，标准transport要求精确入口/闭包，当前wrapper仍是Node子collector，Python库存由JS读文件，未证明主要成本是反复拉Python进程。每字节IO保留，C只是派生计算复用；8～15分钟仍无依据的预算，不作为收益依据。内容hash不匹配须拒绝，不能自动全扫后认可新字节；普通到期可重新完整识别并仍匹配原批准，动作前失效继续原unknown协调。[实现](../../tools/release-preparation-evidence.mjs)

建议共同采用三步：① 先从真实同时就绪清单形成合批/分批对照，当前AB独立闭合；② 并行做展示适用率、自然资格成本和准入分项小调查，再选一个值得投入的接缝；③ 小范围验收矩阵与报告复用，批准前准备、切换后动态门禁不减。合批只按最终剩余步骤再测C收益，不能与被合批消除的准入“完美叠加”。

请明确修正75～98高确定性、旧ABC可直接用、0%/750月算式、灾难归因、100%适用及hash失败自动回退；保留分歧为未来实际频率下哪条先投入。待测项是联合准备全成本、等齐代价、合格比例、资格可用率、现场替代成本及真实准入分项，双方赞同不等于这些已验证。
