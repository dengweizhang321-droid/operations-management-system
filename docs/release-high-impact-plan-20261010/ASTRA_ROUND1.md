# Astra：优先减少整轮固定成本

2026-10-10，baseline 3e08f023。独立只读意见，未读本轮Antigravity报告。16:14[截点](current-observation.json)显示AB仍active，45事件，UI第三次unknown后独立协调为failed，未completed；不猜根因、不改变在途批。

我修订此前顺序：当前真实验收故障必须按原流程闭合，但不应把建设全域行级授权解析器作为高收益优化的先决工程。首选验证已有恢复复用的适用频率和持续资格，支持路线是减少重复严格发布；准入优化与分类扩展按实测投资。

**首选：持续提供可复用的恢复点。** [现有方案](../release-fastpath-evidence/DAILY_BACKUP_ADOPTION.md)已具备多数基础，改造限于自然备份结果、同点演练衔接与失败审计。对应工具首次仍严格采用，另获唯一调度授权；每个新保留点完成自然Backup、Verify、同点完整Restore/序列/清理后才合格，最新失败或未知不能被旧成功覆盖。26小时点、7天同点演练、现场软件/目录/权限及三份保护策略不变。

毛成本参考是历史前后两备份＋两恢复阶段50.612～55.397分钟，包含其准入，绝非净收益保证。令G为同条件完整流程中实际被替代区间，V为快路径新增现场资格/验证时间，F为失效后的额外等待：每次用户净等待改善＝G−V−F。日后台新增成本D＝自然备份＋对应演练＋归档/资格维护的实际增量；不能把必要日备份已有成本再记一次。月机器净改善＝合格发布次数×每次被省机器工作−ΣD−首次严格采用及开发摊销。用户等待与机器工时分列，不能混算。

频率是决定性门槛：先用近期真实最终差异按现分类回放统计合格比例，不运行生产。此前三历史批均strict，不能拿它们证明适用率。投入为已有入口接缝、最新失败覆盖负例和自然演练审计；后台演练也可能争用发布锁，需量并避开实际在途任务。若资格覆盖少、反复失效或摊销不成立，就停止为提速扩建，日备份本身的恢复价值另评估。资格失效则阻断，原批安全闭合/取消后重新封存完整流程，不中途补跳步骤。

**并行支持：把“多轮严格”变“一轮精确组合”。** 只适用于尚未执行、同前驱、同时准备好且独立验证完整的改动；不把旧批准拼接。两批合一的毛节省是一套重复严格步骤，备份恢复部分可参考上述50～55分钟，另有切换/自然验收固定成本但须实测。净收益＝两独立批次实际区间并集−组合批总区间−新增集成/返工/等齐成本；不能另加被其覆盖的恢复复用收益，更不能把历史145分钟排队全算节省。

无固定日后台成本；每遇一组可合并改动可用，投入主要是组合准备、依赖/回滚兼容复审和计划编排。紧急修复、数据迁移与无关高风险功能、尚未完成验证的功能不等齐；组合首次验证失败在批准前拆回独立计划，已执行失败仍原协调。先用真实待发布清单比较“各自最早交付”和“组合最早交付”；组合等齐吞掉节省就不合并。

**准入与验收矩阵：小投入验证后再扩大。** [wrapper](../release-integration-review/batch-v2/collector.mjs)仍逐次Python7918文件后启动子collector。打通C必须保留完整字节/环境及动态门禁；已有三阶段身份配对仅省21.6～24.2秒，23～42分钟历史准入不是全部可省。毛收益是可消除的进程/派生计算，替代成本为会话核验与完整重读，净收益取实际配对差；无新增日任务，频率覆盖使用新入口的批次。先分项测wrapper、Python、制品、Status；若主成本不可消除且仅秒级改善，不投入大重构，失败回原子进程路径并保留记录。

批准前完成组合测试、真实候选、fixture和工具副本预检；现场保留精确版本/资源/权限/就绪、变更相关真实交互和自然守护。未变行为证据只在完整依赖和环境绑定有效时研究复用，不减首次控制链验收。矩阵净收益＝原重复静态验证−重绑定/现场替代；后台成本是准备工作前移，不叫总机器消失。离线报告仍计入全部交付，配对无收益则保持原矩阵。

**延后：全域行级鉴权与泛化“客户端只读”分类。** 前者投入大且不直接省四项恢复；后者须证明所有请求/状态副作用、权限/归属、完整依赖及写入不可达，不能按fetch/useEffect名称放行。先从高频真实低风险差异抽一个可证明子集评估：净收益＝新增合格次数×实测恢复净改善−证明/维护/误判处置投入；频率与开发成本未知，无日备份之外固定成本。若只能覆盖罕见语法或负例不能闭合就停止，全部回strict。现有B来源证据可小范围复用，缺失仍阻断，不先造全系统账本。

2. 两批合一的等齐与集成风险怎么量，如何避免与恢复复用、准入收益重复累计？
3. 愿意为哪个具体高频只读交互子集投资证明，什么结果会让你停止扩分类？
