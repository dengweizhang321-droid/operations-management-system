# 更高收益的发布优化：优先减少整轮重复工作

2026-10-10，Asia/Shanghai。用户认为P0条件性节省5～15分钟不足，要求Antigravity与GPT-6 Astra重新讨论。两位实际完成独立意见、交叉质询/答复与最终澄清；本轮只有只读方案和文档，没有实施或生产操作。

**建议改变投资顺序：近期优先对同时就绪、尚未执行的严格改动做精确合批；并行调查持续恢复资格的实际适用频率；准入和验收矩阵先做小范围分项验证。** 当前真实阻断仍需原流程闭合，但不先为常态提速建设全系统行级鉴权或泛化UI证明工程。

## 为什么这比单独P0更值得比较

历史三批前后2次Backup＋2次隔离Restore阶段分别 **55.397、50.612、53.204分钟**，是每次严格发布的大固定成本池。只减少误报协调，不能消除这个池；两次严格发布若在条件成立时成为一个精确组合批次，则有机会少做一整套重复数据库阶段及部分维护/准入。

50～55分钟是历史毛成本，包含阶段边界准入，不是保证净省。必须扣除新增联合验证、等齐、额外任务验收、资格检查及返工。历史145分钟排队不能直接再加上去；已在两方案总区间里的成本不能重复加减。此前三批都strict，不能拿它们证明展示路径已可用或未来永久0%。

**建议把“每个真实可合批机会，中位净省至少30分钟”作为扩大投入的验收目标。** 这是价值门槛，不是已测成绩。若仍只有秒级或5～15分钟收益，就不扩大重构；正确性、恢复保障和当前真实故障的必要修复另行评价。

## 路线一：同时就绪的严格改动，一次组合发布（近期首选）

1. 汇总真实待发布清单，逐项确认代码、独立测试、依赖、精确回滚/前向恢复及必要业务验收都已准备好。只合并共享同一实际前驱且兼容的改动。
2. 从该前驱构造固定组合源码、唯一不可变包、联合验证和一个新精确批次；排除main中无关未批准功能，保留每项原任务全部验收与副作用授权。
3. 完成准备和独立复审后，一次明确批准组合范围，一轮严格前后备份/恢复、维护切换、自然守护和必要收尾。组合不是拼接旧批准，也不自动固定为原21步，步骤需覆盖最终实际范围。
4. 紧急修复不等未就绪功能；互相影响、不可兼容迁移、无法独立回退的高风险组合拆开。未切换时若失败，先按原规则证明无未知/副作用并闭合占用，再准备独立计划；已执行异常继续原协调/兼容回退，数据库恢复另授。

**收益边界：** 一组两次严格发布变一次时，约50～55分钟数据库重复成本值得优先试算，另有重复准入/维护成本待测。净收益若被等齐和集成成本吃掉，就不合批。每次只有一个严格改动时，这条路线没有可合批收益。

**当前边界：** AB已经切换，不能换成旧D5 ABC。旧候选/计划对当前前驱已失效；任何下一次C或组合都须按实际新前驱重新构造、绑定、封存与批准。本轮没有发给原执行者任何指令。

## 路线二：持续恢复保障，供真正合格的发布复用（先调查，再投入）

复用 [现有恢复资格方案](../release-fastpath-evidence/DAILY_BACKUP_ADOPTION.md) 和 [批次协议](../RELEASE_BATCH_WORKFLOW.md)，不再发明第二套备份：对应工具先严格采用，另行授权原唯一自然备份调度；每个新保留点衔接同点完整演练与清理，最新失败/未知覆盖旧成功。

合格发布现场复验26小时内仍保留点、7天同点演练、软件/目录/权限/角色/序列及实际影响证明；资格变化仍拒绝。三份与保护策略不变，新点可能淘汰旧演练点，需要持续衔接。日备份/演练的后台耗时和对发布通道的争用必须单列，不把夜间工作说成消失。

**收益边界：** 每个合格展示发布可研究替代约50～55分钟四阶段毛成本，减去现场资格验证与失效处置后才是用户净收益。当前四文件可执行交互仍strict，单个严格改动不自动适用。先看真实生产前驱→最终制品的完整差异与待办频率，main提交只能辅助；不是先开启生产演练才能调查。

若合格改动频繁且资格稳定，这条路线可反超为首选；若样本很少，则不为提速先投入每日演练接缝的大工程。备份及恢复本身的数据安全价值独立于发布节省，不能因展示样本少而断言它为负。

## 路线三：准入及验收，先找真正瓶颈（小投入支持）

现wrapper仍逐次校验7918个Python文件再调用Node子collector；装入C代码不等于标准in-process transport已生效。C既往三阶段身份实验仅省21.6～24.2秒，不能推出准入8～15分钟或所有批次100%适用。

先分项读取既有日志并在获准隔离样本中测wrapper、Python、源码/工具、完整制品、动态Status与恢复资格。包括动态Status内部的成本，不把所有23～42分钟准入都当作静态散列。若真正瓶颈在进程创建、派生计算或重复安全读取，才打通受控接缝及有界并发；保持完整字节、硬链接/重解析点、动态身份/权限/就绪、动作前检查与共同期限。

hash不匹配拒绝，不自动扫描后认可新字节；仅正常证据过期可按原批准重新完整识别。Status不能被TTL替代。合批后已删除的步骤不再算C收益，只测剩余步骤。

按真实影响准备验收矩阵：批准前完成候选/fixture/工具副本与组合回归；切换后保持精确版本/资源/权限/组件、受影响的真实交互和自然守护。未变行为证据只在完整依赖/环境证明有效时研究复用，工具自身首次采用不减验收。离线报告提前固定模板，锁外收尾仍计入用户等待。

## 暂不做的工程与停止条件

- 不为常态5～15分钟收益先建全系统行级业务授权账本；当前数据差异用已有B及拥有方证据尽量收口，无法证明仍阻断。
- 不强行将useEffect/fetch、前端目录或Django摘要未变划为display。可以从真实高频、狭窄的只读交互子集研究完整依赖、请求与全局副作用、权限/归属、写入可达性及独立负例证明。不能闭合或覆盖极低就停止，保持strict。
- 不以UI nonzero_exit推断网络/DOM根因、数据灾难或所有交互不可证明；不自动重试unknown，不把缺证改成failed。
- 不以重命名P0/P1/P2改变保障，也不把后备份/报告丢到未完成后台就宣称全部交付更快。

## 最小验证与投资决策

先交付一个小范围比较包：真实待办能形成几组同时就绪合批；近期真实发布差异的合格展示频率；现有回执的恢复阶段和资格成本；准入分项。仅读既有证据/获准隔离样本，不在本轮执行生产调度e或新演练。

选有实际频率的一条路线，用同范围、同保障、同规模隔离对照及后续自然发生的真实批次校准，不为测速重放生产动作。公开批准前准备、批准→必要验收、批准→全部交付、故障/等齐/资格失效与真实可用性样本。若净省达不到30分钟目标或失效成本吞掉收益，就不扩建；无法形成可合批组且展示资格低时，不能承诺每次都省数十分钟。
