# Astra 第一轮实施方案

2026-10-10。本轮核心原则：先发现真实同时就绪集合，再准备精确组合；不把构建成功或一份 ready 标签当作生产许可。

现有 release-impact 已提供完整源码读取、字节库存和保守分类；release-batch 已封存前驱、候选、测试、验收及四项数据库阶段；rotation 已有相同源码/前驱/构建身份的准备复用。因此没有理由重写发布生命周期，也不应先扩大分类或缓存。

## 最小缺口与实施范围

补一个仅离线的组合清单检查器：输入绑定同一实际 source-snapshot 的待采用条目、精确文件增删改、依赖、独立测试/回滚/验收证据引用，以及拟组合源码的完整身份。工具复用既有 safeRead/readSourceTree/sourceInventory/sourceTreeDigest；拒绝摘要漂移、重复/大小写路径冲突、遗漏和额外组合文件、不同前驱、依赖缺失/循环、已执行条目、未就绪条目及同路径重叠。不会自动 cherry-pick、重绑定旧计划、执行 Status 或产生发布授权。

报告保留每项的原任务验收与恢复要求、阻断原因及完整组合差异；可交给既有 rotation plan 和 release-batch prepare 继续准备。没有真实合批组时明确输出 blocked，而不虚构收益。未知证据保留 unknown；文档/人工声明只作为独立复审材料，不能成为生产门禁替代品。

## 必要验证

用小型隔离夹具覆盖正确增删改组合、未批准额外变化、不同前驱、遗漏依赖/循环、重叠冲突、过期哈希、已执行条目、证据缺失、硬链接/重解析路径。既有完整分类及生命周期测试按实际改动范围运行；本工具不修改原门禁。真实 source-snapshot 到候选的扫描须等主agent确认没有重型备份/恢复争用。

对真实待采用项先核 C、daily wrapper 等仍未采用部分；AB 已执行范围不能加入新组合，旧 D5 ABC 也不能直接复用。四文件 UI 保持 strict。待实际前驱和候选清单确认后才能决定是否准备真实组合，不能从 main commit 数量推断机会。

## 收益与停止条件

沿用 30 分钟配对中位净等待改善的扩建目标；它尚未实测。历史 50～55 分钟四数据库阶段只是毛成本池。当前 wrapper 身份三阶段仅有秒级证据，暂不改 transport/TTL/完整字节/动态 Status。真实清单只有单项、没有共同前驱、展示资格低或新增成本吃掉收益时停止扩建，只交付可重复的调查/准备检查工具及真实阻断。
