# 吉客云通用安全恢复与登录准备重试

状态：候选已实现并隔离验证，尚未用于正式 Worker/helper。用户确认覆盖定时执行、小时重试和手动完整运行。2026-09-27 成功的 4737 属于上一版恢复验收，不能当作本候选的真实业务验收。

## 解决的问题

9 月 15–27 日的本机 n8n 记录中，13 次日定时有 3 次成功；7 次停在登录准备阶段（DPAPI 初始化/绑定 4 次、安全验证 2 次、页面选择 1 次）。另有 26 次 webhook 重试只是重复遇到旧运行未闭合。该统计混合多个历史版本，不能据此推算新候选的预期成功率。

本改动复用原执行锁、失败闭合工具、n8n 完整入口和批次回查；不删除 active、旧计划、旧失败记录或业务目录，不新增绕过 n8n 的下载/导入入口。

## 三段流程

1. **核验并恢复旧任务。** 新 `plan-api` 在原锁内先检查 profile 和只读健康接口，再从同一 SQLite 只读事务读取原失败与新执行。旧任务必须为本工作流的 error、没有成功重试，严格停在 B，五个节点顺序、请求路径、时间、计划和错误白名单一致；新执行必须为同一工作流的 running、有效入口模式、更大的执行编号且开始于旧执行结束之后。除当前新执行外不能还有其他在途吉客云执行。空 exports、无 exportIntent，浏览器事件/导入/验证/下载四目录必须全部不存在，空目录也拒绝。凭据类错误还须当前绑定的 status=ready。再次复验后 create-only 写入 v3 回执，绑定一个新执行；旧计划和 n8n 数据不改写。
2. **有界处理登录准备故障。** 原 binding 短重试继续保留。读取报 missing 时，先对同一绑定独立执行只读 status；明确 ready 才重读，最多三次读取、最多三次 status，等待 500/1000 毫秒。真实缺失、损坏、权限/解密异常、状态不明或探针失败立即停止；原有每次子进程 15 秒超时未提高。局部重试发生在填表之前，不增加密码提交次数。
3. **从原工作流完整运行并核验。** 瞬态页面选择失败或“初始页面状态未确认”在浏览器退出后，只有原 v2 计划和零效果证明都成立才写 v4 回执，返回原 `JACKYUN_PREFLIGHT_RETRY_READY`；现有错误流程等待一小时后，从原 helper 领取入口创建完整 execution。A/B/C/D/E 顺序、五表屏障、45 天销售窗口、库存成本源和独立批次回查保持。

自动读取只允许当前 Windows 用户主目录下固定的 `.n8n/database.sqlite`，使用 `readOnly=true` 和 `query_only=ON`，拒绝路径重解析点及文件硬链接，只查询执行元数据。读取文件的审核摘要为 `abf75f3fac7740574c977bcbdc5d520ed987b87afeb730161cde3022ffa2685c`；数据库边界检查验证精确源码及全部传递入口。换库路径、放开只读、读取其他表，或从公共 app/worker 入口引用，都会拒绝通过。其他 SQLite/D1 访问规则不变。

## 不会自动放行的情况

| 情况 | 行为 |
| --- | --- |
| DPAPI initialize/binding/missing 等明确准备错误 | 当前绑定 status=ready 且零效果证据通过，才允许新完整执行恢复 |
| 页面未形成唯一目标、初始页面未确认 | 零效果证明通过后允许原小时完整重试；明确出现其他来源页面时转人工 |
| 验证码、密码被拒、企业/来源/表单身份异常、人工浏览器占用 | 定时和小时入口停止；人工处理后可由手动完整入口核验并恢复，不自动解验证码或重试密码 |
| 登录提交不明、网络 fetch failed、导出提交/绑定/下载已有进展、部分导入 | 不走通用闭合，保留原任务及原专用续跑机制 |
| 损坏回执、迟到文件、其他在途执行、原失败证据变化 | 失败关闭，不覆盖回执、不删除现场 |

v3 回执只供绑定的新执行消费。如果闭合后发生磁盘写入失败，或新执行在新计划形成前被取消，其他 execution 不得抢用许可，需要人工核查这段中断现场。旧 v1/v2 回执保持兼容；已提交导出任务的恢复许可和库存任务防重复 POST 规则保持。
