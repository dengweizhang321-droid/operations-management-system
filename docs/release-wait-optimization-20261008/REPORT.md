## 实现与适用边界

- `release-impact.mjs`：展示／普通后端业务／严格分级。完整前后源码 inventory、原 tree-hash、变更字节和独立依赖／行为见证绑定。展示证明目前限 JSX 文本和字面 className；执行逻辑、CSS、未知依赖、models、SQL、权限、导入、自动化、生命周期、备份和工具／构建配置不能仅凭“前端／Worker”进入快路径。
- 原 Worker rotation `plan --prepare-online` 在原互斥中查找同一最终源码、前驱、依赖／工具链／配置的已验证计划，复用完整 immutable 包；支持显式 `--reuse-plan-sha256`。仍完整验证源、锁、Node 字节、bundled npm、实际 user/global npmrc、环境／运行配置、dist、helper、合约、guard、链接与前驱。apply／Start 的原停止身份、CAS、完整性和启动许可检查保持。
- `release-batch.mjs`：一批 SHA 绑定全部影响证明、Worker plan、Django prepared ID／收据、维护 owner、测试、任务验收和回滚。阶段真实类型、顺序、恢复点引用及验收覆盖强制复验；重算摘要不能删掉必需门禁或误带另一候选。原非阻塞发布锁＋内存 lease＋持久 active 防多个聊天争抢；started 先 fsync，unknown／中断禁止重放，独立精确回查后安全续接。
- 展示切换通过唯一 Worker 的 `BeginWorkerDrain → StopForRelease → apply → Start → EndWorkerDrain`，复用原 helper／backup／background／request leases，在持久 requests gate 下切换，保留 Django／PostgreSQL。新 helper 重新确认精确 gate、协议和无在途后才解除；高风险仍使用原完整应用维护／回滚能力。
- 恢复复用要求：持续 ACTIVE 的日常备份最近成功≤26小时；当前恢复点≤26小时、仍实际保留且原 Verify 完整通过；同点完整恢复≤7天且清理、内容、角色／权限／迁移与序列健康通过；当前软件、目录、角色、operator、保留和调度绑定一致。新 `ReleaseEvidence` 只读复用原 catalogue，不做全业务内容扫描；额外 schema／LO、无法证明的序列 ownership、倒退／耗尽／循环，以及 live cache_size≠1 均拒绝资格。隔离恢复保留原 full profile 和序列下界，并检查 owned 下一值健康。

首次采用本任务修改了生命周期与备份实现，属于**严格级**，不能用新快路径给自身减免。正式日常备份 heartbeat `e` 在只读核查时仍为 PAUSED；没有持续调度成功证据。因此当前生产条件不能进入展示快路径。新 daily 包装只调用原 installed Backup 并记录 started/result/active，暂停或未知不启动新备份；本任务没有安装／启用它。
