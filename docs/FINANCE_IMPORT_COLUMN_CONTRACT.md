# 财报导入内部列号字段修复

2026-09-14，用户要求导入志高事业部 2026 年 8 月财报。正式公开导入口返回 HTTP 400：`财务明细行字段与 finance-normalized-v1 不一致`。写后只读回查确认没有新增 8 月批次，已有财务数据截至 2026 年 7 月。

原因是 `parser.ts` 把包含 `columnIndex` 的 Excel 维度对象直接展开到财务明细。TypeScript 的结构类型没有删除额外属性，JSON 序列化将内部列号发送到 Django，后端精确字段集合验证正确拒绝了请求。

修复在汇总和金蝶明细两个构造点显式投影 `scopeKey/scopeType/scopeName/groupName`。保留后端严格契约、鉴权、金额转换、费用合计、幂等和审计，不扩大写入权限。

验证：新增 XLSX 与 BIFF8 两种格式回归，覆盖规范化边界的精确字段集合、月份、事业部金额和店铺费用。财务相关测试 59 通过、0 失败、15 跳过；隔离生产构建通过。对用户工作簿全部已识别月份逐条比较，除删除内部列号外，金额、比率、身份、来源计数与警告完全一致。真实财报内容不提交源码仓库。

本次用户只授权 8 月导入。原文件包含 1—8 月，继续操作须仅选择 `26.8` 工作表，在内存中生成上传内容，并复验规范化行与原文件 8 月完全一致，然后经公开 `/api/imports/finance` 提交。不能把全年文件直接提交而更新其他月份，也不能绕过公开入口直接写数据库。

全量 Node 回归最终 2160 通过、0 失败、20 跳过。当前修复尚未合并或发布，8 月尚未导入。后续完成受控发布门禁，取得生产发布授权后采用 Worker 修复，再执行本次已授权导入，并回查完成批次、准确月份和财务分析金额。生产发布需协调其他活跃任务及市场计划排空，不自动重放未知结果。
