# 一键销售导入

适用于尚未开通吉客云 API 时的销售明细导入。吉客云导出仍由已登录浏览器完成；从下载文件开始，筛选、成本匹配、导入和复核均由一键任务完成。

## 使用步骤

1. 在吉客云销售单明细账按月度累计设置日期：通常为本月 1 日至昨天；每月 1 日执行时为上个自然月 1 日至月末。逐字段填写并读回核对；查询后等待本轮刷新证据出现并稳定。
2. 仅创建一次导出任务。不要打开或操作“下载记录和系统任务”弹窗；下载文件应落在 `D:\谷歌浏览器`。
3. 自动化将下载事件返回的绝对路径交给统一 runner，并显式绑定同一 `RUN_ID`、本轮导出开始时间和本轮库存 runner 保存的原始成本源副本。任务不再扫描“最新销售文件”或“最新成本源”。

标准入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-download-runner.ps1" --module sales --file "D:\谷歌浏览器\销售单明细账 (N).xlsx" --run-id 20260716-093000 --export-start 2026-07-16T02:30:00.000Z --expected-source-rows <页面稳定总行数> --as-of 2026-07-15 --cost-source "D:\运营管理系统\outputs\jackyun-import-runs\20260716-093000\raw\inventory-分仓库存查询.xlsx"
```

销售是每日五类任务的第 4 项。该 `RUN_ID` 的货品、分仓库存和库龄必须已经依次完成，否则 runner 会阻断销售任务；销售完成后才进入最后的组合装。

## 自动校验

- 浏览器查询区间必须是完整月度区间，文件源行数必须与页面稳定总行数一致；若下载文件里混入执行当天订单，先剔除这些行，再按剩余数据继续校验和导入；晚于执行当天的日期仍视为异常；
- 剔除配置中的仓库（当前为“刷刷仓”）；
- 仅保留配置白名单中的销售渠道；
- 固定成本必须唯一且全部匹配，成本冲突或缺失会阻断；
- 生成处理文件前核对仓库、店铺、日期和成本不变量，写入成功后不再重复完整解析；
- 导入前把本轮文件与系统同期间的店铺快照比对；系统已有数据的白名单店铺若在本轮完整期间文件中整店缺失，视为吉客云导出漏选并停止导入，避免完整快照覆盖时误删历史店铺数据；
- 使用既有分片接口导入 `localhost:3000`，再从数据库核对行数、日期、白名单、排除仓和最新批次归属。

每次成功任务都会将原始下载文件副本、处理后的 Excel 和 `audit.json` 保存到 `outputs\sales-import-runs\`。同一个已成功导入的原始文件 SHA256 会被拒绝，必须重新从吉客云下载。

## 人工备用入口

直接销售 runner 和 CMD 均要求显式输入，不允许猜测历史文件：

```powershell
npm run sales:import -- --download "D:\谷歌浏览器\销售单明细账 (N).xlsx" --cost-source "<本轮库存原始成本源副本.xlsx>" --as-of 2026-07-15 --dry-run
```

```cmd
一键销售导入.cmd "D:\谷歌浏览器\销售单明细账 (N).xlsx" "<本轮库存原始成本源副本.xlsx>" 2026-07-15
```

`--as-of` 指定“昨天”的日期；`--dry-run` 只生成处理文件和审计结果，不导入系统。正式每日任务应使用上面的统一 runner，而不是单独调用备用入口。

## 统一配置

店铺白名单、刷刷仓规则、下载目录、日期策略与成本字段都在 [sales-import-policy.json](/D:/运营管理系统/config/sales-import-policy.json) 中维护。修改店铺名单后，无需再改导入脚本或后端校验代码。
