# 上新跟进：手动学习操作回执与断线恢复

## 需求与结果

用户确认的四点均已实现：点击时先保存唯一操作编号；后端按编号返回原结果；断线后显示“正在确认执行结果”并查询原编号；同一标签页刷新或切到 AI 助理后返回继续查询。当前是已验证源码交付，尚未部署到生产，不把原连接中断的具体诱因记为已查明。

## 实现边界

- 复用现有 `WorkflowWriteRequestReceipt`，不新增表、迁移、队列或模型供应商调用。手动编号使用独立命名空间，永久排除通用七天清理，也不按五分钟重新领取。
- claim、业务修改与完成回执由同一外层事务持有原 PostgreSQL advisory lock；已确认业务回滚后才存失败终态。原事务未提交时查询可能看不到记录，此时仅返回 `unconfirmed`。
- 新增精确 writer GET 查询入口，只返回当前真实 principal 本人的回执；保留 operator/admin、无受限数据范围的要求，不扩大 reader 表权限。
- 浏览器 sessionStorage 按账号仅保存操作编号。自动恢复只执行 GET；有界查询仍未确认时，人工继续使用原编号，终态后下一次主动学习才生成新编号。切换账号会重新挂载组件并废弃迟到响应；存储失败不提交新操作。
- 原 GET 草稿预览、内部主数据导入学习、周报学习和普通写回执保持既有路径。旧浏览器页面需刷新加载新版手动学习协议。
- 本次不保证关闭标签页、清除存储、换设备后自动找回操作，也不宣称消除了网络中断本身。
