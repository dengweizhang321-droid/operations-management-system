# Release StopWorker routing after full maintenance

This development-only fix starts from origin/main `f5b19c01fc7bedc1750e96605924c54b58ab7cfd` in managed worktree `release-maintenance-stop-route`, branch `codex/release-maintenance-stop-route-20261012`. It is not inserted into the already approved f15 candidate, source binding or nineteen-step specification.

The release adapter previously always selected `StopForRelease`. That original action deliberately rejects full maintenance because it is the Worker-only drain path. A full application release had already completed `EnterMaintenance -KeepPostgres`, so its subsequent StopWorker hit that guard even though the maintenance action had already stopped Worker and backend.

The adapter now first reads the original MaintenanceStatus. Its original raw response must start with an object container before JSON parsing, because PS5 can unwrap a single-element root array. The parsed state must be a PSCustomObject with exactly the two original maintenance/drain properties; drain and non-null maintenance must themselves be PSCustomObjects. A fully matching maintenance/drain identity, protocol versions, fixed runtime root, requests phase and boolean keepPostgres/drainedStopped select the existing Worker `Stop` action, without IncludeBackend. With no full maintenance, the adapter retains StopForRelease and its original engine checks. Missing, mismatched or incomplete state rejects before invoking a mutating engine. No lifecycle engine, service ownership, mutex, gate-writing, backend-stop, database or rollback implementation is added.

Validation uses the actual adapter's AST-extracted function and StopWorker clause in both Windows PowerShell 5 and PowerShell 7. The fixture loads original Worker functions with FunctionsOnly and substitutes only low-level process/lifecycle boundaries. It reproduces the old full-maintenance rejection, confirms both intended routes, checks twenty-three invalid-state cases and two direct input-type cases per shell, and verifies zero backend stop calls. This includes root/nested singleton arrays, boolean arrays, all seven string identity/protocol fields as singleton arrays, and an unknownStatus envelope carrying otherwise valid fields. Two shell tests passed; the fifty-four scenario executions are not fifty-four separate test-runner tests. `git diff --check` passed. Original UTF-8 BOM is preserved.
