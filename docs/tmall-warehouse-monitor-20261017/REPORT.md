# 天猫入仓监控与 n8n 导入交付

## 需求与实现

用户要求库存管理新增“天猫入仓监控”，搭建从 `https://scp.tmall.com/` 自动下载并导入的 n8n 工作流，对接正式前端；页面内容参考所附《库存通报表.xlsx》的“京东POP+天猫库存表”，交互参考京东 POP。

正式入口复用系统主导航、库存 `subnav`、KPI、筛选和表格，不另建系统壳。单品按货主与天猫货品 ID 分组，仓库横向显示，可展开完整分仓；分仓指标可切换库存、明确30日销量、采购在途、调拨在途、建议补货和周转。文件导入与历史同时接入“数据导入 → 天猫入仓”，自动化中心展示独立工作流。

来源事实使用独立天猫 PostgreSQL 四表和结构迁移 `inventory.0017_tmall_warehouse`，不混写京东或 ERP。每货主、每日原子替换完整集合，内容幂等、版本CAS、旧采集拒绝、引用批次与当前事实回查、最小角色/scope及真实签名传输均接入库存域既有契约。来源没有货主列时使用导入声明或采集器实际登录身份，供应商不充当货主。

实际观察的实仓报表导出32列、25条分仓记录，没有来源日期和30日销量。实时快照绑定本轮真实上海采集日；缺少销量时不显示猜测的周转或补货。附件历史“数据源”可识别15条及2026-09-29来源日，其无期间“销售出库”不认作30日销量。参考表里的人工补货、ERP编码和补货后周转不从不匹配来源推断；采购执行沿用已有备货计划。

## n8n 与首次采用

已通过官方CLI实际创建独立工作流 `TmallWarehouseDaily2026`，名称“天猫入仓监控·实时库存下载与导入”，保持 inactive；节点、连线、设置与仓库定义一致，原23条工作流定义未变。首次CLI超时的失败及后续安全创建分别保留，见[N8N安装证据](N8N-INSTALLATION.json)。

流程为领取共享门禁 → A冻结货主、采集日与scope版本 → B唯一导出、签收、完整校验并导入 → C重读原件并回查精确批次/重复引用和当前事实 → D释放资源。导出/导入意图先持久化，结果未知不重放，跨execution不能接管。顶层SPA只能在实际活动报表根内检查筛选；留存首页的日期控件不能当成库存筛选。详见[自动化](AUTOMATION.md)和[真实定位证据](BROWSER-LOCATOR-EVIDENCE.md)。

本轮没有生产应用切换、正式数据库迁移、真实自动导入或定时启用。首次使用须先由用户从固定 main BAT 发布就绪版本，再在正式 helper 相同 mutableRoot 完成人工专用会话登录和身份核验，最后运行一次完整 n8n 链路；定时仍需明确启用。不能把停用草稿、开发测试或制品准备称为已上线。
