# 网店分析共享数据与交互契约

本文件定义五个栏目的共同语义。下面标为建议新增的协议须由F实现并经I冻结；现有接口继续保持自身版本与语义，不将文档草案当成已可调用API。

## 事实源与身份

PostgreSQL各业务域是其结构化事实的唯一权威。页面经同源Worker、真实principal和固定Django reader访问。跨领域读取使用既有有界consumer，不直接拿其他域写权限或新增第二份事实库。派生缓存不能绕过权限、版本和新鲜度检查，不能恢复D1业务读取或双写。

店铺唯一身份沿用现有平台＋精确店铺复合键及序列化函数；底层有ERP channel时继续交叉核验。商品身份至少含平台、店铺、维度、商品ID；SPU、SKU、推广商品、触发SKU、跟单SKU和ERP货品代码分别建模。名称模糊相似不是自动关联证据。

当前已知平台能力：京东有SKU/SPU日、主数据、推广及B2B类型；天猫有SPU日、主数据和推广。类型存在不证明字段或所选店铺期间有数据，B2B类型更不证明客户身份与分母关系。其他ERP平台可以展示其已验证销售指标，但不能借用京东/天猫流量能力。

## 日期与范围

- 业务时区为Asia/Shanghai；展示起止日均含，查询使用左闭右开。
- UI保留用户选定的期间与预设意图，同时返回来源实际截止日；不能暗改选择、把未同步尾日填0或将最新日期当完整覆盖。
- 环比复用现系统规则：单日比前一日，完整自然月比上个完整月，同月多日范围比上月对应日，滚动区间及跨月自定义比前等长区间。季度等预设复用已存在定义。短月和闰日按同一比较日历处理。
- 返回本期、环比、同比实际范围和规则版本。自然周从周一开始，月按自然月，首尾截段标明天数；每7天仅是明细分组，不能与自然周混称。
- 新增页面首期日期范围上限建议366天，店铺最多50个；不改变旧API730天等既有上限。新列表默认20行、上限100行，旧推广500行能力不被静默删除。最终参数枚举与预算由F冻结，超过边界明确拒绝。
- 继承同一筛选不等于所有来源可比；同一请求可返回不同来源截止日。比较只使用定义一致、双方覆盖成立的指标。

## 指标语义

| 指标 | 语义与约束 |
| --- | --- |
| 平台成交或支付 | 来源商品日报的对应金额；不等于ERP净销售或天然完整的店铺交易概况 |
| ERP净销售 | 正负分摊金额按既有销售领域口径汇总，退货为负；订单毛利与大毛利定义继续分别复用 |
| 大毛利率 | 按现有销售规则，不能以订单毛利直接除净销售代替；不得改成本、仓库排除或费用规则 |
| 财报利润与目标 | 月度来源按实际月份显示；不插值为日/SKU利润，不另造目标维护系统 |
| 商品访客及客户累计 | 商品×日累计，非店铺或跨日去重人数；SKU与SPU不能相加 |
| 商品累计转化率 | 同源、同维度、同范围成交客户累计/商品访客累计；分母不成立返回不可计算 |
| 商品访客价值 | 同源成交金额/商品访客累计，不能命名店铺UV价值 |
| 广告归因成交 | 京东总订单金额与天猫净成交等原定义分别保留；归因窗口未知须说明 |
| ROAS | 平台归因成交/花费，单位倍数，不是利润ROI或广告增量效果 |
| 推广费率 | 同平台×同店×同日的花费/对应平台成交；商品层还需适用商品身份一致 |
| 广告归因成交与平台成交比 | 包含关系或归因窗口未核验时仅显示定义清楚的比值，不能声称自然/付费渠道份额 |
| 退款与退货率 | 复用所属来源明确分子分母；金额率、订单率、件数率不能同名混用 |
| 企业购占比 | B2B须是对应分母的可证实子集，店铺/日期/业务事件/退款定义一致；未知时不可计算 |
| 客户复购及新老客 | 商品日报新老买家只能以原累计口径展示；真正复购需稳定匿名身份、订单规则和历史覆盖 |
| 当前档案和库存 | 显示各自快照日期，不能画成历史日序列；当前映射不能未经验证回填历史归属 |

金额计算传输使用安全整数分，元除以100，万元除以1000000。数量须校验整数范围。比率返回未乘100的小数；前端只格式化。比率按合计分子/合计分母重算，不平均各日/店百分比。费率、转化率的差异使用百分点；ROAS变化标倍数或明确相对变化。基期0、基期缺失、负基期分别解释，不输出无穷增幅或一律当新增。

## 统一可用性

为兼容01在途DTO，通用展示状态沿用四态，并由reasonCode细分原因。旧接口不强行改类型，通过显式适配进入新展示合同。

```typescript
type MetricStatus = "available" | "partial" | "unavailable" | "invalid";
type MetricValue = {
  value: number | null;
  unit: "CNY_CENT" | "COUNT" | "RATIO" | "MULTIPLE" | "SECONDS";
  status: MetricStatus;
  reasonCode: string | null;
  sourceIds: string[];
  basis: string; // 由共享schema枚举冻结，禁止任意自由文本作为指标定义
  aggregation: "sum" | "ratio_of_sums" | "source_value_only";
  numerator?: number | null;
  denominator?: number | null;
  coverageRef: string;
};
```

`available`有可信完整数值且reasonCode为空；`partial`只允许披露已覆盖范围的可加总结果；`unavailable/invalid`数值为null。真实0仅在字段确实提供且覆盖成立时为available。原因至少区分无记录、缺日、缺字段、不适用、未关联、多义关联、零分母、基期不足、来源未核验、归因窗口未知和超出安全整数。权限失败、接口故障不是业务空值，返回既有错误协议。

整期费率覆盖不完整时主值为null。若有已匹配部分的辅助值，必须单独提供其范围和覆盖，不能复用主值标签。缺日折线断开，不默认补0；两期不可完整比较时不展示仿真的完整增幅。

## 响应元数据与版本

新增合同建议版本名为 `netshop-insights-v1`。每个专属DTO在共享合同之上明确自己的字段，不将不同业务响应强制塞进无类型万能JSON。

| 共同字段 | 要求 |
| --- | --- |
| schemaVersion、requestId、scopeKey | scope由服务端规范化真实账号权限与请求产生，不信任前端自报身份 |
| requestedScope、effectiveScope | 平台、精确店铺、商品维度、日期、筛选及本次实际纳入集合；变化必须披露 |
| periods | current/previous/yearAgo的起止日、endExclusive、天数、规则与版本 |
| sourceRevisions、snapshotToken | 各来源的修订向量与绑定该范围/协议的服务端令牌；不比较不同种类token字符串是否相等 |
| freshness、coverageBySource | 按来源×平台×店铺×日期核验；最后成功日期不代替完整性 |
| capabilities | 本范围可用字段/钻取/导出/诊断能力及限制；不是硬编码“平台有此按钮” |
| sections | 有类型的指标、序列、列表；每节关联自己的来源和覆盖 |
| pagination | total、returned、page/pageSize或cursor、hasMore、truncated；截断不能冒充全部 |
| warnings | 有界、可解释的来源与映射问题；不输出凭据或原始客户资料 |

跨页、汇总、图表、比较和导出绑定同一scope及适用来源版本。源发生变化时使用已有有界恢复策略，持续变化明确失败，不无限重读。跨领域不能假装存在分布式原子快照：组合计算须复核参与域读取前后revision，不能一致时停止该组合指标；独立章节可显示各自可靠结果及截止日。

覆盖必须逐店逐日检查。A店只有推广、B店只有商品日报，不会生成可用费率。聚合不能从一页排行、被截断数据或日期并集推导全店完整性。

## 接口与服务归属

| 用途 | 当前或建议路径 | 负责人 |
| --- | --- | --- |
| 已有元信息、目录、商品和推广 | 保留`/api/netshop/overview`、`products`、`product-performance`、`promotion-performance/*`的原含义 | I协调旧接口变更 |
| 总览01 | 在途`/api/netshop/store-overview`；按O最终交付核验，不另占同名 | O |
| 商品新分析 | 建议`/api/netshop/product-insights`及`product-insights/detail` | P |
| 推广新分析 | 建议`/api/netshop/promotion-insights`及其有界对象详情 | A |
| 单店全景 | 建议`/api/netshop/store-panorama` | S |
| 店铺平台比较 | 建议`/api/netshop/comparison-insights` | C |

以上新路径是分工建议。F先检查最新main及O交付，能复用既有稳定接口就不新增等价入口；冻结路径、DTO、服务归属、超时、响应上限、允许参数和测试夹具后发给各角色。专属处理器可由栏目编写，公共urls、gateway allowlist和共享权限接线由I串行完成。

业务聚合留在Django拥有者层；浏览器只渲染、格式化和操作已返回图表，不拉全量事实自行关联。跨域必须走既有权限内只读consumer；如需新consumer或reader grants，由I单独核验角色、最小权限及备份/恢复影响，不在栏目分支放宽权限。

新增数据若应可被AI查询，由栏目交付有界工具需求，I在中央注册表显式接线并验证权限、surface和预算。不从API或数据表自动暴露工具；不声称现有聊天候选已验收。

## 页面上下文与旧路由

继续使用 `module=shop` 及五个既有view值：analysis对应店铺全景，outlets对应网店总览，platforms对应对比，products对应商品表现，promotion对应推广。保留旧书签及01自己的新旧模式。

F冻结一份共享 `ShopContext`：平台和精确店铺集合、日期及预设、比较开关、日周月、商品维度及精确商品身份、页内章节。序列化复用 `app/shell` 原导航契约，不随手使用另一套history。账号/权限不写入客户端可伪造字段；URL不携带客户隐私、凭据或任意外部跳转地址。

全景以单店为主；无选择时提供店铺选择，不偷偷选择任意第一店。产品/推广从全景进入时保持单店；从专题自行选多店时明确范围。返回恢复列表筛选与页码；范围改变时页码归一，只有实际规范化范围相同才保留。

全局筛选改变所有相关区块；表内搜索若仅过滤列表，标题必须说明上方汇总不变。用户改变范围后旧结果不可静默沿用，必须保留原范围标签并提示刷新失败或清空新范围视图。旧请求须取消且拒绝迟到覆盖。

## 必测场景

1. 同SKU或同名商品跨店不串，未经授权店铺不返回。
2. 商品本期第1页、基期第3页仍能正确比较；增长榜先配对全集再排序分页。
3. 两店错位缺日不能产生完整推广费率；缺字段不转0。
4. SKU/SPU不相加；当前映射/库存不冒充历史。
5. 月末、闰日、自然周、每7天尾段、同比缺日和零/负基期正确。
6. 省略、重复、非法范围参数明确处理，UI、API、AI和导出权限一致。
7. 同scope不同版本拒绝混合；跨域不一致只降级相关组合，错误不当无数据。
8. 快速切店、日期、页码及浏览器前进后退不串范围。
9. 旧五视图、01新旧模式、原图片/搜索/分页/导入入口不回归。
10. 缺源、API失败、超限、空态、部分覆盖均有可验证展示；合成页面通过不称生产数据通过。
