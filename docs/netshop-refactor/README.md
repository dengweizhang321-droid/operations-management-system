# 网店分析方案二多 Agent 重构工作包

本工作包供用户审定内容、分发栏目任务、并行开发与串行合并使用。目标是让用户充分了解每家店的经营情况，并复用现有商品、推广、销售、财务和库存能力。

版本为 1.0，编制日期为 2026-09-30。用户已选方案二；栏目详细内容为上一轮内容清单 V1，尚未逐项补充定稿。**生成此工作包只授权文档工作，不表示已启动功能开发、接通新数据源或批准生产上线。** 用户以后明确转交某份执行提示词时，该提示词中列明的核心内容成为该次隔离开发范围；条件内容按来源证据推进，可选写功能仍不自动纳入。

## 阅读与分发

1. 先读[协作契约](01-collaboration-contract.md)，确定唯一集成负责人、角色和文件所有权。
2. 读[共享数据与交互契约](02-shared-contract.md)，统一身份、日期、指标、接口与缺数处理。
3. 按[合并顺序](03-merge-order.md)分波次开展，不把所有提示词同时派发。
4. 用户按[栏目内容清单](04-content-scope.md)的编号增删。总控把确认后的范围写入任务交接记录。
5. 各执行 Agent 同时收到本目录和自己的一份提示词；没有前置提交时先完成本角色的设计、夹具与接口需求，不私自绕过依赖。

## 最短执行路径

契约定稿 → 既有总览 01 验收与合入 → 公共底座 → 商品和推广并行 → 商品、推广依次合入 → 店铺全景和对比并行 → 全景、对比依次合入 → 总体验收 → 生产候选 → 用户另行批准上线。

允许按验收能力调整并发数量，但不改变依赖与共享文件单写规则。建议一个总控加最多三个活动工作角色；角色数不等于必须同时启动的 Agent 数。
