## 接口、字段与复用

- S 专属 GET 草案：`/api/netshop/store-panorama`，`app/netshop/panorama/api.ts` → `backend/netshop/store_panorama.py::read_store_panorama`。单平台、单精确店铺；F shared 7 参数加 `q/page/pageSize/section/sectionToken`，默认 5，最多 100；未知/重复/跨店参数拒绝。S token 绑定范围、参与修订、q 与 pageSize，不绑定 page/章节；分页和章节仍严格 echo。
- 严格 DTO：`app/netshop/panorama/contract.ts`，固定八章、逐能力 owning 证明、完整 UTF-8 2MiB 上限。P/A 数据只各保留一次完整信封，不把广告京东 SKU context 塞入 S/P SPU context，金额与分母不混算。
- P `ProductInsightsResponse`/`decodeProductInsights`：summary、baselineReads、comparisons、structure/changes、growth、efficiency.metrics/visitorValue、dataQuality、metadata、items/pagination。q/page 仅过滤表，不从本页重新计算整店指标。原商品图片状态按 P 可信资料显示。
- A `PromotionInsightsResponse`/`decodePromotionInsightsForQuery`：整期 summary/comparisons/changes、attribution、主 paired-whole 与独立 matched 子集、trend、items/pagination、contributions、coverage/limitations。CPC 是 `netshop-money-per-count-v1`，保留未舍入分/点击，不塞旧整数金额单元。
- 平台序列需求：I 已接纳 owning `read_product_scope_series`（独立作者实施中，未 actual main）。完整本店日、本期与实际对应基期日期、P core/extra/visitorValue、覆盖/字段存在性与修订；不能遍历详情或把本页排行求和画线。
- ERP 需求：精确 platform/shop/channel、原 signed 净额/件数/成本/订单毛利/大毛利/退货、两期完整汇总与贡献/分页、修订前后复核。订单身份回退 source-line 不算去重订单；旧件均净额不叫订单客单价。
- 财务/目标：拥有方无 scope 身份门槛不扩大；精确店铺月和年度 pair 在分页前筛选；真实月份、既有年度目标、原定义进度及 digest。不得将月利润变成日/SKU 利润。
- 事件：精确 platform/shop、`occurredAt` 上海时区半开范围、真实分页与修订；`updatedAt` 和今日工作流状态都不替代发生时间。

S 中的跨域显示投影是消费需求，未冒充已冻结 owning API。I 发布准确 public main、DTO/export 和最小权限后再同步适配；参与域进入 joined 向量，未参与域不制造组合失效。
