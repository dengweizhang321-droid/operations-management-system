# Sales two independent periods: candidate contract

Author core baseline: actual main `b7fafb482b39fb82382f7ab42e54175b89b9eece`. This document describes dedicated, unregistered core until I's consumer dispatch/SDK/RPC changes and independent Q review are complete. No production adoption, data migration, business replay or model call is part of this work.

Owned symbols are `sales.netshop_periods.validate_netshop_periods/read_netshop_periods`, `NetshopPeriodsError(code,status)`, `netshop.sales_periods_client.read_sales_periods`, and `lib/netshop/sales-periods-contract.ts` external/internal validators plus `decodeSalesPeriodsForRequest`. Operation is `netshop_periods_v1`, response schema `netshop-sales-periods-v1`.

Request uses two independent left-closed/right-open ISO windows `{startDate,endExclusive}`, each 1–366 days. Unequal lengths and overlap are allowed; neither window is generated from the other, shortened to the latest row, or renamed F.previous/yearAgo. Optional `rawOutlets` is at most 50 exact `{platform,rawShopName,rawChannel}` identities; omitted/empty means the authorized union. A provided channel is a nonempty raw string, not null or a wildcard. Raw whitespace is retained and the owning projection keys must agree with raw values. Canonical conversion remains I's existing netshop resolver; the sales core never interprets an arbitrary canonical label or global same-name OR as authority. Each triple is conjunctive, between exact triples is OR, and existing `_apply_principal_scope` warehouse/channel/platform rules are always applied. Native `resolved_category` label cohorts are supported; adapter callers must not pass P labels as ERP taxonomy evidence.

Whole totals and complete candidate count are calculated over both authorized windows before q/page. Candidates appearing only in the baseline remain. q searches raw identity strings only; page defaults 1/20, maximum 10000/100. Binary identity ordering is stable. Response `candidatePagination.collection=authorized_two_period_union_before_search_pagination`, candidate/filtered counts and returned/hasMore are exact; there is no top500 or truncated control total. Snapshot binds windows, raw identities, native labels, actor fence and the sales/ERP pair; q/page do not change its whole-scope meaning. Requested expectedRevision/snapshot mismatches fail 409.

All signed amount/cost/quantity expressions are reused from `sales.analysis.expressions`; no import/cost/warehouse/profit rules are rewritten. `grossProfitCents` is the existing net amount less source cost, while `reportedGrossProfitCents` is the independent original source gross profit. Fee remains separate. Rows absent from a period produce nulls/no_records, while actual rows whose sum is zero produce zero. Quantity keeps original is_net_quantity_row exclusions and signed positive/return rules.

Trusted order count uses only a nonempty, bounded, exact raw ERP `order_no` without leading/trailing whitespace or controls. It is distinct within the raw platform/shop/channel identity, deduplicates multiple product lines and counts same order numbers in different shops separately. It never falls back to online_order_no/source_line_key. Overall totals calculate the tuple distinct count directly rather than adding candidate/day counts. Missing usable order numbers suppress the new `CNY_CENT_PER_ORDER` net amount mean; this is an imported shipped-business-date order-group mean, not a paying-customer average. Raw order/customer identifiers are not exported.

Observed date ranges compact actual imported business dates. `observations.completeness=unknown` always: observed or maximum dates are not continuous shop-day settlement proof; dates without rows cannot establish genuine zero or missing imports. Latest batch metadata is related to the actual selected two-period facts, not the unrestricted global latest batch.

One whole read is capped at 65 seconds and includes actor reads, every business SQL, serialization and final checks. Each SQL uses min(original connection timeout, 7 seconds, remaining time). Serialization rejects a complete UTF-8 response over 2 MiB instead of dropping vectors/items. The new signed internal RPC body may contain safe integer `expiresAtEpochMs`; the receiver converts UTC remainder once to its local monotonic deadline and min65, so network time cannot reset a source's budget. The expiry is not a business fact or snapshot ingredient. External C/S request decoding rejects it. This same-host mechanism does not claim zero clock skew across hosts or immediate termination of already executing SQL.

Actor reads use the existing five-column definition email/role/status/scope/version and compare before/after. Ordinary absent/disabled/role/scope/version changes fail closed. Reserved signed local-admin inherits only F's existing edge policy, never an absent-user fallback. Isolated PG must verify actual minimal role privileges; core never creates grants. Sales participating vector is exactly `{domain:'sales',kind:'sales_erp_revision_pair',scopeKey,revision:'sales:erp'}`. It cannot be substituted by finance/netshop revision:digest or a snapshot token. Only participating domains are declared.
