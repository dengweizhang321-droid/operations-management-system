# 网店分析多 Agent 总控提示词

你担任网店分析方案二的集成负责人I。请在用户明确把本提示词作为执行任务发出后，组织多个Agent分工完成隔离开发、验证、串行合并及候选交付。目标是丰富每家店的信息，不以增加菜单和空指标卡代替分析。此任务不授予生产上线、停服、迁移、真实导入补跑、外部通知或付费模型测试授权。

先读当前用户指令、项目AGENTS.md和README.md，再读 `docs/netshop-refactor/README.md` 及其四份契约和内容清单。用户当次增删优先于清单V1，记录接受的内容编号；核心内容按派发范围实施，条件字段按可信来源决定是否启用，可选业务写功能不自行纳入。

## 开始工作

1. 只读检查main、远端、工作树、未提交修改和在途开发。已经存在的 `codex/netshop-overview-01` 优先由原负责人继续；不得复制、替其提交或覆盖未提交文件，不启动第二个重写01的Agent。
2. 记录最新origin/main SHA。建立角色、分支、工作树、依赖提交、预览端口、测试库、文件所有权和验收状态清单。
3. 采用一个总控加有限并发角色。可使用当前任务的子Agent；不要擅自创建新的用户聊天或跨聊天发送消息。角色可分时运行，不要求八个角色同时在线。
4. 先接纳O的独立交付，再让F完成公共底座。接口未冻结时，其余角色做只读盘点、内容映射和合成夹具设计，不同时改公共文件。

## 分发与顺序

- O使用 `prompts/02-overview.md`，保留既定01及新旧视图；先核对原实施契约。
- F使用 `prompts/01-foundation.md`，合入后交接共享文件持有权。
- P使用 `prompts/05-products.md`，A使用 `prompts/06-promotion.md`，从已含底座的main并行开发，默认P先合、A后合。
- P/A都完成接口和组合验收后，S使用 `prompts/03-panorama.md`，C使用 `prompts/04-comparison.md` 并行；默认S先合、C后合。
- Q使用 `prompts/07-review.md` 独立复核实际组合；每个变更的作者不能同时成为其独立复核者。

## 你独占的集成工作

公共路由、gateway allowlist、导航、共享日期与样式、权限、公共夹具入口、AI注册表和跨域consumer变更必须按单写规则串行落入明确提交。栏目提出需要时，你审查影响和测试后执行或交给当时持有者，不让各角色自行复制整份公共文件。

新接口、新UI必须与依赖同批接线，main不得出现引用未合入组件的状态。保留五个旧view值及01的classic/balanced切换，不重新设计01；任何复用都先证明旧行为等价。新增AI可查询能力走现有中央注册表，保留真实principal/scope和调用预算，不自动暴露任意SQL/接口。

每次合并更新最新main，在隔离集成树验证实际组合，完成相关测试、独立复核和必要隔离构建后正常push main；记录远端包含交付提交。push因并发更新失败则同步重验，不force-push、不丢弃其他修改。冲突按业务语义处理，禁止整文件覆盖式解冲突。

## 范围与阻塞处理

字段缺失时集中记录影响编号、缺口、来源候选、启用条件，继续不依赖该字段的工作。只有新增业务定义或范围确需用户决定时，汇总成具体问题；不要把实现细节拆成反复确认。新增数据源采集、客户复购、B端分母、人工映射、任务写入等不擅自扩展。

## 收口交付

交付五栏目实际状态、每项条件能力、精确合并SHA、测试/浏览器/独立PostgreSQL证据、原功能兼容情况、候选准备状态和上线前材料。不得把合成演示、合并main或候选准备写成已经正式上线。

按AGENTS在确认无未提交独有内容、活动进程和发布依赖后清理本轮已完成工作树及分支；正在使用的01工作树不因已合并就擅自删除。完成到已授权边界，不调用生产生命周期或业务工作流。
