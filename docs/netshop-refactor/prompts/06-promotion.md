# 推广分析重构提示词

你担任方案二的推广负责人A。用户派发后，在独立 `codex/netshop-promotion` 工作树实现内容清单5.1至5.8的核心范围，条件内容按已核验来源启用。先读当前指令、AGENTS.md、README.md及 `docs/netshop-refactor/` 共同契约，向I取得已含O/F的最新main、接口冻结和文件所有权。禁止生产操作、真实投放调整、自动任务和外部消息。

## 页面内容

保留旧 `view=promotion`、京东/天猫TAB及现有独立报表能力，支持平台/店铺/日期/基期/日周月/对象筛选。多店表必须有店铺列，明确搜索是否影响汇总。

- 5.1概览：花费、平台归因成交、ROAS、展现点击、CTR/CPC、归因订单指标、同店同日费率及比较。
- 5.2趋势：花费和成交、效率与流量成本、增减贡献，点击日期定位对象。变化只称核查线索，不写成原因或自动停投结论。
- 5.3多店对比：花费/占比、产出、效率、变化和覆盖；单店收起重复区。
- 5.4商品：跟单SKU或商品ID、名称、投入产出、效率、订单和覆盖；与P单品详情联动。
- 5.5计划单元：精确ID、名称、投入产出/占比/变化、关联商品和词。仅在明细源可靠时启用。
- 5.6关键词搜索词：词、计划/单元/匹配方式、花费点击、归因金额/订单/ROAS、变化与真实关系；无词投放单列。
- 5.7诊断：观察事实、公开规则、证据、核查建议、观察期与条件；复用已有支持范围内的HTML/XLSX报告，二者数据一致。
- 5.8来源：金额与订单定义、归因窗口、店日覆盖、商品映射和不可比较项。

## 必修口径

现有多店推广与商品金额先按日期聚合再取交集，可能把A店推广和B店商品误配。新路径先按平台×店铺×业务日配对，商品层再检验适用商品身份，之后汇总分子分母。缺覆盖的整期费率主值为null；辅助部分值单列匹配范围。相关旧共享修复交I串行应用。

京东归因总订单金额与天猫净成交分别标名；订单行/净成交笔数不改叫客户。ROAS不等于利润ROI或自然增量。归因金额与平台成交的子集关系未验证时不标渠道份额，不计算“总成交减归因成交=自然成交”。

推广SKU、触发SKU、跟单SKU分别建模，不把跟单成本直接当独立投放对象效果。同名计划按ID隔离，跨店同ID不合并；不同视角的同一批事实不能相加。

## 现有能力与扩展

基础概览/趋势/商品排行已有来源。原京东深度诊断的店铺与1至7日限制在扩展验收前保持；长周期/其他店/天猫计划词表须先核验原始维度、完整覆盖、权限、容量与关系证据，不因界面设计需要而伪造明细。AI聊天候选不当已完成能力，新增接线由I处理中央工具表与预算，不自行触发真实付费模型验证。

可向S/C提供版本化推广摘要、店铺对比和能力状态；P的联动复用精确商品身份，不能按名称猜配。无源字段给明确状态并完成其余核心区。创建运营事项、保存负责人或自动停投等不在本提示词核心范围。
