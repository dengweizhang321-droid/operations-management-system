# 店铺全景重构提示词

你担任方案二的店铺全景负责人S。请在用户明确派发本提示词后，实现 `docs/netshop-refactor/04-content-scope.md` 中2.1至2.8的核心内容，条件字段按可信来源启用；用户当次增删优先。本任务是隔离开发和验证，不包含上线、补跑或新增业务写操作。

先读当前指令、AGENTS.md、README.md及 `docs/netshop-refactor/` 全部共同契约。向I取得已合入main的O/F/P/A提交、冻结DTO和共享文件范围。从该最新main的独立 `codex/netshop-panorama` 工作树开展，不复制其他Agent未合入或未提交文件。

## 页面目标与内容

将店铺分析升级为单店全景，保留旧 `view=analysis`。采用固定平台/完整店名/日期/比较栏与页内章节导航；未选择店铺时明确选择，不默默采用任意第一店。

- 2.1经营成绩与变化：平台成交、ERP净额、订单销量、客单价、毛利退货、推广分组，实际比较日期、差额及商品贡献，独立趋势和逐日表。
- 2.2流量成交：商品浏览/访客累计、收藏加购、下单支付、累计转化和访客价值；来源支持的搜索/停留/跳失，高访客低成交清单。
- 2.3商品结构：成交商品、TOP5/10贡献、类目、增长下降、当前状态/库存摘要，点击进入P单品详情。
- 2.4推广经营：复用A花费/归因/ROAS/点击成本/费率及覆盖，显示趋势、投入分布和重点对象，带范围进入A。
- 2.5毛利退货：复用ERP领域成本、订单毛利、大毛利和退货；贡献排行与原商品经营/销售入口，不造第二套利润算法。
- 2.6客户企业购：已有平台商品级新老买家可按原口径呈现；企业购金额/订单/件数/商品结构只在专用来源成立时展示。客户去重、复购、B端占比条件未成立时显示具体缺口。
- 2.7目标复盘：只读引用现有年度目标/月财报进度与历史同期；已记录事件可以叠加，不能推断因果、不线性虚构月目标。
- 2.8数据口径：按源/店/日覆盖、截止日、映射、不可比项；进入原导入或工作流记录，不启动补跑。

重点商品表包含图、名称/精确ID、类目、成交件数/访客、转化、贡献/增减、推广、退款、映射和覆盖。来源无法关联时保留原记录和明确状态。卡片定位章节、日期定位明细，返回恢复用户范围。

## 实现职责

只改分配的 `app/netshop/panorama/**`、专属只读处理器/API/测试及对应文档。名称以F冻结表为准。公共入口、注册、gateway、旧共享文件和其他领域consumer扩展交I协调，不自行编辑或加权限。

P/A接口是主线依赖，不能复制它们的聚合算法到全景。跨域组合须复核来源revision，独立分区分别披露实际截止日；无分布式原子快照时不能自称全源同一时点。页面按需加载，不因某一领域失败吞掉其他可信内容，也不把错误当未接入。

网店总览01及其新旧模式保持；全景不另做全平台总览。真实店铺UV/自然付费/企业购比例缺源时完成其余内容，不填模拟或广告点击推算。
