# 店铺与平台对比重构提示词

你担任方案二的对比负责人C。用户派发后，在独立工作树实现内容清单3.1至3.6的核心范围，保留旧 `view=platforms`。执行前读当前指令、AGENTS.md、README.md和 `docs/netshop-refactor/` 共同契约，取得已合入main的F/P/A接口提交与I的文件分配；用户补充优先。

## 目标

提供店铺对比和平台对比两个模式，解释规模、效率、结构和变化差异。平台可展开旗下店铺，店铺可进入S，商品可进入P，推广可进入A，统一保留日期和指标语义。S尚在并行开发时使用冻结的导航目标，合入前由I确认真实依赖已落主线，不引用未合入组件。

## 必需内容

1. 3.1规模与增长：平台成交、ERP净销售、订单销量、毛利分口径排名，本期基期、增减、占比与贡献。
2. 3.2经营效率：客单价、毛利率、退货率及来源成立的商品/推广效率；指标矩阵、规模与效率分布，不默认综合评分。
3. 3.3趋势：同指标日周月对照，绝对值与以有效基准为100的相对走势；基准0/负/缺失不能强算指数。
4. 3.4结构：类目占比、TOP集中度、成交商品数、定义清晰的价格带、经核验同款映射的商品对照。
5. 3.5推广：花费/占比、归因金额、ROAS/CTR/CPC、费率及变化；同平台优先，来源不一致时明确并列观察而非混合评分。
6. 3.6可比性：两期店铺集合、各源覆盖/缺字段、纳入排除原因；只有身份与历史成立时拆持续店铺变化和统计集合变化。

筛选包括日期、基期、平台/店铺、指标来源、日周月和覆盖状态。主图同时2至4对象，完整排名有界分页；部分覆盖对象可查看，但不能静默填0或混入完整排名。综合表按规模、效率、投放和覆盖分组，支持列设置。

## 不变量

- 平台与其店铺不能混排累计；当前和基期使用明确可比较集合，不用各期TOP页作为全量比较。
- 比率按合计分子分母算，不能平均店铺ROAS、转化率或毛利率。
- 京东SKU与天猫SPU访客不直接当同口径店铺效率；缺乏可比指标时提供源说明而非硬排。
- 同名店/商品不模糊合并，类目未知保留未分类，同款映射缺失不猜。
- 平台成交、ERP净额和财报金额分别显示，不混合成一个销售额。
- 点击/返回/URL刷新/前进后退保持范围，快切对象拒绝旧响应覆盖。

## 代码与验收

只写分配的comparison组件、专属服务/API/测试。公共文件和共享算法需求交I，不复制P/A或销售日期算法。验证两店同ID、不同覆盖、两期不同排名、缺失/零/负基期、加权比例、平台展开与各专题钻取、权限及响应上限；在独立PostgreSQL复验查询与代表规模，UI使用隔离合成数据。

交付六分区完成表、对比集合规则、数据源/不可比矩阵、接口/共享变更请求、测试/截图、分支和提交SHA。由I串行合main，复核组合；不部署、不启停、不迁移生产、不触发真实导入或外发。
