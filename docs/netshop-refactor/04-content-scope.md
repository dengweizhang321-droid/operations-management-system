# 网店分析各栏目内容范围

本表继承用户已选择的方案二和上一轮内容清单V1。编号可供用户逐项增删，也用于Agent任务和验收追踪。**核心**表示建议本期用已有事实实现；**条件**表示必须先验证字段/来源/覆盖/关联；**可选**不因本工作包自动获得开发或业务写入授权。用户明确派发栏目提示词时，以提示词列出的范围及其当次补充为准。

## 网店总览

01布局及其原契约保持：平台/店铺/日期筛选，天猫京东TAB，成交金额、访客累计、推广花费、推广费率、转化率五卡，店铺详情，两张趋势，逐日/每7天明细，真实旧新视图切换。这里只协调既有O工作，不重选版式、不改变已确认字体与数据真实性要求。

## 店铺全景

单店为主，固定平台/店铺/日期栏和页内导航，八章节按需加载。多店比较在第三栏目进行。跨页保留上下文，卡片和日期可定位到明细；错误不让旧店铺内容伪装新范围。

| 编号 | 内容 | 核心交付 | 条件与边界 |
| --- | --- | --- | --- |
| 2.1 | 经营成绩与变化 | 平台成交、ERP净额、订单、销量、客单价、毛利/退货、推广分组；本期/基期/差額；独立趋势及逐日表；商品增减贡献 | 不自动对账平台与ERP，不推断事件因果 |
| 2.2 | 流量与成交 | 商品浏览、访客累计、收藏加购、下单支付、商品累计转化及访客价值；高访客低成交清单 | 搜索、停留、跳失按各平台字段能力；真实店铺UV/付费自然流量须补源；不是同一批用户路径漏斗 |
| 2.3 | 商品结构 | 成交商品数、商品/类目贡献、TOP5/10集中度、增长下降、重点商品表；进入P详情 | 在售状态和库存为当前快照；无历史不能判新品/滞销；价格带定义明确 |
| 2.4 | 推广经营 | 花费、归因成交、ROAS、曝光点击、CTR/CPC、订单指标、费率；趋势及投入分布；进入A | 复用A；计划/词明细仅在源支持时展开 |
| 2.5 | 毛利与退货 | ERP成本、净销售、订单毛利、大毛利率、退货金额/量/率；贡献排行；进入原商品经营/销售 | 精确商品映射后才能单品关联；不称净利润，不擅自扣费用或摊月财报 |
| 2.6 | 客户与企业购 | 专题能力状态；有可靠来源时展示新老买家原口径、企业购金额/件数/订单/商品结构 | B端占比需子集关系；去重客户/复购需匿名身份与历史；不从商用品类猜B端 |
| 2.7 | 目标与复盘 | 只读引用既有年度目标及月度财报进度；差额、历史同期；已记录事件对照 | 不新建目标编辑；无月度目标不自动线性摊成年目标月进度；事件不是因果证据 |
| 2.8 | 数据与口径 | 每来源截止日、店日缺口、字段缺失、映射状态、可比较性；进入原导入/工作流记录 | 只读查看不启动补跑；技术明细放展开层 |

重点商品表：图、名称、精确ID、类目、成交/件数/访客累计、转化、贡献/增减、推广、退款、映射与覆盖。各来源相应列只在有可靠关联时显示，未匹配记录不丢弃。

## 店铺与平台对比

两个模式分别选择店铺或平台，主图建议2至4对象、完整排行服务端分页。默认显示已选范围；缺数对象可查看但不混入完整比较排名，不静默删除。

| 编号 | 内容 | 核心交付 | 条件与边界 |
| --- | --- | --- | --- |
| 3.1 | 规模与增长 | 成交/ERP净额/订单/销量/毛利分口径排名，本期基期差额及贡献 | 平台和店铺不混排；固定统计集合 |
| 3.2 | 经营效率 | 客单价、毛利率、退货率、具备条件的商品效率与投放效率；矩阵和分布 | 分母加权；不默认综合评分；跨平台来源定义差异披露 |
| 3.3 | 趋势对比 | 同指标日周月、两期比较；绝对值及基准值归一走势 | 基准为0/负/缺失不强算指数，图轴与单位清楚 |
| 3.4 | 商品与类目结构 | 类目占比、TOP集中度、商品数、价格带、验证过的同款比较 | 类目字典和同款映射成立后启用；未知分类保留 |
| 3.5 | 推广对比 | 花费和占比、归因成交、ROAS/CTR/CPC、费率及变化；钻到A | 优先同平台比较；归因口径不一致不能无说明排名 |
| 3.6 | 可比性与差异 | 来源覆盖、两期对象集合、排除原因；条件成立时拆持续店铺变化与范围变化 | 不把平台某日有行当所有店已覆盖 |

综合表：对象、平台、本期/基期金额、增减/增幅/贡献、订单、客单价、毛利率、退货率、推广、有效天数与可比性。金额与效率列分组，点击平台展开店铺，点击店铺进S，商品或类目进P。

## 商品表现

三个二级页为经营表现、单品详情、货品档案。详情由精确商品身份进入，不把无选择的详情做成空菜单。默认SPU，京东可切SKU；天猫SKU日经营能力不凭主数据目录伪造。

| 编号 | 内容 | 核心交付 | 条件与边界 |
| --- | --- | --- | --- |
| 4.1 | 商品概况 | 本期有数据商品/成交商品数、金额、件数、客户累计、访客累计、退款 | 有数据商品不称全店在售全集 |
| 4.2 | 贡献与增长 | 成交贡献、TOP集中度、增长下降贡献、持续/新增成交；类目及价格带 | 两期完整后才判断无成交；价格带注明成交均价或当前标价 |
| 4.3 | 流量与效率 | 浏览/访客/收藏/加购/下单/支付、平台搜索字段；公开规则关注清单 | 最小样本与规则可查；不是用户旅程或爆品黑箱评分 |
| 4.4 | 推广与ERP关联 | 广告指标、ERP净销售/成本/毛利/退货、关联状态 | 两条金额链分开；未映射不能默认零成本；天猫映射另验 |
| 4.5 | 单品经营档案 | 身份图文、规格、类目编码、两期成绩、独立趋势、SPU下SKU贡献、当前库存 | 历史SKU归属需可靠版本关系；库存/标价不是历史序列 |
| 4.6 | 单品逐日明细 | 平台、推广、ERP分别展开；日期钻取、来源/覆盖、字段说明 | 同类token范围内分页，跨来源使用修订向量 |
| 4.7 | 货品资料与映射 | 原目录图片、SPU/SKU/商家码/ERP码、品牌类目、状态、价格库存及各自快照 | 保留目录原功能；不按名称合并事实 |
| 4.8 | 资料质量 | 缺图/编码/类目、冲突、陈旧资料、未关联 | 只读展示；修改映射、批量改码和合并删除为可选后续 |

列表列组：身份、成交、流量、比较、推广/ERP关联、覆盖状态。列设置、服务端搜索/排序/分页和返回恢复必须成立。商品当前页的两期比较按精确ID配对；增长榜要先全集配对再分页。

## 推广分析

京东与天猫保留来源名称；多店表必须显示店铺。页面搜索是否影响顶部汇总明确展示，相关钻取保留当前店铺/日期/对象身份。

| 编号 | 内容 | 核心交付 | 条件与边界 |
| --- | --- | --- | --- |
| 5.1 | 效率概览 | 花费、归因成交、ROAS、展现点击、CTR/CPC、订单指标及同店同日费率；两期变化 | 京东订单行与天猫净成交笔数不改叫客户；整期缺覆盖费率主值为空 |
| 5.2 | 趋势与变化 | 花费和归因成交、ROAS/流量成本趋势、变化贡献 | 公开核查规则，不断言归因原因或建议立即停投 |
| 5.3 | 店铺对比 | 投入/产出/效率/变化/覆盖表，多店时展开 | 同平台优先；单店不重复一张比较表 |
| 5.4 | 推广商品 | 跟单SKU或商品ID、花费/占比、归因金额、ROAS、点击订单、覆盖；进P | 推广/触发/跟单身份分开；不跨店误合 |
| 5.5 | 计划与单元 | ID、名称、投入产出、贡献变化、关联商品和词 | 仅已保留可靠明细的源可做；扩店扩周期另验容量和权限 |
| 5.6 | 关键词与搜索词 | 词、计划/单元、匹配方式、成本/产出/效率/变化与真实关联 | 天猫商品日聚合不能伪造词表；无词投放单列 |
| 5.7 | 深度诊断与复盘 | 观察事实、规则、证据、核查建议、观察指标/期、停止条件；复用原报告 | 原京东诊断店铺及1至7日限制保留直到扩展验收；HTML/XLSX同源 |
| 5.8 | 数据与归因 | 金额/订单定义、归因窗口、店日覆盖、映射及不可比说明 | ROAS不等于利润或增量；归因金额不可与自然成交简单拆分 |

推广行动创建、负责人、截止日和保存状态为可选扩展，需要用户明确纳入后复用运营事务；不得默认自动投放、停投、调预算或发送消息。

## 完成判定

核心内容有可用数据时交付真实查询与展示；条件内容缺源时交付清晰的能力状态、缺口证据与补源要求。不可把大量空卡或模拟结果当完整业务功能；也不可因一个字段缺失擅自删掉其他核心分区。

角色交付逐项列“已实现并验证、需来源启用、未实现、用户明确不做”。合成UI、独立PostgreSQL验证、真实来源只读核验、生产采用分别记录，不能合并成一个完成勾选。
