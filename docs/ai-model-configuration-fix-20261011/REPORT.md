## 原因与修复

1. Django 默认仅信任 OpenAI origin，截图的 OpenCode 被拒绝。Django 与 Worker 同步增加精确 `https://opencode.ai`，不放行子域、相似域或非默认端口；原 HTTPS、私网、查询凭据、DNS 固定、重定向保护保持。
2. 用户提供 `/zen/go`，原请求拼接会遗漏 `/v1`。仅对该来源的精确 `/zen/go` 根路径补全 `/v1`，保存和旧记录运行时均兼容，其他供应商路径保持。
3. 新增后再次编辑的回归复现 `includeStreamUsage 必须为布尔值`。公共 SQL 布尔 helper 返回整数，生成参数却是 JSON 对象，保存后为 0/1。生成参数新写入保留 JSON bool；读取仅兼容历史 int 0/1，请求侧继续严格拒绝数字。无需历史批量迁移。
4. 页面增加 OpenCode 地址提示；未知来源报错提供环境变量配置入口。跨 origin/协议必须新密钥、管理员权限、版本检查保留。

| 参数 | 截图值 | 判断与建议 |

| 最大输出 | 65,536 | 低于 models.dev 对 Go 该模型标注的 384,000；适合复杂推理/长报告，日常建议从 32,768 起步，观察截断再调。额度包含推理消耗与否须按端点语义验收，不能全视为可见正文。上限不会强迫输出同样数量，也不是越大越聪明。 |

| 任务总时限 | 1,800 秒 | 是模型和工具共用的 30 分钟预算，长分析可保留；日常建议 600 秒，按实际等待与失败率调整。更长时限不承诺更快或更准确，其他渠道仍受自身期限限制。 |
| 推理、温度 | 跟随供应商默认 | 兼容性较稳妥，可保留；这不代表推理关闭或温度为零。不建议在未验证端点支持时额外强制推理强度/温度参数。 |

建议分为日常问数（32,768 输出 / 600 秒）与复杂分析（65,536 输出 / 1,800 秒）两类；上下文保持 1,000,000。上述为工程起点，未作真实供应商性能基准。
