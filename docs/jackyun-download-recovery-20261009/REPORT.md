# 吉客云已绑定库存下载重试与自动续跑

日期：2026-10-09。本文记录开发阶段验证；后续已按用户明确授权采用 Worker/helper 与 n8n 分类器，生产结果及限制见 [生产记录](PRODUCTION.md)。原业务没有补跑，不能把发布成功视为五表数据已恢复。

## 问题与目标行为

正式执行 7380 在首张库存导出任务创建并唯一绑定后，OSS GET 报 `fetch failed`，本地仅留下空 inventory 下载目录。共享错误流程按普通瞬态错误安排一小时重试。7394 从完整入口运行，但旧计划还在 exporting，且没有 operator API 续跑许可，A 节点被防重复导出门禁拒绝。错误流程 7395 正常结束只表示停止派生重试，不表示业务成功。

本次将恢复能力接到原完整执行入口；原任务、原计划、原 n8n error 与防重复 POST 约束保持。新逻辑不处理跨日采集、部分导入、任务不唯一或提交结果未知。

## 改动

1. `lib/jackyun/oss-download.ts`：同一附件 GET 最多三次，失败后间隔 2 秒、4 秒；使用同一个 AbortSignal/总期限覆盖等待、重定向和文件流，沿用调用方预算、最大 300 秒。仅白名单网络错误及 HTTP 408/429/500/502/503/504 重试；TLS、认证、文件格式、来源和磁盘错误停止。每次重新下载前清除本次独占的 `.part`，清理失败不重试。最终文件仍经原 XLSX 签名、字节摘要和来源回执校验。
2. `tools/jackyun-api-export.ts`：只有首张 inventory 已绑定、短重试失败且本轮不是续跑时，返回精确 `JACKYUN_BOUND_DOWNLOAD_RESUME_REQUIRED`；其他模块及续跑再次失败返回终止自动派生的下载错误。错误仅包含允许的机器码与尝试次数，不含 URL、凭据或响应正文。
3. `lib/jackyun/automatic-api-resume.ts`：领取 helper 后，在原全局运行锁内，通过现有 n8n 只读证据和 API 原任务检查器核验原失败、当前运行身份、空下载槽、唯一完成任务和附件摘要。核验前后比较 n8n 证据及本地计划/controller/policy/active 字节摘要；随后用 create-only 单文件同时保存证明与唯一新 execution 绑定。不会提前一小时发放只有 30 分钟有效期的许可。
4. 同一个绑定执行可继续原 A/B/C/D/E；第二个执行、损坏回执、跨日或原 n8n 证据变化均停止。初次核验超过 30 分钟也拒绝。已批准的 operator 许可继续使用原通路和原 30 分钟限制。历史 `fetch failed` 仅在同样严格的已绑定库存证明成立时可由新完整执行恢复，不凭错误字符串直接放行。
5. 共享错误分类器与生成的 n8n Code 节点同步：精确库存恢复标记才进入小时续跑；普通吉客云 B 节点 `fetch failed` 因阶段不明停止派生，其他下载错误及恢复阻塞转人工。新分类只改变吉客云分支，原登录/验证码/归属/未知提交等终止规则优先。

## 隔离验证

- 使用临时目录、合成任务与受控 HTTP 替身，不读取真实业务数据或平台凭据，不执行真实导出/导入。
- 真实导出执行器实验：首次三次 GET 失败形成可恢复错误；恢复仍使用原 taskId；恢复再次失败不再产生无限小时链；随后受控成功实验只为检验同一绑定任务下载路径，库存 POST 总计仍为一次。该实验不是生产复跑成功，也不是五表真实导入验收。
- 自动恢复覆盖一小时后领取、原文件保持、重复/并发消费、损坏回执、下载残留、验证效果、附件变化、原证据变化、核验中本地变化、在途执行、错误节点、日期不符及核验超期。
- OSS 覆盖瞬态连接、HTTP 503、响应流错误、403/TLS/格式拒绝、重定向来源/凭据/端口拒绝、等待与正文共同期限及错误脱敏。
- 本地分类与实际生成的 n8n Code 同测全部允许机器码、未知码、越界次数、错误节点和同时存在安全验证/提交未决。
- 最终专项：39 项通过；较早完整吉客云专项 291 项通过，之后追加两项期限负例并在最终专项/全量中执行。
- `npm run build` 通过；真实构建 helper 的原零效果恢复隔离冒烟通过，合成 n8n 与旧计划字节保持，真实业务动作 0。最终 helper SHA-256 为 `41f428a77b4919971402e29b1f1c2e581f48ec83e7f2ba02e25d1acbaf538cdd`。
- 后端边界扫描 650 个模块、0 违规；n8n 元数据读取仍只通过原精确摘要批准的 helper 入口。
- 修改源码和测试的 ESLint 0 错误、0 警告。全库 ESLint 有 1 个既有错误及 35 个警告；错误位于 `docs/performance-experience-audit-20261008/tools/frontend-function-probe.mjs:24`，该文件与起始 main 的 Git blob 均为 `fa6fcde4f3b57962d83f23388817a78f19b6867b`，单文件复验重现。

## 上线与恢复范围

需要一起受控采用 Worker/helper 和原共享错误工作流的分类节点。不能仅依据仓库 JSON 推断正式 n8n 已更新，不能整套覆盖生产工作流定义。原工作流 ID、计划时刻、所有权、Webhook 和历史执行保持。

本次上线已获得明确授权并按项目严格发布流程执行；发布授权不包括原 7380 的真实续跑。后续恢复仍需另行授权，并在同一上海自然日、原附件和本地状态不变时重新核验。跨日、附件刷新、部分文件或已开始导入仍转人工，不删除 active，不重新提交原库存任务。

网络故障的 DNS/TLS/连接底层原因未由历史 `fetch failed` 证明。本改动提高瞬态故障的恢复能力并保留后续诊断码，不声称已消除平台或网络故障。
