## 追加调整：组合装大毛利率区间

- 上方四张区间卡片始终按组合装种类统计，独立于下方单品／组合装明细类型及已选毛利区间；仍遵守当前日期、平台、店铺、搜索、品类条件。点击卡片自动切到组合装并应用对应区间，回第一页。单品视图的品类选项也包括组合装品类，避免卡片有统计而筛选入口缺失。
- 区间为 `<38%`、`≥38%且<42%`、`≥42%且<46%`、`≥46%`；标题、下拉筛选、实际大毛利率列及预警色同步。净额为零／负值的大毛利率保留不可用，不混入四档。
- 商品域明细与汇总的大毛利率统一纠正为 `(销售净额－货品成本)÷销售净额`，不扣费用分摊；订单毛利金额继续取原订单毛利，不混用两个指标。此更正也作用于既有商品 API 的同名指标；数量、金额、库存及权限不变，旧区间参数保留兼容。历史规格快照协议升级，旧版本分页会触发原有重载。
- 新增独立 `comboMarginMetrics`，不冒充下方分页全集合的统计；同一 scope／snapshot 下与明细一起校验，首屏保留既有渐进读取与 full 退化流程。分布维度、计数、缺字段及越界响应拒绝。
- 私有 PostgreSQL 19 项通过，含新边界、正确公式与订单毛利不一致的负例、组合装排序、单品／组合装切换、区间过滤时卡片不缩水、搜索联动、不可用毛利率。旧版对照继续比较未改变的金额、数量、身份、库存及分页；已明确变更的大毛利率按业务公式另验，不以旧错误比率为基准。

## 页面行为

- 商品经营明细增加“查询”按钮，右侧为“单品（单一规格）／组合装”切换；默认单品，切换立即查询并回第一页，恢复默认回到单品。
- 单品行是同订单凑套后的剩余规格，销量单位为件；组合装行显示整套金额和套数。原有分页、排序、毛利筛选与分区恢复流程继续复用，不生成“其余 N 个”合计行。
- 点击“查看构成”只展示当前子件编号、名称、每套数量，不调用规格趋势接口。单品规格趋势继续使用原始规格订单（含组合装子件），页面明确说明这一口径。
- 毛利测算继续复用已经校验的当前页，不因切换子页额外扫描；所选组合装的均价和均成本按套计算。

## 计算与边界

- 主线此前只有规格汇总，新增计算由 Django products 实现，复用销售域的业务行、特殊货品排除、principal scope、平台和店铺过滤规则。ERP／库存商品集合保持原范围，排除刷刷仓；未传 `productKind` 的既有 API、AI 和搜索消费者保留原字段结构及金额、数量，商品大毛利率按上方追加口径修正。
- 在同一平台、店铺、渠道、订单内匹配当前 ERP 配比。正向和负向数量分开；订单号缺失时回退线上订单号，再回退唯一源行号，不把无编号的独立行凑为一单。
- 子件单买且恰好满足配比会被识别为组合装，原始数据不足以消除这一推断局限。共享子件优先分配给子件种类更多的组合装，再按母件编号 UTF-8 顺序分配；每个子件最多分配一次，结果确定但不代表已识别真实销售套装。
- 每笔源行按累计已分配数量分配销售、成本、费用和订单毛利的整数分，尾差留给剩余分配；全范围“组合装金额＋剩余单品金额”与原规格汇总逐分一致。只对金额验证守恒，件和套不作数量合计。
- 配比不分时间版本。现行 ERP 导入原子替换组合装关系并递增 ERP revision；商品 snapshot 和缓存复用这一 revision，更新后历史订单重新推断，旧分页版本拒绝。
- 编号／名称查询也匹配组合装子件，命中时保留整套金额；按行筛选后的明细可能高于按源规格筛选的汇总。品类、品牌、供应商继续用母件档案；缺母件元数据时保留缺失，不猜测子件属性。
- ERP 比例支持千分精度。销售源只有整数件时，只凑出能消耗整数子件的整数套，避免生成不存在的小数源数量。
- 关系最多 20,000 行、订单源行最多 200,000 行，超限拒绝并提示缩短周期，不返回截断统计。匹配只扫描当前订单子件的候选组合装；产品集合用数据库子查询，不生成大型代码参数列表。
- 货品监控的瓶颈子件法属于组合装出库上限估计（`COMBO_OUT_NOTE`）；瓶颈子件单卖会使估计偏高，组合装与子件监控数量不能相加。本次将用户给出的说明展示在口径中，未修改监控算法或导入流程。
