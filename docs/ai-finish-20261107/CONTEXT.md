# 流式输出与上下文恢复核对

| 能力 | 现有入口与本次交付 |
| --- | --- |
| 普通聊天 | Django chat 的 on_text 将公开正文交给 Worker 流式转发。最终回答仍由原请求收尾。 |
| Pi 正文流 | 对成功验证过 SSE 工具闭环且模型配置指纹仍匹配的前台 prompt，Django 在供应商响应到达时按 dispatch 标识、偏移写入公开文本事件。浏览器沿现有 eventSeq 游标读取，结束后由 Runner 最终消息替换。缺少 SSE 证据的模型保留已有 JSON 调用，不做试探或失败后重发。 |
| 中断与重连 | Pi 原会话的 eventSeq、generation、epoch 和派发身份继续约束重连。恢复显示不调用模型。新事件仅包含公开文字，工具参数、思考和供应商帧不进入这些事件。 |
| 长上下文 | 普通聊天的 fit_context 保留当前问题、整轮删除早期已结束的用户回合；Pi preserve_context 超预算会拒绝请求。工作区已有“压缩历史（调用模型）”以及独立 compact 操作、控制回执和就绪判断。用户可在无活动操作时手动触发；Runner 的自动重试和自动压缩继续关闭。 |
| 知识检索 | 现有 main 已包含按评分保留词法候选的修复。此次没有改变知识检索数据库或语义。 |

普通聊天、Pi 事件续读、上下文预估和人工压缩各自有独立作用。这里没有宣称客户端一次请求就是 Pi 内部逐 token 协议，也没有启用无人值守的压缩或对未知模型请求的自动重放。

后续恢复清单另行实现并核验。见[恢复与压缩报告](../ai-context-resume-20261107/REPORT.md)。
