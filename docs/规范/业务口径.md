# 业务口径与数据查询

路径约定：反引号中的代码、配置和工具路径均相对仓库根目录；Markdown 链接相对本文件。

- 业务时区固定为 `Asia/Shanghai`。自动化日期、今日/昨日、导入覆盖和相对日期均以该时区计算；仅为避免日期漂移的纯日历运算可使用 UTC，但不能把 UTC 当作业务时区。
- 系统金额默认以人民币分存储和传输；展示为元时除以 100。净销售额包含负值退款，销量必须明确是正向销量、退货量还是净销量。
- 销售分析的“大毛利率”口径固定为 `(分摊后金额合计 - 货品成本合计) / 分摊后金额合计`，不扣费用分摊；“订单毛利”仍使用导入明细的毛利字段合计。销售总览、渠道/店铺、品类、趋势、API 和 AI 工具不得把订单毛利直接除以销售净额作为大毛利率。
- 日期查询使用左闭右开区间。店铺身份不能只靠模糊名称，至少保留并核验 `platform + shop_name`；销售源存在 `channel` 时还要交叉核验渠道。
- `刷刷仓` 是当前销售、库存和成本分析的业务排除仓。除非用户明确变更业务规则，不得删除该排除或把它混入经营指标。
- 库存总览与备货计划的销量窗口固定为销售最新截止日向前 30 个自然日，使用正向销量且退款不冲减备货需求；备货计划展示货品跨仓近 30 天总销量。分仓库存供应商优先使用吉客云“规格默认供应商”，老快照才回退 ERP。仓库分类与是否计入库存统一使用 `config/inventory-warehouse-mapping.json`，不得仅靠前端文案或临时模糊规则另算一套。
- 备货计划 Excel 导入只允许操作员或管理员使用标准模板，一次最多 200 行并原子提交；货品与仓库必须存在于同一次最新权威库存快照，过期快照须显式确认，任一行无效则整批拒绝。导入不得自动产生钉钉外部写入；草稿多选的一键操作必须逐条完成本地确认后再复用单计划钉钉幂等标记、契约核验和写后回查，已确认计划的批量同步也复用同一链路。任一阶段失败的项目保留勾选供人工重试，不回滚其他已确认计划，不因混合选择丢失另一状态的选择。
- 备货计划群消息只能由操作员或管理员多选已确认、且采购与工厂身份完整的计划后显式预览和确认发送；目标群、机器人和采购人必须动态精确匹配。话术按“采购 → 对应工厂”分组，货品行固定为“货品编码 货品名称，× 数量台”。发送前同步所选钉钉多维表记录，群消息使用库存域投递账本防重；新多维表标记统一为“运营管理系统备货计划ID”，只把旧“TERUISI备货计划ID”保留为历史查询兼容，任何流程不得据此新增重复记录。
- 市场分析只代表“当前 TOP 榜单覆盖口径”，不得表述为完整行业大盘。SKU 与 SPU、类目、榜单 scope、经营模式、价格段和统计周期必须保持完整身份隔离。
- 市场“正式市场定位价/主图展示价”和底层成交均价保留独立来源；商品榜单的展示契约例外：存在正式主图价时，该行成交均价展示为同一主图价，不存在时才使用底层成交均价。需要正式价格的价格带、AI 工具或发布流程只能使用符合当前确认契约的人工确认价；候选价、分期金额、定金、起售价等不能静默升级为正式价格。
- 市场行业汇报与机会矩阵只有在单一类目、单一榜单 scope、单一 SKU/SPU 维度、连续可比月份和相关商品正式价格完整时，才可输出“建议进入”或“谨慎回避”；任一条件缺失时只能保持“持续观察”并披露缺口。机会评分仅代表当前 TOP 榜单信号，未纳入采购成本、推广、安装售后、退货、滤芯复购和合规准入时不得当作最终投资或利润结论。
- SKU 维度的“标准售价”一经人工复核并正式入库，同一三级类目、榜单 scope、SKU 维度、SKUID 和图片哈希的其他月份直接沿用该分类与标准价，不再调用 AI 或重复标准入库；同一业务身份的 SKUID 图片变化时，只复用仍在当前细分类目字典中的人工确认分类，并重新执行价格专用视觉识别，不得沿用旧图价格；没有合格历史分类的新 SKUID 才执行分类与价格的完整识别。该规则不跨类目、scope 或 SKU/SPU 维度，不适用于定金、分期金额或无法判断的价格。
- 新品阶段矩阵中的“目标店铺”面向用户统一称为“店铺规划”，并可直接进入项目编辑；矩阵单独展示项目负责人和工作状态备注。建模、分析定价、图片、视频、备货五个节点只要求选择状态；阶段负责人、计划截止日、阻塞原因、节点说明/交付结果、证据名称和证据链接均为选填，受阻状态不得因缺少阻塞原因而拒绝保存。
- 上新销售跟进按运行机器本地时区划分和调度自然周，不再固定使用上海时区；销售归集唯一使用吉客云货品代码。产品线名称、产品图与吉客云名称学习关键词由用户维护，一个产品线可以包含多个吉客云代码与货品名称；产品图从本地选择 JPG、PNG 或 WebP，保存前转换并压缩为不超过 300KB 的 JPEG 后随产品线进入 PostgreSQL 权威，页面、Excel 与钉钉周报复用同一图片内容，编辑界面不得恢复手填图片链接。产品主数据导入后触发学习，名称/关键词只命中一个产品线时自动补入，多产品线命中时保留待人工判断，不得猜测归类。产品线从监控开始日持续跟踪，不设置截止周数；操作员可暂停或启动监控，暂停项保留但不得进入钉钉预览、Excel 或发送截图。图片周报的周维度固定从 2026-08-03 起逐周累积，固定展示品牌、产品图、产品名称、净销量趋势和各周净销量；不得静默删除历史周。机器人名称、目标群和发送时间统一在“系统设置 → 钉钉机器人”维护，“运营事务 → 上新跟进”只保留图片预览、下载和直达设置入口。周报外发必须先动态唯一核验“志高助手”和“测试群聊”，将经过校验的 PNG 上传钉盘后由机器人仅发送“新品销售周报”文案与截图在线预览入口，并以数据库投递账本防止同一报告周重复发送；AppKey、AppSecret、token、预览链接和原始外部回执不得写入业务数据库或日志。
- 页面、接口、AI 回复和导出中的同名指标必须复用同一领域口径；不得在前端重新定义服务端指标。

- 上新跟进表格预览支持生成 Excel 工作簿；主数据品牌为空时按当前业务口径展示“志高”，钉钉机器人仍投递同版式 PNG 在线预览。
- 上新跟进的产品图在产品线列表、编辑预览、周报表格、钉钉 PNG 和 Excel 中统一放入固定展示框，按原始宽高比居中完整显示；不得使用 `cover` 裁切产品外观，也不得强制拉伸成方形。

## 运营数据查询规则

1. 查询当前 TERUISI 运营数据时，优先使用只读（read-only）`teruisi_operations` MCP；第一步调用 `get_data_freshness`。
2. 只有 MCP 不可用且用户明确指定本机已导入数据时，才可使用对应业务域 Django/PostgreSQL 的最小只读身份。当前所有业务域均已切换，不得使用本机 D1 或其历史副本查询当前运营数据。回复中必须说明替代来源。
3. 输出必须写明数据来源、数据截止日期、时间范围、渠道/平台/店铺/SKU 等筛选、金额和销量口径，以及缺数或映射异常。
4. 中文筛选必须参数化并保证 UTF-8。零结果要先核验覆盖日期、字段枚举、编码、退款和时间边界，不能直接断言无数据。
5. 只读连接不得导入、修改或删除数据，也不得声称已创建或改变补货计划。相关工具可调用时，不得用记忆、样例或估算代替真实查询。
