# 文档管理

本规范维护文档分类、命名和引用方式。项目开发与交付流程仍以 [开发与交付](开发与交付.md) 为准。

## 分类与入口

- [文档首页](../README.md)提供常用入口，[完整文档目录](../文档目录.md)列出项目自有 Markdown 文档。
- `docs/规范/`维护稳定约定；根 `AGENTS.md`仅维护必读入口与规则索引。
- `docs/使用手册/`按业务模块保存使用说明和人工导入手册。
- `docs/自动化/`按来源平台保存下载、登录、导入、通知和安全恢复操作手册。
- `docs/技术专题/`保存架构、领域迁移、接口契约、方案、候选及技术交接。分类不改变正文中的采用状态。
- `docs/运维/`保存部署启动、监控恢复、备份与存储手册。
- `docs/历史记录/`保存已明确属于旧流程或某次诊断、验证、采用的独立文档；不作为当前执行授权。
- 一次任务的报告与证据继续保存于 `docs/<任务目录>/`，由 [任务记录目录](../任务记录/README.md)分类导航。已有网店重构、性能优化、证据等专题保留原目录；不得只移动 Markdown 而拆散同一证据包。
- 根 `README.md`、`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`，技能 `SKILL.md`、GitHub指令、后端与演示说明、测试夹具说明保留工具或代码要求的位置，通过完整目录归类。
- `docs/OPERATIONS_DATA_QUERY.md`保留为跨项目和技能引用的固定查询规范入口。

## 命名

- 文件名准确表达对象与用途，区分商品主数据和日数据、手册和智能体、候选和现行流程；不得用“副本”“(1)”等下载后缀作正式名称。
- 新增中文文件使用“对象＋用途”，必要时用短横线分隔；英文专名、SKU、SPU、API等保留标准写法。
- 新增英文专题文件统一使用小写英文与短横线，例如 `ai-assistant-setup.md`；版本号、迁移号和执行号原样保留，不把它们替换为无语义序号。
- 一次任务的目录使用主题与日期，如 `markdown-organization-20261015`。描述清楚的任务目录内允许沿用 `README.md`、`REPORT.md`、`PRODUCTION.md`、`HANDOFF.md`等通用文件名。
- 历史日期、正文状态和证据摘要不因改名而重写；没有当前行为证据时，不把“候选”改为“已采用”。

## 移动与验证

1. 在独立分支与工作树操作，先检查已有改动和被代码、技能、测试读取的路径。
2. 移动时同步更新 Markdown链接、图片/附件相对路径、规范入口、技能引用和代码中的文档路径字面量。
3. 不改动带摘要或清单绑定的 JSON、原始日志、截图和测试夹具元数据中的历史路径；旧路径通过整理任务的映射清单追溯。
4. 核对文档数量、路径唯一性、正文保留和新增链接有效性；改到文档读取测试路径时，只运行直接相关检查。
5. 更新分类目录；目录只导航，不复制规范、操作手册或运行状态正文。
