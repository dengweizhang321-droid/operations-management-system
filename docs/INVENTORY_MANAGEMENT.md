# 库存管理板块说明

## 1. 目标与入口

库存管理用于把库存快照、销售需求、库龄、固定成本、在途与运营执行事项放在同一条链路中。页面包含：

- 库存总览：库存健康、补货风险、数据质量，以及按货品和仓别展开的销量映射缺口工作台。
- 库龄分析：10 个精细库龄区间、数量占比、货值占比与明细。
- 备货计划：建议加入草稿、确认、完成或取消；确认后可同步到钉钉“备货管理”并生成采购执行事项。
- 滞销清理：高库龄、低动销与滞销候选；可生成清理执行事项。
- 京东入仓监控：RDC/DC 区域库存、在途、正向出库、计算周转、供应商与长库龄风险。

所有库存、销售和成本分析继续排除 `刷刷仓`。

库存后端已完成 Django/PostgreSQL 正式单写切换：Worker 负责真实鉴权、XLSX 解析、HMAC 和有界传输，库存 reader/writer 固定使用 `127.0.0.1:8051/8052`。实现、迁移证据和运维边界见 [`DJANGO_INVENTORY_MIGRATION.md`](DJANGO_INVENTORY_MIGRATION.md)。

## 2. 公共筛选与跨 Tab 持久化

库存管理的五个 Tab 共用一套顶部筛选组件。货品编码或名称、仓库、品牌、品类属于公共业务范围，切换库存总览、库龄分析、备货计划、滞销清理或京东入仓监控时会保留并同步应用；各 Tab 的专属条件仍独立保留，例如总览的库存类型和健康状态、库龄页的风险状态和库龄区间、备货计划状态、入仓供应商。

筛选状态写入当前页面 URL，浏览器前进、后退、刷新及复制链接后均可恢复。所有公共维度由各接口在服务端筛选，页面不加载全量数据后再做本地过滤；销量映射缺口工作台同样只聚合筛选后的库存范围。筛选变化会重置对应分页、取消旧请求，并通过请求代次门禁阻止迟到结果覆盖当前范围。品牌和品类选项以各接口当前库存或库龄批次的未筛选全集为准，当前筛选没有结果时也不会把已选条件清空。

## 3. 数据来源与口径

| 数据 | 来源 | 主要用途 |
| --- | --- | --- |
| 分仓库存 | 最新完成的库存导入批次 | 可用、实盘、锁定、在途、库龄、固定成本 |
| 库龄报表 | 最新完成的吉客云库龄批次 | 库龄、7 日销量、30 日销量；存在时优先用于库龄分析 |
| 销售明细 | 所选统计周期内的销售订单行 | 同货品、同规范化仓库的需求与出库 |
| ERP 货品档案 | 货品主数据 | 品名、固定成本回退、供应商 |
| 运营设置 | 系统设置 | 补货阈值、销量窗口、负库存、自动补货和预警开关 |

金额按人民币分保存。库存货值仅统计有可信固定成本且可用库存为正的部分；成本不完整时页面必须标注覆盖率，不得把缺失成本按零元解释。

京东入仓仓库优先使用持久化的 `warehouse_type=jd_rdc`，同时兼容吉客云历史快照中的区域平台仓命名，例如 `上海常温C平台仓9号库-CHN`。兼容识别只影响查询分类，不改写历史事实。

## 4. 数据质量门禁

导入前拒绝以下高风险数据：

- 合计、总计、小计、汇总或 `total` 行。
- 系统未允许负库存时的负实盘或负可用库存。
- 单行数量绝对值超过 1,000 万。
- 库龄小于 0 或大于 3,650 天，避免把 Excel 日期序号误当库龄。
- 单件成本超过 100 万元或单行库存货值超过 10 亿元。

总览计算后还会执行全局门禁：

- 同货品、同仓库销量匹配率低于 60% 时，暂停精确补货数量、平均可售天数和新增备货计划。
- 自动补货设置关闭时，暂停自动建议。
- 库存快照超过 3 天时提示数据过期。
- 平均库存数量或平均库存货值明显异常时，暂停精确建议。

筛选或定位单一货品不能绕过全局质量门禁。销量映射缺口工作台最多返回 50 个缺口货品，并按京东、代发、售后、广东、样品、菜鸟和自营仓展示库存、销量、计算周转与在途，同时汇总总库存、已覆盖库存金额、总在途、总销量、总周转、建议补货和预警。仓别先识别明确名称，京东仓同时遵循 `warehouse_type=jd_rdc`；其余仓库归入自营，`刷刷仓` 始终排除。

## 5. 库龄结构

精细库龄区间为：`0–7`、`8–15`、`16–30`、`31–60`、`61–90`、`91–120`、`121–150`、`151–180`、`181–360`、`1 年以上`。

每个区间同时展示：

- SKU × 仓库记录数；
- 可用库存数量与数量占比；
- 已覆盖库存货值与货值占比。

页面可同时选择多个库龄区间，并可按品牌、品类、仓库和风险状态多选；筛选在服务端应用，并同步更新指标、分布图和明细。品牌优先取 ERP 货品档案，库龄快照没有对应货品档案时明确显示“未设置品牌”；品类沿用当前库龄或库存快照，空值统一归为“未分类”。分布图使用“库存数量柱状图 + 库存金额折线图”的双纵轴表达；库龄金额统一按“正向可用库存 × 固定成本价”计算，不采用报表中的零售价或其他金额字段。

库龄分析明细同时展示品牌、库龄分布区间、库龄天数、库存数和库存金额；当前页 CSV 使用相同字段与口径，库存金额以人民币元导出。

数量、货值占比只以库龄已识别且可用库存大于 0 的记录为分母。缺失库龄的库存单独披露，不进入区间占比。旧四区间响应仍保留，避免现有消费者失效。

## 6. 执行闭环与权限

- `viewer`、`analyst`：只读查看。
- `operator`、`admin`：维护备货计划、从已确认计划创建采购事项、创建滞销清理事项。
- `operator`、`admin`：可把已确认计划同步到配置绑定的钉钉多维表；受限数据范围账号不得执行。
- `admin`：另外允许同步库存文件。

库存总览可从缺口工作台或库存健康明细打开“创建备货计划”。货品名称、品牌、供应商、现有库存、近 30 天销量和预计消耗周期由当前权威快照回填；入库库房必须来自该货品当前库存行。人工填写的备货数量、对应采购、对应运营、部门、备货类型、下单日期、预计到货日、验货和备注随计划持久化。没有精确系统建议时仍可创建人工计划，但必须显式填写正数备货量并保留“人工创建”原因；这不会把低可信建议伪装成系统建议。

采购事项只能来自已确认的备货计划，并记录计划类型、供应商、入仓仓库、计划数量和预计到货日。滞销清理事项在保存前会重新核验最新库龄快照，只接受当前仍属于高库龄、低动销或滞销的货品。执行事项进入“运营事务”并关联来源对象；不会自动修改、删除或重新导入库存事实。

已确认计划显示“创建计划”按钮。按钮固定写入 `config/dingtalk-replenishment.json` 绑定的《备货计划进销存表》/“备货管理”，并在写入前回读表、字段和单选项契约。对应采购、对应运营和部门按钉钉真实 ID 精确解析；重名、无法匹配或单选项缺失时失败关闭。每条记录的备注包含系统计划 ID 标记，重试时先据此查找并更新原记录，写后逐字段回查；系统同时保存钉钉记录 ID 和同步状态，因此重复点击或边缘请求重放不会静默新增重复行。钉钉不可用只影响本次外部同步，不改变本地备货计划状态。

同步适配器复用当前 Windows 用户已安装的 DWS 与其钉钉 OAuth profile；仓库配置只保存稳定的组织/用户 profile 标识、Base/Table/Field ID 和字段契约，不保存 access token、密码或应用密钥。部署前须以同一 Windows 用户完成 DWS 登录并对目标 AI 表格保有写权限；授权失效时按钮明确失败，不回退到群机器人 Webhook、浏览器自动化或其他账号。

## 7. 京东入仓监控边界

当前版本提供的是可复核的第一阶段监控：

- 只统计京东 RDC/DC 与受控规则识别的京东区域平台仓。
- 7/30/90 日出库只统计正向销量；退款不计为出库。
- 计算周转天数为 `当前可用库存 / 近 30 日平均正向出库`。
- 库存货值使用系统固定成本；不是京东供应价或结算价。
- 供应商来自 ERP 货品档案，缺失时明确标记待补映射。

京东原生库存、原生周转、供应价/结算价尚未接入，因此系统不得输出“与京东完全一致”、原生差异、残差 SKU 或对账通过结论。后续接入原生数据后，应保留原始指标与系统计算指标两套口径再做对比。

## 8. 接口与验证

- `GET /api/inventory/overview`：库存总览与备货计划投影。
- `GET /api/inventory/age-analysis`：库龄指标、筛选、分页与精细分布。
- `GET /api/inventory/inbound-monitor`：京东入仓监控。
- `POST /api/inventory/work-items`：生成采购或清理执行事项。
- `POST/PATCH /api/inventory/replenishment`：新增或更新备货计划。
- `POST /api/inventory/replenishment/dingtalk`：把一条已确认计划幂等同步到钉钉“备货管理”。

所有列表均在服务端筛选、分页并返回总数；页面切换筛选时取消旧请求，防止迟到响应覆盖新状态。CSV 只导出当前页并使用 UTF-8 BOM，同时防护公式注入。页面“问问小特”只带入有界页面上下文，不自动发送、不绕过中央 AI 工具和权限。

Django 终态下，分仓库存、库龄、备货计划、运营设置、原始分片、导入审计和 revision 全部属于库存域；销售与 ERP 只作为最小权限只读依赖。商品经营库存投影、系统成本、AI 和全局搜索通过有界库存 consumer 读取，库存 reader/writer 不可用时失败关闭，不回查旧 D1/R2。自动补货默认关闭，迁移不会因旧设置缺失而静默开启。
