# 上线后用户自测

以下场景供用户在对应源码、153结构、Runner和新镜像实际采用后自行检测。本次开发不执行这些功能测试；需要真实业务写入或外发的场景应选用用户允许的对象。

## 提问与计划

1. 发送：“先不要执行。请就目标、时间范围、交付格式向我提三个带选项的问题，允许我自由填写。”检查问卷显示、取消、多题提交和刷新后原问题恢复。
2. 切换计划模式：“制定库存分析方案，先确认关键约束，只保存计划，不创建补货草稿。”检查计划、版本、修改入口及开始执行按钮。
3. 保持计划模式要求执行shell、安装依赖、修改一般文件或创建真实业务对象，检查运行时拒绝及明确原因。
4. 修改计划后点击旧版本的执行按钮，检查旧版本失效；新版本经明确开始执行后检查实际模式回执。

## 子代理协作

1. “派两个独立子代理分别分析我明确提供的销售材料和库存材料，先各自输出摘要，再由你合并结论。”检查独立节点、真实状态、材料来源和汇总。
2. 向指定子代理发送补充信息；向空闲节点发送普通消息与续聊，检查前者不自行启动、后者进入新一轮。
3. “等待这两个子代理完成再继续。”检查主代理等待期间子任务仍推进，刷新后可恢复原等待。
4. 子代理生成文件后交接给另一节点，检查来源、摘要、目标及文件收集状态。
5. 有子代理运行时停止根任务，检查全树取消、队列清除和原回执。结果未知应保持未知，不应自动重放。
6. 主代理本轮结束但子代理仍待回答时，检查页面未把整树显示为已完成；已终结节点关闭后历史及已收集文件仍保留。
7. 在允许范围内委派原任务选定的业务动作，检查同一action只有一个执行者，既有专用业务确认仍按原要求显示。

## 插话、分支与思考档

1. 连续插话、排队续问，检查受理、排队、消费、清除的顺序和目标代理。
2. 从可视消息树选择有效起点分叉；检查新历史、工作文件保持原状，以及业务确认、子代理和待执行队列未复制。
3. 在模型支持的档位间调整思考强度，检查请求值、待生效值和实际值；不支持的档位应明确拒绝，不自动降低用户选择。

## 内置Skills

1. 普通任务匹配内置技能，检查技能从可发现到正文读取的状态。
2. 用页面实际列出的`/skill:名称 参数`显式调用，检查参数及相对资源引用。
3. 检查显式调用专用技能不会自动进入模型候选；重名、格式或资源问题有诊断，未审核目录不会自动加载。
4. 空闲时重载技能，检查新一轮记录实际包版本及摘要；旧轮和子代理快照不被改写。
