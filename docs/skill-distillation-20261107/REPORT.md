# 从已完成 Pi 任务提炼 Skill 草稿

## 服务端入口

先读取原有 `GET /api/ai/pi/operations/{id}/skill-candidates` 取得 reportVersionDigest，再调用同一路径下的 `POST /distill`。提交 clientRequestId 和 reportVersionDigest。同一次意图重用同一请求标识。成功返回 201 和候选 item，可交由已有审核流程处理。

服务端从所属任务取最终公开回答、来源、产物元数据和已确认的用户修正，并按原操作的模型版本、店铺和工具目录构造一次结构化模型调用。模型端点需要声明 JSON Schema 能力。返回正文通过本地结构、工具与证据检查后只存为草稿。报告版本在调用期间改变时返回冲突，超过模型上下文时返回错误。对未知派发使用已有 Pi 派发账本阻止换标识重复发送，已成功的相同请求可取回同一候选。

## 核对范围

独立工作树以 77382b5f 为基线。接口测试使用内存 SQLite 与模拟供应商，覆盖成功落草稿、幂等重放、供应商结果未知、报告在途变化、无效正文、归属及过期的版本。Worker 定向检查覆盖路径、写方法、同源要求和 Django writer 转发。未使用真实供应商或业务数据。调用方界面属于后续任务。本项不增加数据库迁移。

独立反审发现本地凭据解密失败会被误记为派发未知。修正后，发送前的凭据失败有明确终态，修复凭据后可用新标识重试。内存测试 6 项通过，凭据用例经过实际 provider 代码并断言网络调用为零。
