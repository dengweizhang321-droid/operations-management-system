## 明天（11-01）11:10 之后要查的事

丽力的调度是 11:10，今天已过，**明天首次自然执行**。

### 必查五项

1. **丽力那一轮的 execution**：status、mode、起止时间、耗时。重点看是否 `success`，失败则读失败码
2. **与亿玖的资源争用**：亿玖 11:00、丽力 11:10，间隔仅 10 分钟。查丽力有没有卡在 `等待前序流程释放 helper` 节点、等了多久
3. **兜底是否真的工作**：如果丽力失败，错误工作流应接住 → 等 60 分钟 → 从专用 webhook 创建新 execution → 发钉钉提醒。**这条链 10-31 刚接通，从未被真实失败验证过**
4. **数据有没有真的入库**：查 `netshop` 域该店的新批次与日期覆盖，不只看 n8n 说成功
5. **缺口规模**：丽力久未发布，策略是"近七日查缺、逐日补齐"，所以明天会补最近七天而非只跑昨天。实际跑了几天、花多长时间

### 为什么第 5 项影响后续决策

如果丽力一轮花了很久（七天 × 商品日 + 推广日），而窗口只有 11:10–11:50 这 40 分钟容纳五条，**五条叠加会撑爆窗口**。所以在看到丽力的实际耗时之前，不要发其余四条。

全部只读：读 n8n SQLite 元数据（`mode=ro` + `query_only=ON`）+ 查业务域批次。不手动触发、不改任何东西。
