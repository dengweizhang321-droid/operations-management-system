## 载体与时间

选择独立 Windows 计划任务，每日上海时间 **20:17**。它独立于 n8n，可在 n8n 没有启动时报告巡检失败；无需为每日一次读取维持另一常驻服务，也避免 n8n 自检自身失效时无人调用。沿用本项目普通用户 Interactive / Limited，不增加系统服务或第四种调度器。

20:17 晚于当前最晚 13:10 日调度七小时零七分，避开整点/半点。巡检仍按原判据检查启用、发布、周期 execution 是否存在及错误流异常；此时间安排不把 execution 存在误称业务成功或所有任务已结束。未来日调度变化需重新核对巡检时间。

## 防重事实

现有发送台账对同一个 key 的 `sending/sent/unknown` 防止重复投递，但 v2 key 包含 anchorEpoch：检查1/2随日周期变化，检查3随小时变化。仅指定固定 `--state-root` **不能**兑现“同一持续异常跨日不重复发送”。本次须在同一状态根记录持续异常观察，沿用原发送台账和未知不重发规则；不能仅在文档声称已经防重。

## 本次实现

- `tools/n8n_schedule_watch.py --continuous-incidents` 是可选入口，默认CLI继续原周期防重。连续模式只在相同state-root中维护 `schedule-watch-incidents.json` 的观察索引，保存异常首次观察锚点；发送成功/发送未知仍完全由原脚本台账判断。未修改发送脚本、身份核验或发送实现。
- 同一workflow/code/原因集合连续出现时保持锚点；完整检查覆盖该对象且异常消失后才结束。目录移除、检查失败、状态损坏、锁忙不能充当恢复。新事件锚点单调分配，避免同秒恢复/新原因导致原sender key碰撞。观察索引在发送之前原子落盘；整个执行观察、读改写及发送处于专用锁中，避免旧健康快照清掉较新异常。
- `identity_failed` 按原规则可在后续周期再次核验；`sending/unknown` 保留且不重发，下一天仍退出2。原台账不扫描、不删除、不迁移；首次从旧周期模式切换时，不能保证之前已经发过的同一问题也自动归并。这是一次采用边界，应在F1恢复及首次启用时核对，而非清空旧账本。
- Windows任务由 `tools/n8n-schedule-watch-task.ps1 -Action Plan` 生成原生XML，运行已有venv的 `pythonw.exe` 加 `n8n_schedule_watch_task.py --execute`。不用额外常驻服务或新发送器。生成器只支持Plan/Status，不包含注册、启用、启动动作；计划要求本机 `China Standard Time`，触发边界含 `+08:00`，Interactive/Limited、IgnoreNew、StartWhenAvailable、25分钟总预算，不配失败自动重试。
- wrapper保存 `schedule-watch-latest.json` 的attemptId/startedAt/finishedAt/status/exitCode。本次开始立即覆盖旧成功为running；超时、非JSON、不可用均记unconfirmed并退出2，不自动重跑。手工预览只写 `schedule-watch-preview.json`，不覆盖正式心跳，不创建事件或发送台账。

## 告警链路断了如何发现

运行 `powershell -NoProfile -File tools/n8n-schedule-watch-task.ps1 -Action Status`，检查任务LastTaskResult、当前attemptStatus、finishedAt与overdue。0是巡检无异常；1表示发现异常且投递已完成或被原已送达台账抑制；2表示巡检/状态/投递未确认。`running`且无finishedAt、超过26小时或未安装均需处理，不能展示为成功。原sender的unknown不会被一天后的新观察洗成sent。

这是本地故障可见性，**钉钉失效时不能保证远程主动通知本人**。必须由值守查看任务结果/本地状态；F1身份恢复是正常告警采用的前置。没有用户登录时Interactive任务不能运行，26小时过期能在下次人工查看时发现；不宣称无人登录也有远程报警。首次采用后若任务非0，先查该状态，严禁为“确认送达”盲目再次执行。
