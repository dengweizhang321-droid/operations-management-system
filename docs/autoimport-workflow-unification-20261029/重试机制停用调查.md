## 这对"告警用哪一版"的直接影响

**我上一轮说"以线上 PowerShell 版为骨架"的建议站不住了。**

线上那版用 `executeCommand`，而 `executeCommand` 恰好是当前环境下**这三条工作流都激活不了**的共同特征。即使把它纳入仓库、改好收件人，只要这个节点类型在运行时不可用，工作流就激活不了——**告警一行都发不出来**。

仓库 HTTP 版用 `httpRequest`，而 `httpRequest` 在那 9 条激活的工作流里广泛使用，**是确定可用的**。

所以方向反转：

| | 线上 PowerShell 版 | 仓库 HTTP 版 |
| --- | --- | --- |
| 工程质量 | 高（418 行、dws 范式、BOM、特殊字符处理、回执校验） | 低（拼字符串 POST） |
| 收件人 | **发群**（违反 `workflow-dingtalk-notifications.md:37` 要求的本人单聊） | 由 `channelId` 决定，也未实现动态唯一核验 |
| 节点类型 | `executeCommand` ← **很可能是激活失败的原因** | `httpRequest` ← **确定可用** |
| 版本管理 | 脚本在 `D:\teruisi-ops\`，**不在仓库** | 在仓库 |

**结论：应当用 `httpRequest` 这条路**，但要把 PowerShell 版那些好东西（dws 动态唯一核验、脱敏、回执校验）搬到它里面，并按规范改成发本人单聊。

这等于"保留线上版的工程质量，换掉它的节点类型与收件人"。
