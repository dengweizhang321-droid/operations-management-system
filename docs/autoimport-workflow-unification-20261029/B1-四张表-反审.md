## 五、几处值得记下的设计判断（我认为都对）

1. **`parent_attempt` 用 `on_delete=PROTECT`** —— 禁止删除仍被子尝试引用的父记录。恢复链的历史不能因为删一条就断
2. **`logical_run` 用 `CASCADE`** —— 删逻辑运行会清掉其尝试与模块结果，这是一致的
3. **逻辑运行唯一约束只对 `schedule`/`backfill` 生效** —— manual 与 recovery 天然允许同一计划日多次，这个条件约束是对的
4. **`automation_attempt_native_execution_uq`（排除空串）** —— 防止同一 n8n execution 被误挂到两条逻辑运行下。这条我专门验过
5. **模块定义字段挂 `validate_code_token` 正则校验器** —— 在模型层（不只 API 层）拒绝协议头、路径分隔符、shell 元字符。符合 REPORT.md §4.1 那条"数据库里的可编辑值不得携带任意脚本、URL 或文件路径"
