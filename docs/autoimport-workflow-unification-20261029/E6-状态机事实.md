## 当前状态机

`tools/tmall-isolated-helper.ts:94` 的 `slots` 与 `retired` 均为内存集合。slot key 为天猫 storeKey 或其他工作流共用的 `legacy`。不同天猫店可在此协调层并存；legacy 与所有已有 slot 互斥（:124）。因此“helper 所有店一律全局单锁”并非该层当前源码的精确描述；Chromium 自身其他锁仍独立生效。

- 无 slot → claim 同步登记 `starting` → spawn ready 后 `running`。
- 相同 owner 可复用；不同 execution 等待；维护期新 owner 等待或拒绝；相同 execution 改计划锚点拒绝。
- spawn Promise 拒绝（:141）→ `quarantined/failed`。
- worker 发 finished 只设置 `clean` 并 terminate，**实际 Worker.exit** 才回调 finish。exit(clean=true) → retired + 删除；exit(clean=false)（:136）→ retired + `quarantined/failed`。error、30秒启动超时、非清洁退出均可沿此进入 quarantine。
- claim(:107) 发现本 key 的 active 已 quarantine → `rejected`，reason=`helper_slot_cleanup_requires_manual_action`。HTTP claim 层(:421) 将 rejected 转成409，`error` 携带该 reason。
- 无 TTL、无通用 release/force-unlock 端点。**但有域人工闭合协调清理**：`:159` 的 closeCoordinator（Jackyun 与客服 JD 分别实例化）允许无匹配 slot，或唯一匹配 slot 已 exited 且 inFlight=0；两者均须无其他 slot、无并行闭合，才可 freeze。存在 slot 时置 closing，complete 再删除 slot/登记 retired，未完成 release 恢复旧状态。零 slot 路径仍须业务侧完整核验，不等于任意 quarantine 通用释放接口。
- 进程重启会丢失 Map/retired，但不能把这一事实当成安全重启或无业务残留的证明。

旧《helper锁残留处置手册》“没有任何释放方式，只能重启”应限缩为“没有通用强制解锁接口”；同时它把 n8n 终态当作残留判据，不足以替代 Worker/browser/未知提交核查。本轮未改手册、未重启。
