## 带入的能力

**B1 运行投影四张表（迁移 `0009_automation_projection_b1`）**
- `AutomationModule` / `AutomationLogicalRun` / `AutomationAttempt` / `AutomationModuleResult`
- 三轴状态是三个独立字段：`execution_state` / `business_state` / `delivery_state`
- 模块结果身份五维：`logical_run` + `module_key` + `subject_key` + `dataset` + `date_range`
- 恢复链用 `parent_attempt` 自引用（`PROTECT`），可表达一条逻辑运行下的多次尝试
- 复用 `WorkflowWriteRequestReceipt` 与 `WorkflowDataRevision`，未另造机制
- 业务证据只读引用 `NetshopImportBatch`，**未给业务域加字段或写入路径**

**B2 闸①②③**
- 闸① 后端自己查业务域批次与覆盖，**不读任何脚本自述字段**
- 双向成立：抓假绿判 `failed`；无缺口/未到期/内容重复判 `no_new_needed` 并带原批次证据
- 闸② 三轴互不顶替；闸③ 与 `no_new_needed` 走不同判据、不互串

**B3 读接口**
- 四级下钻，服务端过滤分页（`base.count()` + SQL `LIMIT`/`OFFSET`），返回 `total`/`returned`/`truncated`
- `completeness` 字段显式标 `truncated_do_not_infer_absence`，防止截断集合被误读为完整
- 异常筛选：待人工 / 持续阻塞 / 无法核实
- 补齐 `get_automation_run_status` 的三个 workflowKey（schema 与 handler **两处**）
