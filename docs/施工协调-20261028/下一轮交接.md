## 四、必须知道的工程事实（今天新踩的坑）

### `package.json` 是受保护发布入口，改它会死锁

它在 `workerGuardEntrypointPaths` 里，sha256 被已上线 release 的 guard 收据（`audit/legacy-worker-guard-receipt.json`）钉死。发布链在**任何工作之前**就校验「活仓库的受保护入口 == 已上线收据里的哈希」：

- `tools/worker-local-release-rotation.mjs:543` 的 `verifyInstalledGuardEntrypoints()`，`protectedSourceRoot` 即 `D:\运营管理系统` 本身（`worker-local-release.mjs:133` 写死）
- `control/tools/publish-main.mjs:113` 在 `withRotationLock` 内第一步就 `verifyInstalledHead: true`，`:126` 又是 `prepareOnline: true`

**两条路径（`--prepare-only` 与停站发布）在这道门上行为完全相同。** 我误判过一次「停站能解」——依据是 rotation 里那段「混合状态只允许在停站态存在」的注释，但停站路径实际也硬编码 `verifyInstalledHead: true`。**应读 publish-main.mjs，不要从别处的注释推断。**

### 发布是两段式，「裸跑即发布」的说法是错的

上一轮交接写「两者只差一个 `--prepare-only` 参数，裸跑即发布」。实测：`发布main.bat` 发现没有现成制品会**停下并提示先跑准备**，不会自己打包。正确顺序是 `准备main.bat` → `发布main.bat`。

### 嵌套 worktree 会污染 lint 门禁

`.claude/worktrees/` 下有 4 个嵌套 git worktree（约 5598 个 ts/tsx），git 自动排除但 **eslint 会走进去扫**。合并后门禁一度报 **532 errors**，查清后 476 个来自那里，真实项目文件正好 **56 个 = 基线**。

**差点就把 `BASELINE_ERRORS` 从 56 调到 532，那会把门禁彻底废掉。** CI 克隆的仓库没有这些嵌套 worktree，所以 CI 不受影响。按 CI 口径核算要加 `--ignore-pattern ".claude/**"`。

### 子代理写不了报告类 md

三个子代理都被工具层拦住，无法写 `docs/**/REPORT.md`，只能把报告内容作为文本返回。**派工时要预期这点**，由主会话代为落盘。

### release 保留清理挂在备份成功之后

`django-postgres-maintenance.ps1:2418`：`if ($MaintenanceRequest.Action -ceq 'Backup' ...)` 才跑清理。所以备份坏了 → 清理不跑 → release 堆积。这是 25 GB 问题的成因之一（另一个是 257 上限）。

### 发布源快照包含未跟踪文件

`listGitSourceFiles`（`worker-local-release.mjs:926`）用 `git ls-files --cached --others --exclude-standard`，**包含未跟踪文件**。排除前缀只有 `dist/ node_modules/ .git/ .runtime/ outputs/ tmp/`。今天发现自己写的临时诊断脚本会被打进生产源快照，已清理。**发布前务必检查非 docs 的未跟踪文件。**

今天并行 3 条子代理 + 多个后台任务，`manage.py test ai_assistant` 全量跑了 **100 分钟**（1822 tests / 142 failures / 232 errors，**属既有基线**，已在 clean main 复跑确认）。两个子代理同时跑 Django 测试会抢同一个 PG 测试库，表现为卡住不动。**跑全量 Django 测试时不要并行。**
