# 京东推广深度诊断六天首版候选

## 范围与验收口径

用户确认首份报告固定为京东「志高商用设备旗舰店」2026-09-20 至 2026-09-25，前等长周期建议为 2026-09-14 至 2026-09-19。09-26 不在首报范围内。首版复用现有网店推广页面、权限、京准通导入事实和 XLSX 写入能力，生成总览、趋势、计划、跟单 SKU、关键词、搜索词、词货、人工行动建议和来源口径九张表。HTML 可离线搜索、排序、分页和导出当前表 CSV；XLSX 的表格数值与 HTML 来源一致，并带标题行、冻结行和筛选。

首版的分析类型为 `deterministic_review_draft`：规则生成待人工复核的判断，不调用付费模型、不自动修改投放，也不把京准通归因额称为店铺净销售、利润或增量效果。原五阶段候选中的影子库、五 Agent 签发链和额外协议不作为首版依赖。

## 系统接线

- Django 只读 `GET /api/netshop/promotion-diagnostic`：管理员、京东平台、精确店铺复合键和最多 31 天范围；按原始 `NetshopRow` 的已导入推广事实汇总，逐日对平 `NetshopPromotionShopDaily`；缺日、缺指标、未知分组身份明确返回；超行数/分组数/响应大小拒绝截断。
- Next 同名 API：沿用应用身份与店铺授权，严格过滤查询参数并代理到 Django reader。
- 推广分析页：仅在目标店铺及 1—7 日已选周期显示“生成当前周期诊断”；前等长周期单独读取，缺失或修订变化时环比留空；切换范围会中止旧请求。来源不完整时只展示缺口，不开放完整报告导出。
- 报告生成器：HTML 和 XLSX 使用同一组表格单元格；来源修订、日期覆盖和五种分组总行数校验失败时拒绝生成。计划按稳定 ID 汇总，未知计划不参加集中度排名；无关键词/搜索词的投放单列，不当作词效果。

## 实际来源的只读预核对

本机 2026-09-20 至 25 六份京准通 CSV 为 UTF-8 BOM，共 61,311 行；每份仅含一个目标业务日。六天合计花费 9,363.22 元、展现 100,460、点击 4,591、平台归因订单行 134、归因总订单金额 105,118.75 元；与当前系统推广页四舍五入后展示一致。计划 ID/名称、跟单 SKU ID 和五项核心指标在这六份文件中均有值；关键词仅在 22.22% 来源行出现，其空值行占花费约 83.27%，搜索词在 84.99% 来源行出现。六天可识别计划 27 个、跟单 SKU 581 个、有值关键词 124 个、有值搜索词 7,790 个、关键词×SKU 分组连空值桶共 1,560 个。CSV 所在账号目录与权威店铺身份的映射来自 `config/jd-store-accounts.json`，CSV 自身不提供店铺 ID；CSV 内原始账户昵称与登记账号标签不同，可能是子账号，正式采用前需对照导入批次和店铺映射核实。

前等长周期六份 CSV 的同五项合计为花费 9,809.37 元、展现 97,094、点击 4,291、归因订单行 151、归因总订单金额 121,753.05 元。两期核心表头相同；前期另有一个不可用的乱码扩展表头，不参与比较。上述是本机文件预核对，不替代正式 Django 来源批次与逐日聚合的在线对账。

## 明确边界与剩余验收

首版暂无同店同日期的品类/SPU 映射、市场、店铺净销售、B 端销售及同比的已验收关联；报告会显示缺口，不补造这些结论。归因窗口成熟度与因果效果未独立核实。61,311 行本地内存读侧演练核得 2.57 MB JSON、五项总额与分组数对平，但不含生产数据库 I/O。当前候选尚未部署到正式服务，尚未用生产 reader 实测查询耗时、完整来源批次和浏览器中的 HTML/XLSX 下载。后续生产采用需先完成这些读侧验收与受控发布；不因此触发新的下载、导入、迁移或付费模型调用。

定向验证：Django 接口权限、店铺隔离、缺日、聚合差异、响应超限；TS 报告六天日期、环比、HTML 脚本语法、XLSX 同值、匿名计划防误判；现有 XLSX 读取用例回归；`vinext build`。生产环境未改变。
