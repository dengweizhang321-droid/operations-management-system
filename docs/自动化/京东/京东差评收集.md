# 京东差评收集

本手册用于按店铺销售排行抽取商品，批量导出京东商家后台商品评价，筛查差评并采集商家回复，输出 HTML 与 Excel 报告。

- 技能：[`.agents/skills/jd-negative-review-collection/SKILL.md`](../../../.agents/skills/jd-negative-review-collection/SKILL.md)
- 店铺注册表：[`config/jd-store-accounts.json`](../../../config/jd-store-accounts.json)
- 评价管理页：<https://wares-jdm.jd.com/ware/goodsAppraise>
- 京麦工作台：<https://shop.jd.com/jdm/home>
- 输出目录：`outputs/`

## 适用范围

**适用**：按店铺销售 Top-N 商品，核查每商品最新 N 条评价是否存在差评；采集差评的商家回复；生成可交付的 HTML/Excel 报告；复盘差评回复时效。

**不适用**：回复评价、投诉申诉、修改评价、批量邀评等写操作。本流程全程只读，任何写操作必须由人工在后台完成。

## 数据口径

| 项目 | 默认口径 | 说明 |
| --- | --- | --- |
| 销售排行 | 近 30 天 SKU 交易额前 20 | 商智商品明细导入数据，按 `transactionAmountCents` 倒序 |
| 数据截止 | 接口返回 `dataCutoffDate` | 报告中必须注明 |
| 评价时间窗 | 近 12 个月 | 可调整；导出单次上限 3000 条 |
| 每商品条数 | 最新 20 条（时间倒序） | 不足 20 条时全取 |
| 差评判定 | 评价等级 `1`（1 星） | 等级 `2` 为中评，`3` 为好评 |
| 回复采集 | `getCommentById` 的 `replies` | 过滤 `nickName` 以 `jd_` 开头的用户追问 |

## 前置条件

1. 运营系统 reader 服务可访问：`http://127.0.0.1:8021`（netshop）。
2. 项目根目录 `.dev.vars` 中存在 `TERUISI_DJANGO_INTERNAL_SECRET`（≥32 字节），用于构造内部签名。
3. 四家店的 Chromium profile 均可正常登录京东商家后台；登录失效时先人工处理，不重试、不换凭据。
4. 每个店铺的 profile、CDP 端口、下载目录唯一（见注册表）。

## 操作步骤

### 1. 取销售前 N 商品

调用 netshop 只读接口：

```text
GET http://127.0.0.1:8021/api/netshop/product-performance
  ?dimension=sku
  &view=full
  &platform=京东
  &outlet=京东\u001f<店铺名>
  &startDate=2026-09-28
  &endDate=2026-10-28
  &pageSize=100
  &page=1
```

- 请求需带内部身份签名头：`X-Teruisi-Principal`、`X-Teruisi-Timestamp`、`X-Teruisi-Request-Id`、`X-Teruisi-Content-SHA256`、`X-Teruisi-Signature`，签名规则见 `backend/sales/auth.py`：对 `v1\n时间戳\n请求ID\nGET\n路径\n查询串\n空正文摘要\nprincipal` 做 HMAC-SHA256。
- `outlet` 的平台与店铺用 `\x1f`（%1F）分隔。
- `pageSize` 上限 100，按 `pagination.total` 翻页。
- 按 `transactionAmountCents` 本地倒序取前 N，保留 `skuId`、`productName`、`transactionAmount`、`transactionQuantity`。

### 2. 启动店铺浏览器（严格串行）

四个 profile 共用同一个 `userDataDir`，**同一时间只能有一个实例**；后启动的实例会直接退出且不监听 CDP 端口。

```powershell
$exe = "$env:LOCALAPPDATA\Chromium\Application\chrome.exe"
$udd = "$env:LOCALAPPDATA\Chromium\User Data"
Start-Process -FilePath $exe -ArgumentList @(
  "--remote-debugging-port=9224",
  "--user-data-dir=`"$udd`"",
  "--profile-directory=`"Default`"",
  "--no-first-run", "--no-default-browser-check", "--disable-session-crashed-bubble",
  "https://wares-jdm.jd.com/ware/goodsAppraise"
)
```

- 参数值含空格时必须加引号，否则 `Profile 2` 会被拆成两个参数。
- 启动后轮询 `http://127.0.0.1:<port>/json/version`，直到返回 `Browser`。
- 切换店铺前先结束上一实例整个进程树：

```powershell
Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" |
  Where-Object { $_.CommandLine -match "remote-debugging-port=9224" } |
  ForEach-Object { taskkill /PID $_.ProcessId /T /F }
```

### 3. 核对店铺身份

1. 打开 `https://shop.jd.com/jdm/home`，读页头店铺名（`.shop-menu-accountV1__right-account-top-name`）。
2. 点店铺名展开“店铺信息”，确认“店铺ID”与注册表一致。
3. 若页头显示同账号的其他店铺，访问 `https://shop.jd.com/jdm/shop-switch` 切换后再核对。
4. 名称或 ID 任一不一致 → **中止该店采集**，不写入数据。

### 4. 导出商品评价

在 `https://wares-jdm.jd.com/ware/goodsAppraise`：

1. 点“重置”清空筛选，等待列表刷新。
2. 在第二个“多个用‘,’或空格分隔，支持Excel粘贴”输入框（SKU 编码，第一个是订单编号）粘贴该店 Top-N 的 SKU，逗号分隔。
3. 设置评价时间范围：开始/结束输入框填入 `YYYY-MM-DD HH:mm:ss`，每次输入后按 Enter，再按 Escape 收起日期面板。
4. 点“查询”，等待“共 N 条”，记录 N。
5. 点“导出查询评价”，抽屉内确认字段全选，点“导出”。
6. 切到“导出记录”页签，反复点“刷新”，直到第一行状态为“已完成”，记录“成功：N”是否与查询数一致。
7. 点**第一行**的“下载”，用 Playwright `download` 事件保存到 `tmp/reviews-<storeKey>.csv`。

导出文件为 UTF-8 BOM 的 CSV，10 列：评价等级、评价星级、评价用户 pin、评价内容、评价时间、订单编号、商品名称、SKU 编号、商品规格、投诉状态。**不含商家回复**。

注意事项：

- 单次导出上限 3000 条；超出时必须缩小日期窗或拆分 SKU 批次，不能只导一部分当全量。
- 导出记录按时间倒序排列，点最后一行会拿到历史任务的文件。
- 页面默认时间窗是“最近 30 天”，不修改日期会漏历史评价。
- 导出弹窗里的“评价时间”可用于反向核对页面筛选是否真正生效。

### 5. 采集商家回复

CSV 没有回复字段，需逐条到页面取：

1. 在评价管理页把“商家回复”筛为“已回复”，可先确认该店有哪些评价被回复。
2. 对每条差评，重置筛选 → 填该 SKU → 日期设为差评当天（`00:00:00`~`23:59:59`）→ 查询。
3. 在结果行内找“查看回复详情”，点击后捕获 `dsm.seller.product.comment.pc.CommentResourceService.getCommentById` 响应。
4. 从 `data.replies[]` 取 `content`、`replyDate`、`nickName`、`status`。

判定与过滤：

- `nickName` 以 `jd_` 开头的是**用户追问**，不能当商家回复；只保留店铺名的回复。
- `isVenderReply` 字段不可靠（实测存在 `false` 但确有商家回复的情况），以 `replies` 数组为准。
- 一条差评可能有多次商家回复，按 `replyDate` 取最后一条作为主回复，其余保留在明细中。
- 弹窗会遮挡页面，下一次点击前必须点 `.jd-drawer__close-btn` 关闭抽屉，否则会报“subtree intercepts pointer events”。

### 6. 判定与汇总

1. 用 `csv` 模块解析（UTF-8 BOM；评价内容含换行，禁止按行切分）。
2. 按 `SKU编号`（去掉前导单引号）分组，按 `评价时间` 倒序取最新 20 条。
3. 评价等级 `1` 记差评，`2` 记中评；与星级交叉校验（等级 1 对应 1 星）。
4. 与销售 Top-N 匹配，输出每商品：评价总数、检查条数、差评数、中评数、结论。
5. 评价总数为 0 的商品单列“无评价、无法判断”，不能计入“无差评”。

### 7. 生成报告

**HTML**（`outputs/京东4店销售前20商品评价差评排查-<日期>.html`）：

- KPI：店铺数、商品数、检查条数、差评数、有差评商品数、已回复/未回复、无评价商品数。
- 每店逐商品表：销售额、销量、评价总数、检查条数、差评/中评、结论、商品链接。
- 差评卡片：完整原文、时间、SKU、商品链接、商家回复（含回复时间与回复店铺），未回复显式标注。
- 每店折叠区：该店全部检查评价原文，差评条目下带商家回复。
- 口径与局限说明。

**Excel**（同名 `.xlsx`），5 个工作表：

| 工作表 | 内容 |
| --- | --- |
| 汇总 | 每店 Top-N 商品统计与链接，差评行标红 |
| 评价明细 | 每条检查评价：店铺、SKU、时间、等级、星级、内容、投诉状态、是否差评 |
| 差评清单 | 差评原文 + 回复状态、商家回复、回复时间、回复店铺 |
| 无评价商品 | 查不到评价的 SKU 及原因 |
| 全部导出评价 | 当期导出的全部原始评价，便于二次筛选 |

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 第二个 profile 启动即退出 | 共用 `userDataDir` 的单实例限制 | 结束上一实例进程树后再启动 |
| 页头店铺与注册表不符 | 同账号多店铺，停留在另一家 | `shop-switch` 切换后按店铺 ID 复核 |
| 下载到的条数与查询数不符 | 点了历史任务的“下载” | 固定点导出记录第一行 |
| 日期筛选没生效 | 输入后未确认 | 每次输入按 Enter，再用弹窗“评价时间”复核 |
| 点击被遮挡 | 回复详情抽屉未关闭 | 先点 `.jd-drawer__close-btn` |
| 某个 SKU 查不到评价 | 该 SKU 无评价或评价在其他店铺链接 | 记为“无评价”，不推断 |
| 导出超过 3000 条 | 超出单次上限 | 缩小时间窗或拆分批次 |

## 验收清单

- [ ] 每店已按页头店铺名 + 店铺 ID 核对，且与注册表一致。
- [ ] 每店导出条数与页面“共 N 条”、导出记录“成功：N”三者一致。
- [ ] 检查评价数 = Σ min(商品评价总数, 20)。
- [ ] 差评条数 = 各店 CSV 中评价等级 `1` 且落在最新 20 条内的条数。
- [ ] 无评价商品数已单独统计，未混入“无差评”。
- [ ] 每条差评都有回复状态；有回复的包含回复内容、时间、回复店铺。
- [ ] 报告注明数据截止日、销售口径、评价时间窗与每商品条数。
