# 工作流本机时区

工作流调度、初始计划的今天/昨天/自然周、今天执行状态和通知使用运行机器本地时区。这里的“本地”指执行 n8n、helper 和 Django 的主机，不是打开页面的浏览器所在地区。

## 新计划和历史记录

- n8n 定义不再固定 `settings.timezone`；启动脚本在清除继承 `TZ` 的独立 Node 查询中，通过 ICU 读取主机 IANA 时区，再设置实例 `GENERIC_TIMEZONE` 和 `TZ`。
- 日期先从真实瞬间按本机日历取出，再执行纯日期加减；UTC 仍用于事件时间、租约、重试等待和去重锚点。日历日不保证等于 24 小时。
- 新计划需要跨阶段校验采集日时，把日期策略及时区随计划、证据和校验传递。旧计划缺新标记继续原约定，不重新解释旧创建时间、批次、下载任务或恢复许可，也不因时区变化漏掉旧 active。
- 平台报表无时区时间、平台任务创建时间的 `+08:00` 仍按来源平台解释；经营查询、财务/BI 期间及手工历史导入不在这次调度变更内。
- 执行状态 API 返回运行机当日两端的 UTC 边界，以及带运行机当地 offset 的显示时间；网页用这些边界判断是否仍属今天，避免浏览器时区不同导致误报。
- C3 检查普通本地每日 cron。遇到无法与 n8n 明确对应的夏令时不存在/重复时刻，报告 `inspection_unavailable`，不猜测漏跑或自动补跑。

## 采用与机器时区变更

源码合并不等于线上采用。现有 n8n 工作流仍可能带固定时区，现役 n8n 启动器也可能绑定旧版本。获授权采用时须同时核对：应用/helper 的对应代码、原 Limited n8n 启动链、已发布工作流是否去掉固定时区、目录和巡检版本。保留原工作流 ID、业务节点、cron 时分、所有者和旧执行记录；不得用重新导入重置历史。

若须重载 n8n，另取得本次授权，按既有受控流程确认零 `new/running/waiting`、helper 空闲及原进程身份后，仅停止原服务、等待 5678 释放、从原 Limited 任务恢复。不得因“改成本地时间”直接停止业务或重放失败任务。

修改操作系统时区后，不能假定已运行进程自动重读时区。需分别按相关受控入口获授权重载 n8n、helper、Django 等受影响常驻进程；仅重载 n8n 不代表其他进程已一致，也不授权停止它们。旧计划继续其冻结时区，新计划使用新主机时区。读取不到有效时区时启动失败，不回落纽约或上海。

n8n 的工作流设置优先于实例设置；删除固定字段必须同时显式配置实例时区，不能依赖其默认值。[n8n 官方说明](https://github.com/n8n-io/n8n-docs/blob/main/docs/deploy/host-n8n/configure-n8n/basic-configuration/configuration-examples/set-the-timezone.md)
