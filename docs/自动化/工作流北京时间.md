# 工作流北京时间

所有工作流的调度、计划的今天/昨天/自然周、今天执行状态和通知统一使用固定北京时间（`Asia/Shanghai`），与执行 n8n、helper、Django 的主机时区无关，也与打开页面的浏览器所在地区无关。

> 2026-11-03 的“工作流跟随主机本地时区”决定已被用户于 2026-11-21 明确取代。取代原因：主机改为美国太平洋时间后，n8n 实例按 `Asia/Shanghai` 触发而 helper 按主机日历取昨天，导致京准通计划拒绝（“不晚于本地昨天”）、客服 30 天窗口滞后一天、`n8n_schedule_watch` 误报 15 个工作流缺失。

## 规则

- n8n 工作流定义恢复 `settings.timezone: "Asia/Shanghai"`；`tools/start-n8n-service.ps1` 将实例 `GENERIC_TIMEZONE` 与 `TZ` 固定为 `Asia/Shanghai`，不再解析主机时区。
- cron 时分保持不变（例如京准通 10:40/10:50、客服 09:05/09:25/09:45/10:05），现在固定按北京时间解释。
- `lib/imports/local-time.ts` 的 `workflowTimeZone()` 返回常量 `Asia/Shanghai`；日期先从真实瞬间按该时区取日历日，再做纯日期加减，UTC 仍用于事件时间、租约、重试等待和去重锚点。
- Python 侧用 `ZoneInfo("Asia/Shanghai")` 取业务日；执行状态 API 返回北京时间当日两端的 UTC 边界和带 `+08:00` 的显示时间，`timezone` 为 `Asia/Shanghai`。
- 导入链路目录的 `timezone` 由生成器从工作流定义投影，现为 `Asia/Shanghai`。
- 平台报表无时区时间、平台任务创建时间的 `+08:00` 仍按来源平台解释；经营查询、财务/BI 期间及手工历史导入口径不变。

## 已冻结计划与旧证据

新计划与采集继续冻结 `datePolicy: host_local_calendar_v1` 和 `timeZone`，值现为 `Asia/Shanghai`。旧计划若冻结了其他 IANA 时区，继续沿用其冻结时区；缺少新标记的更旧计划继续沿用上海约定。证据哈希、恢复许可和 active 检查不因本变更重新解释。后端与吉客云 run-contract 接受任意有效 IANA 时区。

## 采用

源码合并不等于线上采用。现役 n8n 定义已带 `Asia/Shanghai`；启动器更新需另行获授权后按受控流程重载。主机时区变更后已运行的 helper、Django 进程需分别受控重载才能读取新代码。重载 n8n 前须确认零 `new/running/waiting`、helper 空闲及原进程身份，不得因本变更停止业务或重放失败任务。

n8n 的工作流设置优先于实例设置。[n8n 官方说明](https://github.com/n8n-io/n8n-docs/blob/main/docs/deploy/host-n8n/configure-n8n/basic-configuration/configuration-examples/set-the-timezone.md)
