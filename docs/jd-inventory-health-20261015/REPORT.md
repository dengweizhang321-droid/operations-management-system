# 京东库存健康筛选与库存周转设置

2026-10-15。用户要求新增库存健康状态、可点击筛选TAB及缺货/补货内容，并明确库存周转周期是目标库存覆盖天数，沿用现有补货周期，默认30天。本轮不新增第二个周期或销量窗口，不增加schema/migration，继续以HTML交付。

## 实现

库存健康独立于消息提醒配置，仓项按固定30日来源与目标周期判断：缺货、补货、待补充依据、在途可覆盖、低周转、无销量、健康。已知零可用且有需求的缺货不被在途盖住；正可用但目标缺口大于0为补货；在途足以覆盖目标时显示在途可覆盖；零需求单独显示无销量。只有区分健康与低周转时才需要现有库存周转依据，严格大于180天为低周转。缺少某项必要来源或日期时保留未知，不依赖ERP映射是否确认或消息推送是否开启。

汇总保留成员分布及最坏状态，已知缺货/补货不被其他未知或富余仓抹去。补货标记根据任一已知仓的正建议量，不限于商品主健康态，因此商品可以同时进入缺货与补货清单。两类TAB计数允许重叠，未知总建议仍为“—”，可展开查看有依据的仓项。

8个TAB（全部及7态）按当前事业部、仓库、搜索的完整商品集合计数。先完整分组，再筛选商品并保留该商品全部仓项，最后分页；筛后`total/summary/totals/columns`均属于完整筛选范围，不以当前页代替全范围。互斥主状态分布与TAB匹配数分别返回。`healthState`在公开Worker、Django和离线适配层精确约束，未知/空/重复参数拒绝，原角色与事业部范围保持。

页内显示醒目的“当前30天 / 库存周转设置”。正式页面仍由管理员按原CAS接口修改`replenishmentCycleDays`，1–3650天；与补货公式共用目标覆盖周期。HTML可直接打开同一Dialog，在7/14/30/45/60/90天中应用本地试算，仅调用内存回调，不提交保存。旧外置试算条移除，避免两个设置入口。消息提醒阈值/命中仓项明确标为提醒，与库存健康分开。
