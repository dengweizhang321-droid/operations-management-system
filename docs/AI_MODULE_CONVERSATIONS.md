# AI 板块独立会话：首批实现与后续工作

更新：2026-09-09。**首批功能已合入 main 并在本机正式上线。** 采用源码提交 `5a688f6ac3bdb3fa20a093117ede4be5c99ec67b`，包含最初候选和发布复审发现的备份探针兼容修复；开发基线为 `c84afdd9558efe40a9b5a8e69206c12d9d79290e`。不能据此声称四个阶段已全部完成。

## 本批交付

- 全部 12 个导航板块共用一套聊天组件，每个板块拥有独立的个人会话列表。页头“问当前页面”打开当前板块侧栏，AI 助理页显示同一会话控制器的完整视图。
- 关闭、重新打开或切换板块保留本页已挂载的会话和输入状态；重新加载页面按服务器最近打开时间恢复已保存会话和历史消息。未发送草稿不写入浏览器存储，也不承诺跨刷新恢复。
- 销售、财务、网店、市场及主数据、库存、商品、客服和运营事务的主要页面注册实际查询日期、店铺、商品、状态等选择。库存快照、财务月份、任务到期日、新品周报等各自保留原业务时间口径。
- 商品详情只带详情自身的货品代码及日期；不混入列表筛选。客服上下文只包含结构化筛选或内部会话 ID，不复制客户搜索词、客户别名和对话正文。敏感搜索、筛选空交集或体积超限时明确阻止携带不完整上下文；用户可调整筛选，或明确移除页面上下文后普通提问。
- 页面条件只作为低信任参考；模型仍须通过现有中央只读工具查询数据。工具不支持某项筛选时必须说明，不能把扩大范围后的结果声称为当前页面数据。当前上下文未包含列表排序、所有展示粒度或计算器假设值。
- 发出消息后仍使用原来的幂等回执。切换板块与关闭侧栏不会自动重发；刷新恢复只执行 GET，确认原会话及精确回复已落库后才清理恢复指针。结果未确认时提示继续刷新或另开话题。

## 技术契约

前端入口为 `app/ai-workspace-host.tsx`、`app/ai-page-context-provider.tsx` 与 `app/ai-assistant-view.tsx`。每个访问过的板块仅挂载一个控制器，隐藏时保留实例；用户、角色或范围限制状态改变时重建宿主。会话选择、模型切换、删除与发送互斥，避免异步响应覆盖其他会话。历史消息按会话 ID 校验后展示。

新后端逻辑位于 `backend/ai_assistant/conversation_workspace.py` 和 `page_context.py`，公开 Worker 保持薄转发。

| 接口 | 新增契约 |
| --- | --- |
| `GET /api/ai/conversations` | 可指定 `workspaceModule`；按本人及板块筛选，按最近打开排序。 |
| `PATCH /api/ai/conversations` | `action=activate`，携带 `conversationId`、`workspaceModule`，保存本人的历史会话选择。 |
| `POST /api/ai/chat` | 板块会话携带 `workspaceModule`；`pageContext` 省略表示继承，显式 null 表示清空，二者参与不同的幂等摘要。 |
| `GET /api/ai/chat` | 支持板块会话读回及有界 `messageId` 精确消息读回。 |
| `GET /api/ai/chat?clientRequestId=…&workspaceModule=…` | 仅按当前本人查回执，返回状态、会话 ID、回复 ID；重新核验数据范围，不调用模型。 |

新增 `ai_conversation_workspaces` 一对一附表，保存模块、最近上下文和最近打开时间。新表不进入历史 `HISTORICAL_MODELS`，旧 39 张表的迁移摘要契约保持不变；旧无附表的本人会话归入 AI 助理板块。新板块会话始终按本人隔离，管理员也不通过普通对话接口读取其他人的新板块会话。

迁移 `0006_conversation_workspaces` 包含模块白名单、上下文大小约束、写权 epoch 检查及不可变模块/会话身份触发器。AI 表清单增为 46 张；reader/writer 授权、readiness、备份表清单、历史 snapshot 排除和系统数据集排除同步更新。备份校验按迁移记录要求新表，同时继续接受升级前完整的 45 表备份；缺表、无迁移却出现新表或孤立的 0006 证据均拒绝。新表不是通用数据集，不新增跨域写权限、第二事实源、D1 或 R2 路径。

客户端上下文筛选最多 20 个值/字段、160 字符/值、UTF-8 3000 字节；请求完整上下文仍受现有 4000 字节上限约束。浏览器 sessionStorage 只保留按账号和板块隔离的请求 ID，不保存问题正文、业务数据或凭据。

## 验证与限制

### 查询额度与紧凑字体修复（2026-09-09 已上线）

库存板块的一次真实失败先出现 `get_inventory_page_data(view=guangdong, warehouses=[广东仓])` 参数拒绝，随后去掉仓库参数查询成功，再一轮模型返回后出现“工具未获授权或调用超限”。旧实现把工具不可见和单工具次数超限混为 403，并中断整个回答；拒绝发生在执行桥之前，旧审计没有记录最后一次被拒工具名，因此不能仅凭旧日志逐条证明该调用的名称。

修复从中央目录派生每轮剩余次数说明，用尽的工具不再提供给模型，并在原轮数内保留最后一轮生成回答。已注册工具的超限请求不执行，单独记录 `tool_limit_exceeded` 审计，再把拒绝结果交给模型基于已有数据说明结论与缺口；未授权工具仍以 `access_denied` 拒绝。原始目录及签名摘要、真实 principal、单工具/总调用/模型轮数/时长和付费派发上限均保持。审计失败仍关闭，未知模型结果不自动重发。模型若在最后一轮仍坚持调用工具，会有界失败，不能保证任意提问都可完整分析。

库存总览明确优先用库存健康工具，广东入仓清单不能冒充全仓概览。广东工具接受省略仓库或与固定广东仓一致的冗余参数，其他仓库或混合范围在读服务前拒绝，不忽略不兼容筛选。聊天侧栏正文及输入框从 16px 调到 14px，标题 14px、按钮及上下文 12px。

### 已知限制和运维记录

- 合成跨站 POST 正确返回 403 后，紧随的合法 POST 曾得到 Wrangler 本机代理的 503 非 JSON 响应，文案为 restarted mid-request；监听 PID 未改变，不能据该文案认定进程重启。外层 Connection: close 未解决问题。GET 确认原请求未被接收后，使用同一请求号成功完成清空上下文，并通过回执和消息读回确认结果。本次没有修改相关同源检查、代理入口或依赖版本，也不宣称此代理边界已修复。
- 部分外层 PowerShell 原生命令在受控子脚本完成后仍等待输出句柄。只有在核实成功结果、精确 PID/创建时间/命令身份及没有直接子进程后，才结束了本次临时外层命令；随后单独完成角色授权和启动回查。没有因此终止 PostgreSQL 或 Worker 服务。
- 自动审批拒绝了隔离镜像数据及关联基线目录的清理，仅返回 `blocked by policy`。镜像进程已停止，镜像目录保留当前用户/SYSTEM 的私有 ACL；本次 worktree 与分支保留以避免绕过该拒绝，源码已合入 main。正式备份与不可变发布证据继续保留。
