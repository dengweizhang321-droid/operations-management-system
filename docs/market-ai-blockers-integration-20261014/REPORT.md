## 三个阻断及额外实测协议缺口

1. **领取查询和回写锁竞争**：先通过已有 job/status 索引一次读取有界在途身份，再排除候选，避免相关反连接重复扫描整批。历史超容量状态直接阻止领取，不截断后继续派发。成功回写只锁所属 job/item，失败仍使用模型锁协调限流或配置暂停。获锁后及真正返回前重新采样时间、检查协调租约、单图处理/回写预算和维护 gate；预算不足整笔回滚。保留原子领取、A优先/B补位、共享12并发、双租约、防重复和排空。
2. **OpenCode会话协议**：精确 Go chat endpoint 使用服务端 `jobId` 派生稳定SHA会话，真实客户端名 `xiaote-market/1.0`。探针独立命名，缺任务身份拒绝发送；其他供应商保持原适配。请求复用现有公共 body builder。
3. **思考与输出预算不匹配**：仅市场视觉标注请求显式关闭思考，A仍一次调用取得分类与价格、最多600 tokens；B固定已有分类只抽价、最多320 tokens。已保存模型配置、全局AI参数、正式字典和业务Prompt没有改变。

本次首候选真实12次全部收到完整HTTP400：供应商明确表示 `response_format` 类型不可用，旧错误匹配漏掉 `unavailable now`。原失败记录保留，不能用旧报告14次成功证明本次成功。补修对**精确 OpenCode Go + deepseek-v4.1-flash**直接选择 `json_object`，临时技术输出指令附完整schema，本地仍严格拒绝字段、枚举、价格类型、null、置信度或图片身份无效。其他渠道仍用原schema模式，没有失败后自动fallback/重发。依据为[DeepSeek官方JSON模式](https://api-docs.deepseek.com/guides/json_mode/)。

同时检查正常 `finish_reason`、空正文、截断、拒绝和错误信封；HTTP200不等于识别成功。明确协议/配置错误为 `model_configuration`，暂停同模型新派发，保留在途有效结果可回写；单图错误与限流各自分类。POST后未完整确认结果为既有 `inference_result_unknown`，隔离并暂停，不降低历史失败次数。成功/失败均保存原五个timing字段、尝试身份、锁等待及安全诊断；服务端只持久化固定文案和已知安全token，尚未列入的细节可能被丢弃。存储重试复用原结果和固定请求身份，不重新调用模型。
