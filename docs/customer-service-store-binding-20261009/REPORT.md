# 客服手动导入四店身份统一

任务于2026-10-08开始，2026-10-09完成开发验证。用户要求按已说明的方案调整；生产上线仍需对本次版本单独确认。

## 问题与修复

自动客服流程已有四家规范店铺，但客服分析与数据导入共用的手动卡片只写了两个历史短名称；分片导入还按“志高厨电”客服前缀覆盖用户选择，导致同一业务的身份规则不一致。

- 卡片复用 `lib/jd/customer-service-stores.ts` 四店配置，以店铺键作为选项值，显示完整店名；初始为“请选择店铺”，未选择不能提交。
- 上传请求携带 `storeKey + shopName`。multipart与分片完成入口都在解析文件/领取上传前校验这对身份，缺键、未知键、矛盾名称均422；multipart重复身份字段也拒绝。
- 移除以客服名称推断店铺的逻辑；自动流程原有四店明确绑定及来源页头核验保持。手动文件没有可独立验证的店铺编号时，所选店铺是操作者声明，不能把声明校验称作从文件证明店铺身份。
- 上传指纹加入店铺键，上传时锁定店铺和文件选择、拒绝拖入新文件；卡片展示本次目标店铺。
- 分片完成回执保留店铺键，重放时复验同键、规范批次名称和文件对；旧无键回执或其他店铺回执409，要求重新上传，不重写既有业务记录。
- 上方名为“导入目标店铺”，下方名为“会话店铺筛选”。两个页面继续复用同一卡片；统计筛选仍来自真实入库名称，历史短名不隐藏、不自动归并。

没有新增数据库迁移、修改生产数据、触发n8n任务、下载或重新导入京东文件。无需为了修复选项重复采集四店数据。

## 历史名称只读核验

运营MCP不可用，使用用户指定本机 `http://127.0.0.1:3000/api/customer-service/conversations` 的只读替代来源，中文筛选使用URL编码。2026-10-08上海23:49核验：真实枚举为四家规范全名和“志高商用设备”。数据最新咨询时间为2026-10-07 23:38:07。

旧“志高商用设备”有29,018条，咨询日期2026-01-01至2026-07-20；“志高厨电”为0条。本月四店共3,299条，与截图一致。名称及现有选项不足以独立证明旧记录均属于规范设备店，不据此批量改名。后续归并需核对原文件、批次和店铺证据并确认精确影响范围。
