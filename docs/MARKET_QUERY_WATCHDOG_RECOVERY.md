## 候选变化

- 浏览器榜单及预取使用 `includeFilterOptions=false`，筛选由独立接口读取；默认 API 仍保留完整旧返回契约。列表排序、销售投影、价格带、身份、分页和权限不变。
- 全局选项按六个独立标量字段计数，使用已有类目/品牌索引和 `market.0005_filter_facet_indexes` 新增的 scope、维度、经营模式、细分类目四个窄索引。避免六字段联合索引对合法长文本的 B-tree 元组长度限制。
- 聚合局部事务关闭并行工作者，恢复原会话参数；每条 SQL 不提高原 statement_timeout，整个六字段扫描另限 20 秒，所有结果成功后才返回完整统计。无截断、估算或失败后降级成零。
- 每个 reader 进程只保留一份不超过 2 MiB、最多 5 分钟的筛选缓存；键包含数据库、角色、authority epoch 和市场 revision，仍在鉴权后读取，计算后复验 revision。事务内不共享缓存，避免未提交数据泄露；锁有界等待 5 秒，错误只共享 2 秒退避而不保留 SQL/异常详情，旧结果不能冒充新版本。
- 数据库取消查询返回明确的筛选/榜单超时文案。只读请求记录固定类型的成功/失败、耗时和时间；不记录请求文本、用户身份、商品、金额或凭据。只有新请求结果可以覆盖旧请求结果。
- 本机市场 reader 的只读健康入口返回上述被动观测。看门狗最多每 5 分钟读取一次，不主动执行榜单扫描；连续两次业务失败仅告警，不强制重启在线服务。未收到近期结果时显示 unknown，不声称业务正常；已打开故障只有筛选与榜单的新成功观测才能闭合，不能因过期清零。
- 钉钉预发送身份失败保存固定原因及阶段，每事件最多 3 次、间隔至少 15 分钟复核。发送前继续持久预留；sending、unknown、sent 不重发，不改变本人单聊身份约束，也不改变旧 Django outbox/其他业务通知目标。
- supervisor 的 Start 改为重定向文件并只等待直接启动进程，避免后代持有输出通道阻塞 native pipeline；保留直接退出码、原互斥和运行意图摘要。启动未结束时写入 pending 状态，不终止业务进程树、不发起第二次启动。隔离测试覆盖后代继续存活、直接进程返回非零；没有终止正式服务来复现故障。

## 验证与限制

候选验证记录见 `evidence/market-query-watchdog-candidate-20260920.json`。包含真实隔离 PostgreSQL 的市场回归、读写角色正负权限、迁移检查，浏览器合成接口交互，以及 PowerShell 原生父子进程测试。正式四个新索引尚未建立，生产首次/重复查询耗时和旧 supervisor 恢复效果必须在受控采用后验收。

缓存是进程内的，不跨多个独立 reader 进程；进程重启或 revision 变化会触发冷读取。看门狗采用被动业务观测，不是无人使用时执行完整榜单的主动可用性保证。旧通知日志缺乏原因，不能追溯出当时具体是哪一步失败。

## 受控采用与回滚

1. 用户明确批准正式维护后，核验当前工作流和在途任务；按原机制停派、排空，进入持久维护。不要为验收补跑业务或发送测试通知。
2. 通过原备份入口生成备份并在独立环境恢复验证，按既有要求归档 E 盘。保存当前源码、Worker/Django manifest、迁移清单和精确进程证据。
3. 使用原唯一控制器停启、不可变发布和 Django 部署入口；执行 `market.0005_filter_facet_indexes`。不得原地修改 runtime 或降低版本摘要门禁。旧卡住 supervisor 只能在维护边界内核验精确身份后处理，不能按 PID 数字盲目终止。
4. 重新安装看门狗前暂停其下一次调度，等待当前轮自然完成，保留原任务身份、触发器及 GUI 启动器。原规则保护人工 Stop/维护，禁止强制重启健康进程。
5. 退出维护后核验 12 组件、exact_release、启动绑定、Django supervisor 新鲜健康记录、两轮独立看门狗成功。正式页面验证冷/热筛选、榜单、翻页和不同日期；查询超时保护不变，完整结果口径不变。生产导入后的失效由下一次原计划或经授权导入验收，不为测试新建业务导入。
6. 若采用失败，保持维护标记并通过原发布回滚入口恢复前驱，复验数据/迁移状态。四个纯索引不改业务行；若需回退迁移，使用同一维护下的受控 migration 回退，不手改生产表。
