## 一、单行拖垮全批（你选的第2件）—— 已经做完了，但发现一个遗漏

### 已完成的部分

小数数量四舍五入+记警告，不再整批拒绝。这部分不需要再做。

### 查遗漏时发现的新问题：库龄表有同类风险，但表现形式不同

我按你的提示去查了库龄、销售、组合装三张表，发现**库龄表（`inventory_age`）
的"可用库存"字段**（`lib/imports/erp-reference.ts:181-188`）用的是另一套
完全独立的代码，和库存表不是同一个函数：

```
function integer(value, field, label, row, errors) {
  const parsed = parseNumber(value);
  if (parsed === null || !Number.isSafeInteger(Math.trunc(parsed))) {
    errors.push({...});  // 阻断
    return 0;
  }
  return Math.trunc(parsed);  // 静默截断，无告警
}
```

| 对比 | 库存表（已修） | 库龄表（现状） |
|---|---|---|
| 遇到小数 | 四舍五入 + 记警告 | **静默截断，没有任何告警** |
| 会不会整批拒绝 | 不会（已修） | 不会（本来就不会，因为`Math.trunc`总能转成整数） |
| 问题性质 | 曾经会拖垮整批（已解决） | **数据被悄悄改写，没人知道** |

举例：库龄表某行可用库存是 `180.7`，会被静默变成 `180`，不会报错、不会告警，
你翻遍导入结果也看不出这一行被改过。

**这不会导致"卡死"（不属于你选的第1件要解决的问题），但违反"保留原值并告警，
不静默改写"的原则**——这是今天查库存问题时顺手带出来的一个新发现，你选的
第2件原本没打算含这个，所以列出来让你决定要不要一起处理。

### 建议（要你决定要不要做）

| 选项 | 做法 | 工作量 |
|---|---|---|
| **A（推荐）** | 把库龄表的`integer()`改成和库存表一样的"四舍五入+告警" | 小，和今天做的是同一套逻辑，可以直接复用 |
| B | 这次不动，只记录问题 | 零工作量，但隐患留着 |

### 3-3：会不会再产生新的死循环

今天的吉客云闭合解决的是"已经卡住的那一次"。但这套"失败留下记录、下次被拦"的
机制本身没有改——如果客服4店重新打开、下次又失败了，还是会卡住，只是这次失败
原因可能是别的（比如验证码）。**错开定时能降低失败率，但不能保证零失败。**

所以第4步里你提过的"按数据齐不齐判断成功，缺哪天补哪天"这件事，加上"连续失败
自动清理零产物清单"这类机制，才是让这套系统长期不再需要人工介入清理的根本办法。
这次先把眼前卡住的清掉、把明显能避免的互挤解决，长效机制可以放进下一轮。

## 四点五、"失败分两类处理"现在是什么状态（你中途追问的）

**已经做了一半，没做的是最关键的那部分。**

重新读了那条重试流的真实代码（它上次修改是10-13，今天没人动过），确认：

| 你要的 | 现状 |
|---|---|
| 要人工的失败**不重试** | **已经做到**。用一长串正则（验证码/风控/凭据失效/店铺身份不符/…）
把这类失败识别出来，直接跳过不重试，14天实测正确拦下21次 |
| 要人工的失败**立即钉钉提醒你** | **没有**。被跳过的失败什么通知都不发，只是安静地不重试，
你不主动去查就不知道它卡住了 |
| 临时性失败重试，**最多3次** | **没有上限**，是每小时无限重试，直到原计划被核验完成为止 |

也就是说：筛选"能不能重试"这件事做得很好（今天实测证明有效），但筛选之后的
**通知**和**重试封顶**两件事都没做。这正好补齐了你第1件（死循环）要解决的
一半——客服4店每天卡住，本质上就是"要人工处理的失败，没人及时知道"。

### 建议并入第5步方案

| # | 要加的能力 | 工作量 |
|---|---|---|
| 1 | 在"跳过不重试"的分支上接一个钉钉通知（翻译成人话："哪个店、什么时候、
    要你做什么"），而不是现在这样直接 `continue` 什么都不说 | 中（要写消息模板，
    复用现有的 `n8n-manual-action-dingtalk-alert` 机制） |
| 2 | 给临时性重试加一个计数上限（比如3次），超过之后也转成钉钉提醒，
    而不是无限期每小时重试下去 | 小（在"读取原执行计划时间"节点里加个计数判断） |

这两条**不冲突**于你选的前三件事，可以一起做，也可以单独放到下一轮（第4步代码
改动那批）。
