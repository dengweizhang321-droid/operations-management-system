关于"回执4个而批次5个"：销售那张表固定没有 `djangoReceipt`，12次**全部一样**，
是稳定模式不是故障。（10-23 那次明细：货品8583行、库存24474行、库龄5961行、
销售39331行、组合装4458行，全部 `status=completed`。）

### 10-24 那次失败：货品表没有被写入，无需担心脏数据

这是审查要求查清的关键问题（"货品可能已落库、整轮是否原子回滚"）。核实结果：

| 对比项 | 10-23 成功（11006） | 10-24 失败（11007） |
|---|---|---|
| 最后执行节点 | E·独立核验五类精确批次 | **D·统一导入运营管理系统** |
| D 节点状态 | success | **error** |
| D 节点返回 | phase=imported | **完全没有 json 输出** |
| 五表批次号 | 5个齐全 | **一个都没有** |
| E 节点 | 执行并通过 | **根本没执行** |

**结论：没有任何一张表落库，不存在脏数据，也不需要回滚。**

原因定位到源码：`lib/inventory/django-import-service.ts:160`，
这是**库存 Excel 解析阶段**的拒绝（`parseInventoryStockXlsx` 返回了行级错误），
发生在任何写库动作之前。

和第1步查到的另一条历史失败对上了：吉客云曾报
`第 7075 行仓库类型映射与受控配置不一致` —— 同一个解析校验、同一类问题。
**可能的方向**：库存文件里出现了受控配置里没有的仓库，或者仓库类型映射没跟上。
具体是哪一行哪个仓库，执行数据里没留，需要下次复现或查 helper 日志才能确定。
