# 京东物流四源接入与 POP / C仓监控

2026-10-15。状态：独立开发候选；尚未生产部署、结构迁移或启用正式采集。预览使用隔离合成数据，不代表真实经营数据已导入。

## 本轮实现

- 复用实际 React 外壳、库存管理导航、原有 tab、表格及 Dialog。京东入仓监控增加 ERP京东仓 / 京东POP / C仓监控，保留原 ERP 页面。
- POP 提供库存流水、调拨核对、商品对照、导入批次及账号设置；商品对照和人工 ERP 状态独立保存，源替换不会按 Excel 行号错配。人工“已调拨”不表示 ERP 已建单或过账。
- C仓参考用户朋友的单品布局：商品行、来源省市或独立仓列、展开完整分仓明细，7/30日销量窗口、服务端商品分页与当前筛选范围合计。不复制参考系统的商品图、经营数据或固定七城映射。
- 数据导入页增加四类来源；公开 Worker API 复用现有身份校验和 Django HMAC，实际导入、查询、人工维护及账号版本控制已在隔离环境联调。
- Django 库存域新增八张物流专表及结构迁移0012/0013（0013为独立提醒投递账本）；原库存、库龄和销售事实不被本模块覆盖。事业部事实只存一份，不按关联店铺重复累计。读写最小权限、健康检查和归档表识别同步更新。
- n8n 增加独立京东物流工作流模板和自动化页面入口，通过原 helper 共用执行资源互斥。claim/A计划/B采集导入/C精确回查/D缺货提醒/release分阶段留证，未知提交不盲目重放。
- 所有新账号的采集、四源能力、监控和推送默认关闭；物流开关独立于既有京东商品/商智采集开关。

## 来源与口径

| 来源 | 核验到的下载路径 | 完整新样本纯解析结果 |
| --- | --- | --- |
| 仓库库存流水 | 页面导出RPC直接返回原始CSV附件 | 122行 |
| 店铺商品 | 启用商品全集，导出任务ID及下载RPC绑定原CSV | 906行 |
| C仓实时库存明细 | 实际采集时点、完整查询，下载中心唯一新任务 | 427行 |
| C仓库存快照明细/分仓 | T-1单日、全部仓库，下载中心唯一新任务 | 900行 |

四类新文件均完成 TypeScript 解析与 Python 标准化/内容哈希一致核对；原用户两簿的流水2084、实时121、快照112行也完整核对。没有把真实样本写入业务数据库。文件原SHA与规范化内容SHA分别留证，不转换CSV后冒充原文件。

流水的实物与可用库存六个分量分别保存；负变动不等于负结存。事件顺序和源序号不充当身份，重复事件的出现次数参与内容哈希。实时文件无日期时必须提供实际采集时刻，缺事业部列的人工文件仅记录显式声明，不能宣称源文件已证明归属。

C仓`jd_sku`与流水/店铺商品`department_product`命名空间分开，没有可靠关联时不猜店铺归属。店铺商品导出没有平台列，保持未知；缺事业部商品编码的关系仍独立保留，不拿平台SKU或ESG补造事业部编码。仅有仓名时显式采用name身份，不伪造官方仓库代码。额外业务列和来源省市原文完整参与指纹。

本页销量采用京东销售出库件数，不是店铺成交订单数。系统周转为现货÷30日销量×30；可售天数为可用÷所选7/30日销量×窗口；补货后库存为可用＋采购在途＋调拨在途。每个指标只依赖自身所需字段，未知值不转零。汇总先合计数量及需求再计算天数，不平均分仓天数；不同比较时期的合计天数保持未知。京东原生“30天周转”只展示来源单仓原值，不对其求和或平均。

账号可设置缺货阈值，用户已确认按“可用库存可售天数”。缺货依据单独保存为`stockoutAvailableDays30d=可用库存÷30日销售出库件数×30`，固定30日，不随显示窗口改变；系统现有库存周转及京东原生周转继续分列。可用0、现有5、调拨在途5、30日销售出库2时判缺货，现有库存周转75天不能掩盖可售断货；缺现有量不阻这一判断，缺可用量或日期/销量依据仍未知。

用户已指定独立钉钉“测试群聊”；以原受控库存profile只读核实唯一群及“志高助手”status=1、明确robotCode，没有发送消息。通知接口由服务端生成当前合格风险，不接受任意消息或目标；全局渠道配置和账号采集/监控/推送开关均允许后才能发送。独立账本在外发前持久化sending，精确成功回执后记录sent；sending/unknown不得换run或原文件摘要绕过重发。未知库存覆盖单独披露，不让一个零销量商品抹去其他已知缺货风险。通知规则v2及其算法版本进入配置摘要，A阶段冻结的通知语义可复核。

`config/jd-logistics-notifications.json`固定该群与机器人，默认`enabled=false`。`notificationAvailable=false`在本轮表示渠道未启用；页面风险提示、推送开关和工作流完成均不能冒充发送成功。实际外发仅在正式采用及启用授权后发生，本轮消息发送0。
