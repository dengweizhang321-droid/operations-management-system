# 完整独立看门狗包采用方案

本方案替代旧 `watchdog-stability-20261011` 的安装准备结论。安装文件、只读诊断消费、恢复通知和事务恢复已纳入同一个固定候选，不再将核心原因字段留到未知时间的后端发布。

## 精确范围

候选：`E:/codex-artifacts/watchdog-recovery-install-safe-20261011/candidate/tools/`。九个文件包括看门狗、实际配对 helper、新安装库、原无控制台 launcher 源及验证过的原 launcher 二进制、只读控制器/后端包装、核心诊断覆盖和原来源绑定。全部字节与安装计划见 [DELIVERY.json](DELIVERY.json)。

只读包装复用实际已安装库中的 Status；其 CLI 拒绝 Start/Stop 等操作，不修改已安装 Django/Worker 的应用或源码。仅更新独立监控版本目录、安装清单和原监控计划任务的入口引用及启用状态。保留原每分钟与登录触发，以及原自动恢复权限和限次。自然监控仍可能按原规则尝试恢复或发送原本人单聊告警，新版另增加一次恢复事实通知。没有手工 TestNotification、故障注入、应用发布、数据库操作或 n8n 改动。

## 执行

1. 用户对本次精确候选和上述效果确认后，再只读回验九个源文件、原四来源、旧安装/launcher/helper、现有任务 XML 与绑定。候选或前驱漂移重新生成方案；不改旧批准哈希。
2. 等原任务自然结束，调用固定候选 `-Action Install -Execute -ApprovedInstallPlanId <本回执 planId>`。拿不到共用互斥、状态忙、归属不明或当前健康无法验证时零生产修改退出。Install 自身仍在锁内复核所有前驱，不依赖外层等待消除竞争。
3. 安装在固定版本目录放置并核验完整包，保存原安装清单和任务定义于受保护恢复事务目录，再切换清单与任务引用。原旧文件不覆盖；通知和故障流水不回退。按原自然触发开始检查，避免在持有检查互斥时人工发起子检查。
4. 回读新清单、任务入口与原触发器、九个文件摘要和原业务系统状态。确认两轮**已完成**的自然看门狗检查，诊断使用 readonly_driver、核心细化字段出现、所有组件和 HTTP 检查通过，健康期间没有无缘由通知。不能仅凭 LastTaskResult=0 或快照起始时间作完成判断。

## 失败恢复

文件暂存阶段失败不改变旧引用。引用切换阶段失败，原事务尝试恢复精确旧任务 XML 和清单原字节，重新回读；通知 sending/unknown/sent 和恢复记录保持，防止重放。若出现无法证明属于本次的新任务或新清单，不强行接管，不删除证据，保留 rollback_unconfirmed 并人工处理。

恢复材料位于实际 `operations-watchdog/install-transactions/<事务>/`。Unused 版本载荷保留供核验，不为本轮释放空间删除。恢复监控不等于业务数据库恢复，不执行服务树终止或重放未决 Start。

## 完成与观察

安装成功和两轮健康仅证明本次采用验收，不证明间歇故障永久解决。采用后观察一个完整业务日的故障/恢复记录、超时率、各阶段耗时和用户通知；用首个和最近失败分析具体慢点。前驱源码更新后包装退回原状态引擎并标明需刷新，重新准备该次诊断绑定，不用旧健康当新版本就绪。
