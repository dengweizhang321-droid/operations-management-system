## 结论分类与处理顺序

严重度按实证影响：P1 为较易造成范围判断错误的高频问题；P2 为明确阻断、重复等待、操作误触或局部结果不完整；P3 为低频提示/布局负担。本轮没有证据支持 P0 数据破坏或全系统不可用。

| 1 | B01 自定义日期取消不回退 | 已复现 bug / P1 | 公共统计周期，跨模块 | 小至中；拆已应用/草稿状态，风险在 URL/前进后退兼容 |

- 11 个模块入口附带 1024×768 几何/截图（AI 通用标题失败时未做窄窗）；新增正常只读链覆盖 BI 刷新/平台、均衡总览翻页、商品第二页/详情、客服开关详情、运营协作弹窗/Escape、市场趋势、自动化切栏目、导入选择来源、设置草稿焦点。具体失败和补验见覆盖表及 [补充操作](evidence/final-operations-summary.json)。
- 隔离预览为同一受审真实 Home、真实业务组件和全局 CSS，3781/18781/18782、独立合成 SQLite；无生产配置回退。基础样本 6 货品、180 销售、6 库存/库龄；客服/备份/search 的故障组使用明确合成 DTO。普通慢网、乱序/取消、503、IME/229、身份和日期清快照均只在隔离环境验证。
- 复用原工具：确认 5 组、布局 9 组全部通过；公共组件/分区定向测试 18/18，无跳过。另有导航、意图预加载、商品详情定向日志见 [验证说明](VALIDATION.md)。没有重演全库测试或生产构建。
- CPU/内存仅一次同窗快照与短时浏览器趋势。22:22:39 CPU 28%，物理内存约 31.7 GiB、空闲约 2.17 GiB；不能据此归因 n8n/AI/备份争用。12 次合成切页末尾无在途 API，切走后 2.5 秒零新增 API；JS heap 有回落，不能证明长期无泄漏或有泄漏。

## 明确未验证的范围

1. SQL EXPLAIN/ANALYZE、逐请求 SQL 数量/锁等待、Django 队列/序列化/CPU 和 Worker 内部分段没有探针，均为未知；API 时延不等于 SQL 或页面绘制。
2. 没有清生产缓存，因此没有受控冷服务端缓存样本；首次新浏览器、重复进入和刷新已分开，不能把它们都叫冷/热缓存。没有生产 P95、压力或并发吞吐结论。
3. 原生 Windows 输入法候选窗、真实浏览器 125%/150% 缩放、其他浏览器、触摸设备未验。CDP composition 和合成 229 只证明浏览器事件分支。窄窗口并不替代真实缩放。
4. 未在生产改变账号、权限、来源版本或注入失败；真实多账号/店铺权限差异未逐项验证。现有组件测试中的身份对象切换不能冒真实账号验收。
5. 写操作、真实导入、备份创建/恢复、自动化执行、AI接受后的真实模型任务/外发均未触发；AI后台持续语义主要为静态审查，未做真实长任务隐藏页签实验。内嵌 n8n 编辑器内部功能也未全面验收。
6. 大日期范围市场 full、所有网店新旧视图/来源组合、所有详情/弹窗/导出、单店与多店完整指标等价性未穷举。商品真实共696项/每页50、客服共3299条/每页30只表示抽样规模，不是完整业务审计。
7. AI子chunk故障注入被 Vite 开发错误遮罩挡住了重试按钮，本轮没有完成其局部重试验证；不把开发遮罩当生产故障。原始失败和首次脚本未处理 Promise 的错误均保留。

本轮未实施任何修复。建议按表中 1–5 先组成可独立验收的小修复批次，再处理有性能证据的锁与重复读取；BI/网店/市场重计算须先补阶段探针和固定范围等价性证据，由用户决定实施范围。
