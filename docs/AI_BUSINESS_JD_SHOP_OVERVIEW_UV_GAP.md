# 京东店铺交易概况与 UV 来源接线前置核对

2026-09-24 静态核对结论：现有 `jd_shop_overview → trade_overview` 只是通用导入入口，尚不足以形成可信的「店铺×日期总览」或「所选区间去重 UV」经营分析来源。本核对仅查源码、模型、测试及操作说明，没有读取真实客户行、调用平台、启动导入或修改服务。不能据此断言现有平台文件没有这些字段；需要先核平台字段定义与脱敏表头。

## 已证实的系统边界

- `backend/netshop/import_service.py` 枚举 `jd_shop_overview/trade_overview`，但 `_normalize_row` 仅对 `sku_daily/spu_daily/promotion_daily` 强制 `businessDate`；`validate_import_payload` 也只对这三个数据集强制目标起止日和逐日覆盖。交易概况允许空日期、缺日或同日多行。
- `lib/netshop/normalized-import.ts` 的 `firstDate` 从模糊日期/时间列取首个可解析值，失败后还会扫描所有单元格。`metricsFromRow` 接受所有数值字段，没有交易概况专用表头、单位、非加总指标与 UV 定义。JD 通用导入校验完整日期覆盖的分支没有 `jd_shop_overview`。
- 通用非商品日 `sourceRowKey` 由来源、店铺、**文件哈希、源行号、行内容哈希**组成（`lib/netshop/batch-identity.ts`）；`NetshopRow` 只对该键唯一，未对 `source/dataset/platform/shop/business_date` 唯一。Django writer 的 `_scope_shape` 在每行有日期时按区间替换，任一行无日期则改为全范围替换；同批次的同店同日多行仍可并存，跨文件重叠按区间覆盖却不按日识别值冲突，无法仅凭现有键区分合法拆分、重复与冲突。
- `NetshopRow.visitors` 是非空整数投影，缺源字段时 `_metric_integer` 默认写 **0**，且只认 `visitors/商品访客数`，没有核验的店铺访客或区间去重 UV 字段。`metrics_json/raw_json` 可保存原文，但“已保存原文”不等于拥有可信的 typed 指标。
- `backend/netshop/analysis.py` 的 `SOURCES` 只含推广、SKU、SPU、B2B 与主数据，未含交易概况；`analysis_options.py` 也仅从该目录列身份。现有商品 `productDayVisitors` 是商品×日访客累计，不是店铺日去重 UV；任意店铺日 UV 的多日相加也不是完整区间去重 UV。
- 本地操作说明 `自动导入-京东自营网店数据(1).md` 要求交易概况“分天下载”，但该说明没有给出可机器核验的表头、UV 定义、唯一日身份与区间去重定义；不能代替源合同。

## 可执行接线顺序与验收门槛

1. **确定平台原始口径。** 从获授权的平台导出规范或脱敏表头，固定交易概况报表名称/版本、日期列、店铺身份列、金额/订单/访客各列、单位、空值及汇总行规则。逐项确认“访客数”是平台已去重的**店铺日 UV**、商品日访客，还是其他口径；如有独立**区间去重 UV**，固定源请求起止日、去重对象/规则、时区与导出时间。没有明示定义就保持 `null/unknown`，不能改名为 UV。
2. **新增来源专用导入合同。** 只接受明确表头版本和精确店铺；每行日期须从指定列取得并在声明区间内，每个目标自然日必须存在，拒绝合计行、区间行混入日行、空日期、歧义日期及同日重复身份。每项指标区分 `null`、真实 `0` 与无效值，并保留原字段、源文件摘要和单位/口径版本。先用合成文件验证闰日、跨月、遗漏、重复、跨店及单日与区间混杂。
3. **建立不可重复的日事实。** 对已验证的日粒度以 `(source, dataset, platform, exact shop, businessDate, metric contract version)` 建稳定身份；同店同日重叠导入：内容一致幂等，内容不同须明确版本/优先级或报冲突，不得多行求和。采用事务内替换、版本水位及历史批次追踪；旧行迁移前只读盘点并隔离同日多行/空日期，不能静默挑一行。区间去重 UV 若存在，应单独以精确起止日保存，绝不混入日事实表。
4. **接 owning 来源，再接报告。** 在 `netshop.analysis.SOURCES`、来源目录、精确身份权限、修订游标、完整分页、控制总额及日期覆盖合同中新增独立 `shopOverviewDaily`，不要复用 SKU/SPU 商品事实。若有平台区间 UV，做独立 `shopOverviewInterval` 入口并绑定完整区间、源口径和封存证明；无该源时报告标明“区间去重 UV 不可得”。只在 owning Reader 核实报告、账号、原始来源、完整页及发布水位之后供 Agent/renderer 使用。
5. **用源数据验收而不是推断。** 每家店至少验两次重叠导入（相同与冲突）、本期/前期/去年同期完整与缺日、跨店隔离、源金额/订单控制汇总和文件/DB/分析页三方对账。日 UV 只能按日展示；区间 UV 只能与平台对同一完整区间独立给出的去重数对账。商品日访客、日 UV 求和、广告访客及订单客户数都不得替代区间 UV。

当前无可信字段与身份合同，暂不实现纯候选或 owning Reader；否则即使给候选附摘要，也只能证明错误输入被一致处理，不能提高 UV 可信度。
