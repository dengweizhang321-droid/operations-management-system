# 数据导入：运行记录与链路规则

数据导入工作区保留文件导入，原导入历史改为运行记录，新增链路规则，移除数据连续性子板块。旧 `view=history` 链接继续有效；`view=chains` 打开链路规则，旧 `view=continuity` 规范化回文件导入。以下描述源码行为，生产页面需另行受控发布。

## 运行记录

页面复用销售、库存、ERP、财务、网店、客服和 SKU 快递费率的七个有界只读批次接口，仍由各 Django 业务域执行权限检查。列表是各来源最近返回批次的集合，并非全量历史；数据类型、状态筛选和每页 20/50/100 条分页明确只作用于已经读取的集合。

按参考系统采用创建时间、类型、来源、链路/主体、状态、结束时间、失败原因、发起人列；展开可查看批次 ID、文件、工作表、行数、告警及批次处理耗时。接口没有提供的发起人、原因和结束时间显示未知或未提供，不从文件名或时间猜测。未知、进行中、失败、重复和部分完成状态不会误标成功；没有结束时间不以创建时间代替。

导入批次成功不能证明整个 n8n 工作流成功。当前系统没有按权限授权的 n8n 持久化执行投影，下载、登录及导入前失败不会出现在业务批次中；通过链路详情打开原 n8n 执行记录，继续使用 n8n 自身登录态。刷新失败明确显示缺失来源，取消与请求代次保护继续阻止迟到响应覆盖新状态。

## 链路规则

矩阵使用链路为行、账号/店铺为列，可按 ERP、京东、天猫过滤。当前包含 5 类链路、11 个执行主体和 11 份工作流配置。详情显示模块、步骤、频率、主数据周期及共用工作流的主体。共用的京东四店工作流不会虚构为四份独立调度。

展示投影由 `tools/build-import-chain-catalog.mjs` 读取精确白名单内的 n8n 工作流模板及店铺配置，生成 `lib/imports/chain-catalog.generated.json`。前端仅加载名称、主体键、模块、工作流 ID 和计划频率等字段；不打包完整店铺配置、Profile、下载路径、凭据或可执行节点参数。

修改工作流模板或店铺配置后，运行 `node tools/build-import-chain-catalog.mjs` 同步目录，再运行 `tests/import-monitor.test.ts` 的一致性检查。仓库定义中的 `active=false` 是安全导出默认值，不代表线上停用；候选模板也可能尚未采用。因此界面不推测当前启停、今日完成或下次运行时间，实际状态以 n8n 已发布版本为准。

页面不保存规则、不启停调度、不触发导入。操作员/管理员可打开 n8n 的工作流及执行记录；只读用户仅查看配置详情。不会复制参考系统的调度器或退役其外部执行器的业务结论。

## 隔离验收

在独立 worktree 使用既有 `preview:isolated` 入口。预览仅 GET/HEAD，合成销售、库存和 ERP 批次可以检查记录展示；其他域以空态为主。真实 n8n 执行、数据库写入、规则修改、生产部署和服务重启均不属于本次页面验收。
