## 用户选择：不新增密码和备份密钥

用户明确不设置恢复密码，也不自动生成随机备份密钥。此前尚未采用的恢复密钥 UI 和加密封装组件已从当前候选移除；窗口已取消，没有创建正式恢复密钥。现有 Windows、数据库及模型凭据保持原有管理方式。

新归档是 PostgreSQL custom dump，**不新增归档加密**，存储保护依赖原 runtime 目录 ACL 与归档盘保管。只有完整的 0082 关闭配置可使用此路径：私钥表必须为空，16 个受保护签名角色必须保持 NOLOGIN、无继承、无高权限及成员关系。检查失败时拒绝生成归档。既有运营查询、审计、对话与报告流程保留；依赖新签名密钥的实验能力保持关闭。

隔离 PostgreSQL 集群仍需要短期测试连接凭据。这些凭据仅供本次测试，不是用户需设置或保管的备份密钥。恢复归档不含数据库密码；恢复到隔离集群后，应用角色密码为空，真实灾难恢复须从既有凭据保管方式重新配置连接身份。

## 备份与恢复实现

原 django-postgres-maintenance.ps1 入口增加版本化的无新增密钥归档；旧 v1 归档与默认拒绝受保护迁移的路径保留。新路径使用既有 DPAPI 保管的 PostgreSQL 维护身份，普通业务账号不获得额外权限。

备份在重复读事务中校验关闭配置，持有私钥表 SHARE 锁直到 pg_dump 完成，阻止预检后插入密钥。归档和领域证据使用同一导出快照；不使用 --no-owner 或 --no-privileges。完整行摘要通过数据库计算固定长度 SHA-256、排序后流式汇总，不向日志或 manifest 输出业务原文。

新归档记录原角色属性和允许的角色设置、表/列/函数权限、约束、触发器、默认权限及扩展。恢复限定在独立回环端口的新集群，拒绝既有应用角色、非空目标、未批准 manifest、归档篡改与目录差异。角色不从归档获取密码，也不自动开通新签名能力。

序列值不受 PostgreSQL MVCC 快照约束，因此单独验证恢复值不低于备份观察值；仅支持递增且不循环的序列。固定目录仍比较序列参数。逻辑恢复仅规范化已证明等价的默认 ACL、常量 varchar 数组转 text 与保持顺序的布尔括号，条件或额外权限变化仍拒绝。
