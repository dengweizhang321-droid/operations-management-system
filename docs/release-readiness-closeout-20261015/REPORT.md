# 统一发布交付契约与就绪/收尾模板

2026-10-15。用户明确要求按已讨论建议执行，并让本项目所有agents上架发布遵守同一契约。本轮交付代理行为规范与可复用材料，复用现有工具；不修改运行工具、不新建批次框架或自动重试器，不切换生产版本。

## 已交付范围

- [AGENTS统一入口](../../AGENTS.md)第4条只增加一次强制锚点引用，所有本项目主代理、实施与审查代理均须先加载同一契约；没有追加任务流水或另存AGENTS副本。
- [统一发布交付契约](../规范/验证与发布.md#统一发布交付契约)是唯一规则正文：合并前完成适用预案、取证、演练与独审，最终来源/制品冻结后准备就绪包，授权后现场动态准入，按原入口发布，必要上线确认与真实收尾。
- [工作单模板](../运维/部署与启动/release-delivery-templates.md)可复制到以后任务；覆盖就绪证据、适用异常分支、原操作回执、双计时和文档/Git/保全/清理计划，初始均未就绪，不用占位或声明代替真实结果。
- [原批次协议](../运维/部署与启动/release-batch-workflow.md)只补契约和模板链接；原候选/采用状态、批准、WAL及操作语义保持。规划依据见[独立方案](DESIGN.md)。

## 已有工具与未自动化部分

已有完整差异计划、原批次封存/inspect/执行/状态、独立只读取证与原精确协调、离线收尾草稿继续按实际已采用版本使用。取证为只读；协调可写入原审计/WAL，仍按原协议和授权执行。现有收尾工具要求受支持的原batch、连续WAL和精确回执；legacy只有独立操作回执时按模板保留原格式，不伪造batch/WAL。

`release-closeout-report.mjs`只产离线草稿，`acceptancePassed:null`不关闭批次，不执行Git提交/推送/归档；批次CLI没有通用reconcile子命令。契约附加就绪项、独审适用判断和跨工具完整收尾，当前由负责人/审查者据证核验，没有新增底层自动hook。填写模板是减少现场临时准备的措施，不冒称所有收尾已一键自动化。

15分钟是已验证且制品就绪常规版本的目标，包含必要收尾；本轮未进行真实发布计时，不宣称达标。更早授权至全部交付的原总等待不重置，异常/迁移/恢复及未完成项照实报告。前次市场发布的13分17秒成功续接和6分52秒收尾仅为历史单次观察，不能外推稳定承诺；本轮没有重跑那个生产流程。

## 直接相关验证与限制

- 复用现有收尾离线回归20项及范围计划回归10项，均通过。覆盖原失败/unknown保留、缺检查/摘要漂移拒绝、静态完整性与现场新鲜度分离、敏感回执投影、CLI错误不泄露，以及前端/后端/迁移/未知范围分类。[结果摘要](evidence/validation-summary.json)。
- 首次在新工作树加载原测试时缺typescript依赖，未执行任何用例，原[加载失败](evidence/original-module-resolution-failure.log)保留。随后只借用既有node_modules做模块解析；没有安装依赖、构建应用或改生产。成功日志分别保存，不回填原失败。
- 文档与模板按实际路径、锚点、示例JSON及真实工具接口检查；本次完整Git差异的发布范围随最终交付记录。独立审查原件见[evidence/contract-review.json](evidence/contract-review.json)，不能把执行者自验称为独审。
- 发布负责人仍须在真实故障后确认原操作效果，执行原协议要求的独立现场观察；预审不替代动态事实。unknown不得自动重放/换身份、清owner或凭旧head回写入口。没有通过规范放宽权限、迁移、数据保障、进程或字节门禁。

## 后续适用

以后所有本项目代理从最新main的AGENTS加载此契约，在各自任务填写工作单并复用有效原工具/证据。新版本只有就绪且具备本次实际生产授权才进入维护；本文不对未来任意候选授予上线权限。

Worker校验/切换和服务启动的进一步加速仍先分段计时；不因本契约启用跨域并行、跨进程权限缓存或新增生产协议。若后续确需补工具，应按实际范围单独开发、隔离验证、独审及受控采用；本轮纯文档范围无需生产应用打包或部署。提交、远端和保全状态以最终交付清单为准，原始证据保持。
