该流程固定处理京东店铺注册项 `jd-yiyong-director`：

- 业务店铺：志高商用设备旗舰店
- 京准通页面账号标签：志高亿用-总监

## A → B → C

### A：固化日期、店铺和执行所有者

A 调用 `POST http://127.0.0.1:5791/jd-promotion/plan`，并携带同一个 n8n execution ID。它校验本机运营系统、受控店铺注册项和 Default profile，只接受同一自然月、最多 31 天的连续日期范围。空 execution ID、跨执行接管、并发或乱序调用均失败关闭。

### B：生成、下载、校验、导入和首次回查

B 调用 `/jd-promotion/run`，执行下列受控步骤：

1. 打开京准通自定义报表并核验页面显示“志高亿用-总监”。
2. 选择“AI推广数据自动下载”，将自定义日期精确读回为目标起止日。
3. 先读取下载中心 baseline；若已有唯一精确范围任务则接管，否则持久化 `submitting` 恢复清单后只点击一次“开始生成”。
4. 下载中心只能接管报表名前缀、起止日期、创建时间和 baseline 共同锁定的唯一任务。任务状态从生成中变为已生成不会改变任务身份。
5. 下载 CSV 后验证 UTF-8、非空、必需表头、连续日期覆盖、账户集合、行数、关键指标和 SHA-256。
6. 以 `source=jd_promotion`、`dataset=ad`、`platform=京东`、精确店铺和日期范围调用运营系统导入接口。
7. 只有返回 `imported` 或 `duplicate`、批次为 `completed`、零告警、行数/日期/店铺/原文件哈希一致且落库回查成功，B 才结束。

### C：独立复验

C 调用 `/jd-promotion/verify`，重新读取已保存 CSV，重算 SHA-256、行数、日期和账户集合，再按 batch ID 只读查询精确批次。文件与批次任一不一致，整次 n8n execution 失败。

## 手工运行与恢复

独立命令行运行：

```powershell
npm run jd:promotion -- --start-date 2026-08-13 --end-date 2026-08-14 --run-id jd-promotion-20260813-14
```

登录失效、验证码、安全验证、生成点击结果未决或下载中心出现多个候选时，执行器保留恢复清单并停止。不得删除清单后重建任务；应先核对当前账号和下载中心，再从 n8n 的 A 节点启动新的完整 execution。账号、密码、Cookie、Token、Session 和 profile 路径都不写入 n8n 工作流。
