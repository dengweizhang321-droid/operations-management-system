**建议先恢复现有功能的可靠使用，再补 Skill 和自动日报。** 首批重点是让 Pi 能正确管理保留环境、暂停后能继续工作、停止按钮有明确结果、普通经营问题不再误进推广限制，同时修正已发现的指标口径并补足 pandas 错误定位。

## 1. 建成后应有什么变化

- Pi 保留历史和工作文件，同时能分清“可继续的休眠环境”“仍有未知结果的环境”和“正在执行的环境”；容量不足时说明真实原因。
- 暂停再唤醒后恢复本地执行模式和模型配置，并重新核验当前权限；计划模式仍不能执行命令，旧操作的模型/系统工具授权不会复活。
- 点击停止后能看到“取消意图已保存”“等待收尾”或“结果仍未知”；不再以断开页面连接冒充任务停止。
- 普通店铺分析不因“报告、SKU”等词误进推广专用通道；分析结果采用系统现有指标口径。
- pandas、模型和投递失败能指出实际停止阶段，便于只修有证据的问题。
- 后续按独立批次补齐报告、图片、Skill 和日报；后续扩展不阻塞首批交付。

### W1 — Pi 容量与保留环境生命周期〔已证实缺陷〕

- **触发/证据：** A+C，8 个 exited 容器占满 8 会话名额；Runner 确定拒绝被外层误记为未知。
- **复用与文件：** 复用现有 rootless Runner、SQLite ledger、工作卷和身份检查；`backend/pi_runner/server.py`、`workspace.py`、`backend/ai_assistant/pi_transport.py`、`pi_worker.py`、`pi_workspace.py` 及直接调用方。
- **修改一：** 仅把经逐项确认“未派发”的 `create/session_limit` 等拒绝回传为明确错误。当前签名 400 只带精确 error body，须用本次 nonce 验签绑定实际请求并匹配状态/正文，不能只认字符串；沿 transport→`runner_dispatch`→worker/init 完整链正确收尾且不误 freeze。超时、断线、签名/身份不符及含混响应仍为 unknown；不扩成通用重试名单、不重写旧 unknown。若已产生回收意图或删除效果，不得再把整轮描述为纯 session_limit、无效果。
- **修改二：** 在原生命周期内补“保留工作卷的休眠容器回收→同身份重建”最小契约，优先将回收作为独立精确维护动作，不混入普通 create。联合核对 Django 会话、operation/control 与 Runner ledger、活动控制/进程、精确容器/卷；任一侧 unknown/frozen、仍活动、未决或两侧不一致均不能回收。正常终态或已核实 stopped 仅是候选，还须排除 `retained_reference` 保护的升级前驱。exited 不是安全回收证明。
- **关键语义：** 当前 `dispose` 会标记 disposed，清除内存 session，且 `create` 的恢复扫描排除 disposed/frozen；虽然卷未删，也不能承诺旧会话可恢复。因此不可直接拿 dispose 冒充休眠。优先沿既有 stopped 状态增加“容器可缺席但工作区可恢复”的明确表示与加载/重建分支；若现有字段不足再设计最小兼容字段。
- **依赖/风险与恢复：** 要一并处理 Broker 重启加载、create/wake、容量计算、回收与新建竞争及中途失败；保原 image、volume、seq、generation、scope/epoch 和审计。原卷缺失、归属冲突或不可验证时隔离该对象并报告，恢复分支不得走普通 create 的新卷兜底、用空卷冒充恢复。删除仅限已核验的容器外壳，永不默认删除卷；失败保留原记录/操作回执，结果不明即停止该对象，不重新挂载到其他身份。
- **完成标准：** 隔离满额样本合法回收后可新建；恢复原会话若再次满额，须先合法释放其他名额或明确拒绝，全程不超过 maxSessions，不在夹具中暗中越额。完成恢复时原文件/历史/身份保持；任一侧未知/活动、升级保护前驱、卷缺失/冲突均不被回收或空卷恢复。Broker 重启后状态一致；确定容量拒绝在完整 worker/init 链正确终态且不误 freeze，真正未知仍保留。
- **生产处置单独交付：** 对 8 个对象逐个列出可处置性、保留内容和恢复路径，取得精确维护授权后才执行。若没有可安全释放对象，明确容量仍阻断；不简单调大上限、不先删后补证明。

### W2 — 暂停与唤醒恢复执行绑定〔已证实缺陷〕

- **触发/证据：** B+C，`wake` 仅 `session.start()`，新 JS 进程没有本地执行绑定，execute 会话被当作 plan。现有 `/runner-bind` 同时携带 operation-scoped gateway capability；初始化收尾清空 capability_hash/lease，wake 只携 admission，Runner ledger 也不保存该凭据，故不能直接重用旧网关绑定。
- **复用与文件：** 复用现有 metadata/admission、技能安装和绑定校验；`backend/pi_runner/workspace.py`、`server.py`、`backend/ai_assistant/pi_workspace.py`、`pi_worker.py`，以及 `containers/pi-agent/gateway-extension.mjs`、`native-capabilities.mjs` 的原协议。
- **修改边界：** 明确分开“恢复本地 metadata/admission/技能”和“授予模型/系统工具网关访问”。wake 仅恢复受信本地状态并核验当前 mode、scope、epoch/generation、model、skills、thinking 和有效 admission；不持久化或复活旧 capability，不为 wake 签发新的模型权限。模型/系统工具仍由新的合法 operation 经原流程单独授权。
- **协议范围：** 若 `Session.bind/_bind` 继续耦合网关凭据，沿原协议增加最小本地恢复分支，复用校验但不接收网关 secret；明确 Runner 与容器扩展/镜像的配套版本及兼容拒绝。不得改成空 capability 伪装合法绑定或默认 execute。
- **依赖/风险与恢复：** 与 W1 重建分支共用本地恢复逻辑；撤权/过期/版本不兼容继续明确拒绝，不标可执行 ready，不靠新 prompt 掩盖失败，不改原文件或重复原模型请求。
- **完成标准：** 无 active operation、初始化凭据已清除时仍可 wake；当前 execute admission 有效则可直接做许可内 Bash，但旧 capability 不能调用模型/系统工具。plan、撤权、scope/epoch 变化、重启和恢复失败分别保持原限制。Python/npm/uv 资源与模型/技能选择按实际结果核验；后续新合法 operation 才能重新取得网关授权。

### W3 — Chat 停止按钮与持久取消〔已证实缺陷〕

- **触发/证据：** A+C，UI abort 后持久取消为 false；Worker fire-and-forget 吞错，服务端更新 0 行也返回 ok。
- **复用与文件：** 沿原 clientRequestId、请求回执和 AI `mutation` 事务序列修改，不另造锁；`app/ai-assistant-view.tsx`、`app/api/ai/chat/route.ts`、`lib/ai/django-route.ts`、`backend/ai_assistant/views.py`、`chat.py` 及必要模型/迁移。通过受保护、同源的公开 Worker 写入口衔接内部 HMAC cancel；当前没有公开 `/api/ai/chat/cancel`，不能让前端照旧调用 404 路径。
- **修改边界：** 显式 Stop 与换页、断线、刷新触发的 AbortSignal 分开，普通断流不能冒称用户确认停止。取消请求独立于已 abort 的流连接；以真实用户+clientRequestId 持久记录意图，优先复用现有回执字段。复用 `GET /api/ai/chat?clientRequestId=…&workspaceModule=…` 查询，并覆盖尚无 conversation 的已认证早到取消意图；按主体/模块隔离、限定保留规模与期限，不能依赖进程内标志。
- **竞争处理：** 在原 `mutation` 事务序列内原子判定早到取消、请求登记与派发预留，覆盖先到、晚到和重复取消。`provider_started_at` 在网络 POST 前即写，不能单凭它认定供应商已收到或已经执行；预留到 POST 之间的取消竞态与发送后的未知分开处理。更新 0 行需区分未登记、已终态和无权访问等结果；迟到取消不覆盖已完成结果，不撤销既成工具副作用。
- **依赖/风险与恢复：** UI 展示取消已保存、收尾中、完成或未知；已终止的本地等待与供应商执行分别说明。真正未知继续保留禁重发约束；可清楚提供另开独立新会话入口，但不得把原内容自动搬过去重放。
- **完成标准：** 停止意图可刷新读回，早到/晚到均不丢失且幂等；已确定未派发的请求不再派发，不能停止的供应商请求不伪造 cancelled。页面恢复可操作性不以擦除原 unknown 实现。
