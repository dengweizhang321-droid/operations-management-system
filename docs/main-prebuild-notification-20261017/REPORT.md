# 打包状态查看窗口与本地完成提醒

用户希望直接知道发布包何时打包完成，无需翻日志或反复询问。本轮新增固定入口同目录的 `查看打包状态.bat`：双击后保留或最小化窗口，观察器每5秒只读检查本机已获取的main及对应准备记录，状态变化时显示版本和日志目录；完成或需处理时弹出独立本地消息框。关闭观察窗口不影响准备，但不会继续提醒。

观察器不fetch、不创建发布请求、不构建、不拿发布锁、不调用维护、迁移、部署或服务生命周期。它不发送钉钉或其他外部消息，也没有后台常驻或定时自动化。用户仍双击原 `发布main.bat` 手动发布；该入口重新核对远端和完整原生制品，查看完成提示不是新的发布许可。

状态绑定本机origin/main、冻结请求SHA、原生PREPARED版本、源码commit/tree形状与组件范围。旧目标不显示为当前完成，采样中main变化后不显示旧绿灯。已有STARTED无SUCCESS优先提示结果待核对；存在SUCCESS仅报告对应完成回执，不声称当前线上健康。FAILED优先于保留的PREPARED；读取PREPARED或重读主线期间出现新STARTED/FAILED也会再次采样并抑制完成通知。无PREPARED时，PREPARING只表示已开始且未完成，中断也会保留；失败保留原记录，不自动重试。指针读取中断或绑定不匹配时不判定完成，稍后重读。

覆盖局限：准备前置检查失败、无需生产制品或当前版本已在线等路径可能没有写出当前指针，旧queue结果又不保留精确目标，不能把任意旧失败归给当前main。因此无当前记录只显示“可能排队或前置检查停止，无法确认”，引导查看固定目录logs及prebuild-queue日志，不承诺所有早期失败都能自动弹窗。本轮不扩展队列写入协议。

弹窗使用普通用户独立hidden PowerShell进程的WScript.Shell.Popup，内容只展示已验证提交和固定说明，不执行BAT。提醒启动失败只在观察窗口报告，不能改变原准备结果。弹窗需要登录的Windows桌面；未使用真实“完成”测试弹窗干扰当前尚在准备的版本。

验证：新增14项状态/竞态/未知/弹窗边界测试及原12项队列/安装/实际环境测试通过。真实Windows PowerShell 5可创建WScript.Shell COM对象；现场只读CLI成功识别ff46目标仍在准备，`publicationPerformed:false`，未弹出测试完成框。安装测试验证生成BAT与安装后的真实状态CLI可运行；独立审查、固定目录BAT实际一次读取及最终提交另记录于本机交付证据。

本轮未修改发布执行器、原生完整性或环境绑定规则，未迁移正式库、维护、部署、启停服务或终止任何准备任务。新查看器交付与main原生包是否准备完成分别报告，不因安装观察入口而声称业务已上线。

独立审查按当前映射请求Sol High，发现并修复FAILED与PREPARED共存及完成采样期间新STARTED/FAILED的状态优先级问题；增量26项独立测试和额外第二轮读取交错核验通过，无阻断。实际底层型号未独立确认。观察结论只对应取样时刻，随后状态或远端main的变化仍由发布入口作最终核验。
