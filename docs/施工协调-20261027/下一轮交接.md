### 2. xlsx 原型污染补丁

```
分支     codex/xlsx-prototype-pollution-patch-20261028
worktree D:/.codex/worktrees/xlsx-proto-patch-20261028/运营管理系统
状态     未动手（刚建 worktree 就被停）
```

**只修 CVE-2023-30533（原型污染）**。另一个 CVE-2024-22363（ReDoS）**已决定接受风险**，不要碰。

**修复落点已查明**，`node_modules/xlsx/xlsx.js:11646`：
```js
var r = decode_cell(comment.ref);        // ← 锚点，实测全文件唯一
if(dense) { ... }
```
官方 0.19.3 在其后加一行 `if(r.r < 0 || r.c < 0) return;`。

**根因**：`decode_cell()` 对 `comment.ref = "__proto__"` 返回 `{c:-1,r:-1}`（只累加大写字母数字），代码未检查负值；而 `sheet["__proto__"]` 取到 `Object.prototype` 本体（真值），走"已存在"分支后 `cell.c = []` 污染全局原型。

**照现成先例写**：`tools/install-workerd-heap-patch.mjs`（`package.json:9` 的 postinstall），关键是**反向还原校验** —— 打完补丁反向还原，哈希必须等于已知原始 sha256，否则抛错拒绝。要幂等（postinstall 每次 `npm install` 都跑）。

**要注意**：先确认 `node_modules/xlsx/` 下的实际文件布局，可能不止 `xlsx.js`（查有无 `xlsx.mjs`、`dist/`），**每个被实际 import 的副本都要打**。

**预期落差**：`npm audit` 仍会报那两个 high（它看版本号不看实际代码），这是正常的，要在报告里说明。

**为什么不升级**：registry latest 停在 0.18.5（SheetJS 0.19 起转 CDN）；CDN tarball URL 与 vendored tgz + `file:` 两条路已实测被堵死（发布链 `npm ci` 强制离线且缓存按 URL 做键；`worker-local-release.mjs:251-264` 的打包清单是硬编码、不含 vendor）。

### 周报的时间门在 Django 层不在 PowerShell 层

曾误判"脚本没有时间门、开了会每 5 分钟发 288 条"。实际时间门与去重都在 `backend/workflow/management/commands/new_product_weekly_report.py`：
